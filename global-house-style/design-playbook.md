# 디자인 플레이북 — 프로젝트를 넘어 쌓는 디자인 기준

> 정본 · 전역(모든 프로젝트). 트리거와 갱신 의무는 `~/.claude/CLAUDE.md` 「전역 규칙 — 디자인 작업 = 같이 성장」.
> 건별 내용(고객사 · 화면 목록 · Figma 노드 · 확정 색값)은 여기 두지 않고 그 프로젝트의 디자인 프롬프트 md에 둔다.
> 판단 골든셋(등급)은 Dan Jr. `~/.claude/persona/persona.md` — 디자인 항목 D-08 · D-16 · D-18 · D-21 · D-26 · D-32 · W-10 · W-16 등. 여기와 어긋나면 persona.md가 우선이고, 이 파일을 고친다.

## 1. 적용 범위

- 제안 시안만이 아니라 모든 프로젝트의 디자인 작업: 앱 · 웹 화면 시안, 대시보드, 디자인 시스템 · 컴포넌트 · 공통 가이드, Figma 작업, HTML 목업, 와이어 → 디자인 디벨롭
- 하우스 스타일(문서형 · 슬라이드형 HTML)은 별도 규칙. 이 파일은 「제품 화면 디자인」 쪽 기준

## 2. 프로젝트 프롬프트 md (건별 정본)

- 위치: 그 프로젝트의 구글 드라이브 작업 폴더(프로젝트마다 다름). 착수 때 사용자가 준 경로 또는 프로젝트 폴더에서 찾고, 없으면 묻는다. 드라이브 폴더가 없는 프로젝트는 그 프로젝트 리포 · 작업 폴더에 두고 위치를 보고
- 파일명: 산출물 파일명 규칙. 업무 산출물 `업무명-디자인시안프롬프트-v0.1-YYYYMMDD.md`, 공식 산출물이면 단계코드 포함
- 처음 만들 때: 직전 프로젝트의 최신 md를 복제 → 건별 내용만 교체. 장 구성 = 역할 · 목표 · 범위 / 스킬 역할 분담 / 입력 자료 · 차용 범위 / 착수 전 확인 / 단계별 작업 / 출력 · 점검
- 작업 중: 사용자 지적 · 결정 · 확정값은 그때그때 해당 장에 `(YYYY-MM-DD 추가)`로 넣는다. 대화에만 두지 않는다

## 3. 품질 하한 (어느 건이든)

- 와이어에 색만 입힌 수준 금지 → 바탕 · 구역 블록 · 1px 연회색 경계 · 넉넉한 여백으로 위계 (2026-11-25)
- 검은 구분선 금지. 변수(토큰) 연결 색은 기본값까지 해석값으로 확인 (2026-11-25)
- 서체 Pretendard(지정이 없으면), 굵기 4단계 이상 위계 (2026-11-25)
- 컴포넌트 캔버스: 분류별 열 · 라벨 · 어두운 섹션 배경 · 흰 카드, 만들 때마다 재정렬 (2026-11-25)
- 강조 줄 · 색 테두리 · AI 기본 룩 회피 = persona D-08 · V-03, 반복 아이콘 = D-21

## 4. 레퍼런스 디자인 시스템 차용 선

- 따른다: 공개 문서의 구조 · variant 체계 · 수치 · 조립 규칙 · 문구 규칙 → 직접 그린다
- 반입하지 않는다: UI Kit 파일 · 패키지 렌더 캡처 · 아이콘/이모지 세트 · 목업 이미지 · 브랜드 색 hex · 토큰 이름 그대로. 결과물이 시안 · jpg여도 같다
- 문서에 없는 치수 = 공개 예시 실측 근사 + 명세표에 「실측 근사」 표시
- 아이콘 = Lucide · Tabler 등 오픈 라이선스, 크기 · 굵기 규칙만 레퍼런스처럼
- 레퍼런스 제품을 지정받으면 화면 구조 · 요소 모양까지 재현(persona D-32), 차용 선은 위와 같음
- 사례: Toss TDS Mobile(2026-11-25) = 「2단계: 구조 + 공개 수치 재현」, 라이선스는 앱인토스 외 사용 금지

## 5. 확장형 골격

1. 컴포넌트 명세표 — 컴포넌트마다 variant 축 · 상태 · 수치 · 출처(문서 / 실측 근사). 필요한 것부터 만들고 나머지는 이름만
2. 토큰 3층(primitive → semantic → component) + 브랜드 모드. 다음 고객사는 모드만 추가, 그레이 · 타이포 · 간격은 공통 층
3. 반복 패턴 템플릿(목록 · 상세 · 비교 · 검색 · 결과 · 시트 흐름 · 빈 상태 · 오류 …), 인스턴스 · 슬롯 구조
4. 화면 = 템플릿 조립. 템플릿 수정이 전체에 반영되게
5. 출력 2갈래 — 발송용 이미지(jpg 2x 등) + tokens.json → CSS 변수(HTML 목업 · 덱)

## 6. 같이 성장 — 보고 방식

- 보고 = 바꾼 것 + 왜 그렇게 판단했는지 1–2줄(위계 · 간격 · 색 역할 · 레퍼런스 근거)
- 사용자가 직접 할 때 쓸 Figma 요령(변수 · 컴포넌트 · Auto Layout · 스타일 연결)을 필요한 만큼
- 사용자가 직접 고친 디자인은 전후 차이를 읽어 기준으로 흡수 → 프로젝트 md 또는 이 파일
- 보고 끝에 한 줄: 「디자인 기준 갱신: 프로젝트 md N곳 · 플레이북 N곳 · Dan Jr. 후보 N건」(없으면 「없음」)

## 7. 갱신 규칙

- 건별 내용 → 프로젝트 md. 두 건 이상에 통할 기준 → 이 파일 해당 장 + 아래 이력 한 줄
- 사용자가 고른 판단 · 반복 지적 → Dan Jr. 후보 큐 `~/.claude/persona/candidates.md` 「대기」(persona.md는 사용자 승인 후에만)
- 기존 줄은 지우지 않고, 바뀌면 고친 날짜를 남긴다
