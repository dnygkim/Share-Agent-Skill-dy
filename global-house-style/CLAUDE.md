# 전역 규칙 — HTML 산출물 하우스 스타일

**별도 요청이 없으면 HTML 산출물은 전부 이 하우스 스타일로 뽑는다.** 일반 대화든,
에이전트 하네스(`agent/*`)든, 스킬이든 같다 — 분석서·리포트·리서치 요약·제안서 덱·PRD 등
문서성 HTML 산출물의 기본 스타일은 하나다(2026-08-27 통일).

**하네스·스킬 세션은 추출 전에 한 번 확인한다** — HTML 추출 직전 인테이크에서
「기본 스타일(하우스 스타일)로 추출할까요?」를 묻고, 확인을 받은 뒤 추출한다
("기본으로/네/알아서"면 하우스 스타일 · CI 적용을 답하면 그때 HEX 확정).
일반 대화에서는 확인 없이 기본 적용한다.
**확인 질문 없이 진행되는 경우(질문 생략·무응답·일괄 진행 지시·비대화형 실행)에도
스타일을 임의로 고르거나 추출을 보류하지 않는다** — 그 하네스/스킬에 정의된
기본 양식(= 이 하우스 스타일의 골격·토큰)으로 작성한다.

- **스타일 정본**: `~/.claude/house-style/house-style.css` — 작업 전에 읽고 `<style>` 안에 전문을 그대로 인라인한다.
- **골격은 둘**. 산출물 성격에 맞는 쪽을 쓴다.
  - **문서형** = `~/.claude/house-style/base_template_doc.html` — 토프바(GNB) + 좌측 LNB(앵커 목차) + 표지 + 목차 + 섹션 + footer. 롱스크롤 + A4 인쇄. 분석서·리포트·PRD 가 여기 해당한다.
  - **슬라이드형** = `Share-Agent-Skill-dy/agent/proposal/template/base_template.html` — 1280×720 덱. 정본의 §1 서체·§2 토큰만 복제하고 슬라이드 전용 규칙은 자기 `<style>`에 둔다.
- **GNB(topbar)·LNB·표지·목차·footer의 구조와 스타일은 고정**한다 — 매번 그대로 쓴다.
- **콘텐츠 영역(섹션 본문)은 고정하지 않는다.** 골격 파일 안 "콘텐츠 컴포넌트 팔레트" 주석 아래 있는 표·요약 스탯·플로우·루프·트리·mermaid·진단박스·노트·등급목록 중, **추출한 내용의 성격에 맞는 것만 골라 조합**한다. 팔레트를 통째로 나열하지 않고, 섹션마다 쓰는 조합이 달라도 된다. 전체 클래스와 용도는 `house-style.css`의 섹션별 주석(§1~22)이 정본이다.
- 산출물은 **자기완결 단일 HTML 파일**로 만든다 — 외부 `.css`를 상대/절대경로로 link하지 않는다(파일을 옮기면 깨진다).
- 팔레트는 warm paper(`#F1EDE5`) + near-black ink 2톤이 기본이다. 강조는 색이 아니라 **반전**(ink 배경 + paper 텍스트)이나 명도 단계로 만든다 — 원색 포인트를 임의로 추가하지 않는다.
- **앵커·LNB는 정본이 이미 처리한다** — `[id]{scroll-margin-top}`(토프바가 제목을 덮지 않게)와 `.lnb` sticky 위치를 정본에서 잡아 두었으니, 산출물 `<style>` 끝에 같은 보정을 다시 덧대지 않는다. 어긋나면 산출물이 아니라 정본을 고친다.

## 클라이언트 CI 컬러 — 옵트인

CI 적용은 **명시적으로 요청받았을 때만** `house-style.css` §2b 방식으로 얹는다.
묻지 않고 임의로 켜지 않고, 과거 산출물·다른 프로젝트의 CI 를 재사용하지도 않는다.
요청받았는데 끝내 HEX 를 확정하지 못하면 중립 팔레트를 새로 만들지 말고 하우스 기본값으로
렌더링한 뒤 `[CI 확인 필요]`로 표기한다.

**CI를 얹으면 콘텐츠 영역도 CI 톤으로 맞춘다**(2026-10-22 지시). 포인트 색만 바꾸고 웜 베이지 바탕을
그대로 두지 않는다 — `--paper`·`--paper-2`·`--line`·`--line-2`·`--ink-2`·`--ink-3`를 CI 색상 계열(쿨/웜)의
저채도 중립색으로 함께 바꾸고, 정본에 웜 페이퍼 `rgba(241,237,229,…)`로 박힌 반전 글자·반투명 바탕 10곳도
흰색 rgba로 덮는다. `--ink`는 거의 검정을 유지한다. 값 예시와 덮을 목록은 정본 `house-style.css` §2b.

## 이 스타일을 강제하지 않는 경우

- **HTML 이 아닌 산출물** — pptx(`deckslide-design-guideline`·`weekly-report`)·xlsx·docx 는 각자 규격을 따른다.
- **산출물 성격이 문서가 아닐 때** — 코드 스니펫, 웹앱 UI 프로토타입, 랜딩페이지·포스터처럼 이 스타일과 무관한 산출물이면 강제하지 말고 사용자에게 방향을 확인한다.

# 전역 규칙 — 거버닝 메시지 문체 (장표·섹션 헤드라인)

**보고서·리서치 자료·제안서·PRD 등 문서성 산출물의 장표 대제목, 섹션 헤드라인, Key Message·결론 바, 카드 타이틀은 전부 이 규칙으로 쓴다.** HTML·pptx·Figma·마크다운 등 매체를 가리지 않는다(2026-09-11 전역 적용, 출처: GS칼텍스 제안 작업에서 확정한 피드백).

거버닝 메시지 = 그 장표(섹션) 하나의 결론을 한눈에 읽히는 한 줄로 세운 것. 발표자가 제목만 읽어도 장표의 주장이 전달돼야 한다. 제안 전체를 관통하는 슬로건과 다르고, 장마다 새로 쓴다.

- **형태**: 20~30자 안팎의 **짧은 상태 묘사** 한 구절. 명사구 또는 명사형 종결(「~구조」「~메뉴」「~부재」「~집중」). 「~입니다 / ~합니다 / ~해야 합니다 / ~이유」 같은 설명·서술 어미와 「~음 / ~씀」 어미는 쓰지 않는다.
- **구조**: 「현상, 결론」 또는 「A가 아니라 B」의 한 문장 대비를 기본으로 한다. 예) 「자료는 받아 가지만, 문의로 이어지지 않는 여정」 「콘텐츠를 더하는 개편이 아니라, 방문자와 콘텐츠를 잇는 순환을 설계하는 개편」. 두 문장으로 나누지 않는다.
- **수치·근거는 본문으로**: 제목에 숫자·출처·함의를 다 넣는 논증형은 쓰지 않는다. 수치는 본문·근거 박스·결론 바가 맡는다. 예) 「하위 메뉴 49개 중 26개가 Business 한 축에 몰려 …」(×) → 「비지니스 중심으로 배치된 카탈로그와 같은 메뉴」(○).
- **실체 있는 말로**: 「최우선으로 생각하는」 같은 태도 서술, 「유기적·순환고리·설계·적용」 같은 추상어 중첩은 피하고, 화면·구조가 실제로 하는 동작 하나를 쓴다. 비유(「카탈로그와 같은」)는 허용.
- **강조는 한 구절**: 핵심어 한 구절만 강조(블루·볼드 등 매체 규칙에 따름). 대시(—)로 절을 잇지 않는다.
- **짝 장표는 대구**: 타입 A/B, AS-IS/TO-BE, 1/2처럼 짝이 되는 장표는 같은 문장 구조·같은 어미·같은 명사로 맞춘다. 예) 「방문할 때마다 신규 소식을 먼저 안내하는 메인」 ↔ 「방문자의 용건에 먼저 답하는 메인」.
- **서브타이틀**은 「무엇 · 범위 · 기준」만 적는다(예: 「AS-IS 메뉴구조도 · gscaltex.com/kr · Depth 1–3」). 주장을 겹쳐 쓰지 않는다.
- **결론 바·Key Message**는 판단 + 함의까지 한 문장으로 허용하되, 「2.3의 출발점」 같은 문서 구조 언급은 넣지 않는다. 「명사형 어미로」 지시가 오면 「~없습니다」→「부재/전무」, 「~합니다」→「집중/이탈/미열람」으로 바꾸고 「있다/없다」 대비는 살린다.
- **제안 절차**: 거버닝 메시지를 요청받으면 짧은 상태 묘사형을 1안(추천)으로, 대비 강화형·동작 명시형을 대안 2개까지만 제시한다. 사용자가 확정한 문장은 그대로 두고 손대지 않는다.
- 본문 서술 톤(명사형 종결·말미 마침표 제거·개조식)은 별도 기준을 따른다 — 메모리 `doc-tone-nominal-endings` 참조.
  **「~함 / ~임 / ~음 / ~둠 / ~씀 / ~따름 / ~않음」처럼 용언을 ㅁ으로 명사화한 어미도 쓰지 않는다**(2026-09-17 지시). 명사구로 끝맺는다 — 「정의하지 않음」→「정의 대상 제외」, 「두지 않음」→「보관 금지」, 「필요함」→「필요」, 「지키게 함」→「지키게 하는 관리」, 「PM 판단에 따름」→「PM 판단」. 헤드라인·결론 바·본문·푸터 모두 같다.

## 줄바꿈 — 어절 단위 (2026-09-17 지시)

한글이 글자 단위로 끊겨 「…두는 네 / 줄 규칙」처럼 두 줄로 떨어지지 않게 한다. 정본 `house-style.css` §3 `body`에 `word-break:keep-all; overflow-wrap:break-word`, 제목·콘셉트·결론 문장(`h1,h2,h3,.concept p,.closing p,.cover .lead`)에 `text-wrap:balance`를 두었다. 산출물 `<style>`에 다시 덧대지 않고, 두 줄로 떨어지는 헤드라인은 문장을 줄여 한 줄에 넣거나 어절 경계에서만 나뉘게 둔다. 슬라이드형 골격도 같은 두 규칙을 자기 `<style>`에 둔다.

## 출처 외부링크 — 항목에 직접 연결 (2026-10-19 지시)

리서치·RFP 분석·벤치마킹처럼 **출처 URL이 있는 문서형 HTML 산출물**은 `[S번호]` 태그나 출처 표에만 URL을 두지 않고, **본문 항목에 하이퍼링크를 건다.** 처음 추출할 때부터 적용한다.

- **어디에**: 출처 1건 = 항목 타이틀(굵은 라벨 · 표 첫 열 서비스명)에 / 출처 2건 이상 = 각 출처가 뒷받침하는 구절에 각각. 요약 스탯 라벨 · 표 캡션 · 출처 표 「자료」 열 제목까지 포함하고, `[S번호]` 태그와 출처 표 URL 열은 그대로 둔다. URL이 없는 내부 자료(RFP · 회의록 등)는 링크하지 않는다.
- **마크업**: `<a class="ext" href="URL" target="_blank" rel="noopener">텍스트</a>` — 굵은 타이틀은 `<b><a class="ext" …>타이틀</a></b>`. 본문 사이트 · 채널 URL 링크도 같은 `a.ext`로 통일한다(체인 아이콘 `a.ref`는 쓰지 않는다).
- **스타일**: 정본 `house-style.css` §22가 처리한다 — 옅은 밑줄 + 텍스트 끝 외부링크 아이콘, **마우스 hover · 포커스 시 반전(ink 바탕 · paper 글자)과 아이콘 우상향 이동**, 인쇄 시 아이콘 숨김. 산출물 `<style>`에 다시 덧대지 않는다.
- **검수**: 링크를 건 뒤 화면에 보이는 문장이 바뀌지 않았는지(링크 전후 텍스트 비교), 출처 표의 모든 URL이 본문 어딘가에 연결됐는지 확인하고, 본문에 연결되지 않은 출처는 완료 보고에 적는다.

# 전역 규칙 — 산출물 파일명 (2026-10-01 전역 적용 · 2026-10-28 원문 대조 보강)

출처: 신승 `SSBP-PM-산출물관리계획서-v0.1-20260820` §1.2·§2.2·§3 (원본 `G:\내 드라이브\100. 워크스페이스\120. Output\9999 기타 산출물\`). 문서 종류·매체(html·pptx·xlsx·docx·pdf)를 가리지 않는다.

**두 트랙으로 나뉜다.**

| 구분 | 파일명 | 비고 |
|---|---|---|
| **공식 산출물** (프로젝트 사업의 납품·보고 문서) | `프로젝트코드-단계코드-문서명-버전-작성일자` | 단계코드는 아래 7개. 신승 규정 그대로 |
| **업무 산출물** (프로젝트가 아닌 사내 검토·내부 보고·리서치 등) | `업무명-문서명-버전-작성일자` | **단계코드 없음**. 추후 공식 산출물로 전환될 때만 단계코드 부여 |

- **조각**: 하이픈( - )으로만 잇는다. 「최종·진짜최종·수정본」 같은 접미사 금지. 산출물 내부 식별자(요구사항 ID 등) 채번 규칙은 두지 않는다.
- **업무명**: 공백 없이(예 `eMatrix`). **처음 쓰는 업무명은 반드시 사용자에게 확인받은 뒤 적용**하고, 확인된 업무명은 그 업무의 산출물 전체에 고정한다. 임의로 정하지 않는다.
- **단계코드**: `PM` 사업관리 · `AN` 분석 · `DG` 설계 · `IM` 구현 · `TE` 테스트 · `DE` 오픈·이관, 어디에도 안 맞으면 `ET`(기타). 새 코드는 PM 승인 후에만 추가한다. 같은 단계의 문서는 문서명으로 구분하고 일련번호는 붙이지 않는다.
- **문서번호**(프로젝트코드-단계코드): 한 번 부여하면 문서가 폐기될 때까지 바꾸지 않고, 버전이 올라가도 그대로 유지한다.
- **문서명**: 띄어쓰기 없이. 반복 생성 문서는 괄호로 구분값(`주간보고서(3주차)`). 하위 뎁스는 밑줄 `_`로 **최대 2단**(`개선요청서_01_공수입력마감흐름`), 그 이상은 문서를 쪼개지 않고 문서 내 항목으로 관리한다. 밑줄은 문서명 내부에서만 쓴다.
- **버전**: `v0.1`~`v0.8` 작성 중(작성·수정할 때마다 +0.1, 작성 완료 시점도 v0.8 초과 금지) / `v0.9` PM 검토·지적사항 반영 완료 / `v1.0` 고객 확인까지 끝난 승인·확정(고객 제출본은 항상 v1.0 이상) / 확정 후 부분개정 +0.1(v1.0→v1.1), 전면개정 +1.0(목차·범위 변경, v1.1→v2.0). 문서 안 개정이력과 일치시킨다.
- **확정본 보존**: v1.0 이상은 덮어쓰지 않고 새 버전 파일을 별도로 만든다. v1.0 미만 작업본의 링크 추가·오탈자 같은 소규모 수정은 파일명·버전을 유지한 제자리 갱신(persona F-05).
- **작성일자**: 그 버전을 저장한 날짜 `YYYYMMDD` 8자리.
- **개정이력(공식 산출물)**: 표지 다음 장에 표를 둔다. 열은 버전·개정일자(YYYY-MM-DD)·구분·개정 내용·작성자 5개이고, 승인자 열 없이 구분=승인 행으로 갈음한다.

# 전역 규칙 — 자동화 창은 서브모니터로 (2026-10-28 지시)

**브라우저·데스크톱 앱 등을 직접 조작하면서 별도의 창을 새로 열 때는, 그 창을 주 모니터가 아닌 서브모니터로 옮긴 뒤 진행한다.** 주 모니터는 사용자가 쓰는 작업 공간이므로 자동화 창이 가리지 않게 한다. Chrome 자동화(claude-in-chrome)·computer-use·Playwright·앱 실행 스크립트 등 창을 띄우는 모든 경로에 같다.

- **Chrome 은 항상 새 창**(2026-10-28 지시): Chrome 브라우저를 동작시킬 때는 사용자의 기존 Chrome 창에 탭을 끼워 넣지 않고, **서브모니터에 새 Chrome 창을 열어 그 창 안에서만 진행**한다. claude-in-chrome 으로 작업할 때도 첫 단계에서 새 창을 만들어 서브모니터로 옮긴 뒤(또는 `--new-window --window-position=<서브 X>,<서브 Y>` 로 띄운 뒤) 그 창의 탭만 쓰고, 작업이 끝나면 그 창을 닫는다. 사용자의 기존 창·탭은 건드리지 않는다.

- **모니터 확인**: 창을 열기 전 `[System.Windows.Forms.Screen]::AllScreens`로 `Primary=False`인 디스플레이의 Bounds를 읽어 그 좌표로 옮긴다. 배치는 바뀔 수 있으니 값을 외워 쓰지 않고 매번 조회한다. 2026-10-28 기준 배치: 주 `DISPLAY2` 2560×1440 (0,0) · 서브 `DISPLAY1` 1920×1080 (-1920,0, 왼쪽).
- **옮기는 방법**: 새 창은 실행 옵션으로 위치를 지정(예 Chrome `--window-position=-1920,0 --window-size=1920,1032`), 이미 뜬 창은 PowerShell에서 `user32.dll`의 `SetWindowPos`/`MoveWindow`로 핸들을 잡아 서브모니터 Bounds로 이동한다. 옮긴 뒤 창이 실제로 서브모니터에 있는지 좌표로 한 번 확인한다.
- **예외**: 서브모니터가 없거나(`AllScreens` 1개) 창을 옮길 수 없는 환경이면 주 모니터에서 새 창으로 진행하되 완료 보고에 한 줄 적는다. Chrome 이 아닌 앱에서 사용자가 이미 쓰는 창 안에 탭만 여는 경우(창을 새로 만들지 않는 경우)는 창 위치를 건드리지 않는다.

# 전역 규칙 — HTML 산출물 수정 이력 메타정보 (2026-10-28 지시)

**HTML 산출물 파일을 갱신해 저장·배포할 때마다 `<head>` 안 메타정보 영역에 수정한 페이지와 내역을 기록한다.** 제안서·보고서 등 문서형·슬라이드형 HTML 모두 같다. 화면에 보이지 않는 주석이므로 렌더링에는 영향이 없다.

- **위치**: `<meta name="viewport">` 바로 아래. `<meta name="revision" content="YYYYMMDD">` 를 그날 날짜로 갱신하고, 그 아래 `<!-- ═══ 수정 이력 ═══ … -->` 주석 블록 **맨 위**에 한 줄 추가(최신이 위). 블록이 없는 파일은 같은 형식으로 새로 만든다.
- **형식**: `[YYYYMMDD] 담당자 · 수정 페이지: <슬라이드 코드 또는 섹션 번호, 예 B01, A03~A05, 별첨4, §2.3> · 내역: <무엇을 어떻게 바꿨는지 한 줄>`
- 날짜만 바뀐 재저장도 한 줄 남긴다(내역: 「변경 없음, 날짜 갱신」). 기존 이력 줄은 지우거나 고치지 않는다.
- 원본(드라이브)과 배포본(서버)을 같은 내용으로 유지한다 — 한쪽만 고치지 않는다.
