# PPT 장표 디자인 시스템 가이드 (범용판)

> **표준 디자인**: 풀 폭 블랙 헤더(2단 위계 GNB) + 라운드 코너 카드 레이아웃 + 포인트 컬러(`accent`) 강조 + 제안사 브랜드 컬러(`brand`) 분리.
> 프로젝트별 변수(`{clientName}`, `{proposerName}`, `accent`, `brand`, 폰트)는 SKILL.md 인테이크에서 확정한다. 이 문서의 컬러 기본값은 청록(#2DBFB8) 계열 예시다.

---

## 0. 캔버스 사양

| 항목 | 값 |
|---|---|
| **비율** | **4:3** (표준) |
| **물리 사이즈** | 10" × 7.5" (pptxgenjs `LAYOUT_4x3`) |
| **여백** | 카드 내부 좌우 0.4" / 상하 0.3" 기준 |
| **본문 영역 폭** | 약 9.2" |

> 이 문서의 모든 좌표는 4:3 기준. 16:9로 변경 시 x·w 좌표를 13.33" 폭 기준으로 재산정해야 한다.

---

## 1. 레이아웃 및 그리드

### 1-1. 전체 구조

- **상단 블랙 바 (Top GNB)**: 슬라이드 최상단, 검은색 배경, **전체 너비를 꽉 채우는 형태**.
- **콘텐츠 영역 (Main Body)**: 블랙 바 하단에 **흰색 '라운드 코너 카드'**. 카드 상단 양쪽 모서리에만 큰 곡률 적용.

### 1-2. 치수

| 영역 | 위치 (x, y, w, h) | 비고 |
|---|---|---|
| **상단 블랙 바** | `0, 0, 10, 0.55` | 슬라이드 폭 100%, 검정 채움 |
| **라운드 카드** | `0, 0.55, 10, 7.5` | 흰 배경, 상단 양쪽만 라운드(`rectRadius: 0.25"`) — 하단은 슬라이드 너머로 빠져 라운드 미노출 |
| **카드 내부 패딩** | 좌우 0.4" / 상 0.3" / 하 0.3" | 텍스트·요소 정렬 기준 |

### 1-3. 라운드 코너 처리 방식 (구현 팁)

pptxgenjs의 `ROUNDED_RECTANGLE`은 4개 모서리가 모두 둥글게 처리되므로, **상단만 라운드**처럼 보이게 하려면:

1. 슬라이드 배경을 검정(`headerBg`)으로 설정 → 상단 블랙 바 영역으로 자연스럽게 노출
2. 흰색 `ROUNDED_RECTANGLE`을 `y: 0.55, h: 7.5`로 그림 → 하단이 슬라이드 끝(7.5") 너머로 빠져 둥근 모서리가 보이지 않음
3. 결과: 상단 좌우만 둥글고, 하단은 직각 마감

## 2. 컬러 팔레트

### 2-1. 배경색

| 토큰 | 기본값 | 용도 |
|---|---|---|
| `headerBg` | `#1A1A1B` | 상단 블랙 바 (짙은 블랙/차콜) |
| `bodyBg` | `#FFFFFF` | 콘텐츠 영역, 라운드 카드 배경 |

### 2-2. 포인트 컬러 (프로젝트별 교체 지점)

| 토큰 | 기본값 (청록 예시) | 용도 |
|---|---|---|
| **`accent`** | **`#2DBFB8`** | **메인 강조 — 본문 강조 키워드, To-Be 카드 헤더, 화살표, 인용 박스 보더** |
| `accentLite` | `#E8F5F4` | 강조 영역의 옅은 배경 (인용 박스, 차별화 카드) — `accent`의 옅은 파생 |
| `accentDark` | `#1FA8A2` | 강조 텍스트의 더 진한 톤 (옵션) — `accent`의 진한 파생 |
| `brand` | 제안사 CI 컬러 | **제안사 로고 점 전용** (강조 요소와 분리, 본문 사용 금지) |

### 2-3. 텍스트 컬러

| 토큰 | HEX | 용도 |
|---|---|---|
| `headerText` | `#FFFFFF` | 헤더 텍스트 (전체 화이트, 강조 글씨도 화이트) |
| `titleText` | `#000000` | 본문 내 제목성 텍스트 (완전한 블랙) |
| `descText` | `#666666` | 거버닝 메시지 등 설명문 (중간 톤 그레이) |

### 2-4. 보조 그레이 톤

| 토큰 | HEX | 용도 |
|---|---|---|
| `gray100` | `#F2F3F5` | As-Is 사이드 라벨 배경 |
| `gray200` | `#E5E7EB` | 카드 보더 (옅은) |
| `gray300` | `#D9D9D9` | 카드 보더 (기본) |
| `gray500` | `#8E8E8E` | 캡션, 푸터 페이지 번호 |
| `gray700` | `#4B4B4B` | 본문 보조 텍스트, As-Is 카드 헤더 |

> **위계 원칙**: `accent`는 슬라이드당 **3~5개 포인트**에만 적용. 본문 핵심 강조 키워드 1~2개 + To-Be 카드 헤더 + 인용 박스 보더가 기본 사용처. **제안사 로고 점만 별도 `brand` 컬러**를 사용해 브랜드 정체성 유지.

## 3. 타이포그래피 및 계층 구조

**기본 폰트**: **Pretendard** (권장 기본값). 헤더·본문·푸터를 단일 패밀리로 통일한다.

> **설치 안내**: 빌드 머신과 발표 PC 양쪽에 폰트가 설치되어 있어야 한다 (Pretendard: https://github.com/orioncactus/pretendard). 미설치 환경에서는 시스템 폰트로 폴백되어 자간·줄간격이 어긋난다.
> **fallback 정책**: pptxgenjs `fontFace` 값은 인테이크에서 확정한 폰트명으로 고정하고, 임의로 다른 폰트로 대체하지 않는다 (일관성 유지).

### 3-1. 헤더 (GNB) — 2단 위계

**핵심 원칙**: 좌측 GNB는 **중단원(장)**과 **소단원(절)** 두 단계만 표기하고, 폰트 크기 차등으로 위계를 시각화한다. **Part(대단원)는 우측에만 표기** (좌측 중복 금지).

| 위치 | 텍스트 구성 | 폰트 | 색상 |
|---|---|---|---|
| 좌측 (x: 0.4) | "{중단원}  >  {소단원}" — 한 줄 베이스라인 정렬 | 아래 구성표 | `headerText` (#FFF) |
| 우측 (x: 7.85) | "{Part 명}" 예: "Ⅲ. 서비스 관리 체계" | 11pt Medium | `headerText` (#FFF) |

**좌측 GNB 폰트 구성표**

| 구분 | 사이즈 | 굵기 | 비고 |
|---|---|---|---|
| 중단원 (장) | **12pt** | **Regular** | 위계상 보조 |
| 구분자 ">" | 12pt | Regular | 좌우 공백 2칸 |
| **소단원 (절)** | **16pt** | **Bold** | **슬라이드 타이틀 역할** (강조) |

> **헤더 색 정책**: 헤더 안에서는 **모든 글씨가 화이트**. 컬러 강조는 헤더에서 사용하지 않는다 — 시각적 노이즈를 줄여 본문이 잘 보이게 한다.
> **긴 챕터명 처리**: 우측 GNB가 길면 Part 번호 + 핵심 키워드 2~3단어로 축약한다.
> **베이스라인 정렬 구현**: 단일 `addText`에 rich-text run 배열(12pt Regular 런 + 16pt Bold 런)을 넣고 `valign: "middle"` — §9-2 표준 코드 참조.

### 3-2. 본문

| 요소 | 크기 | 굵기 | 색상 |
|---|---|---|---|
| 본문 타이틀 | — | — | **두지 않음** (헤더 16pt Bold 소단원이 타이틀 역할) |
| **거버닝 메시지 (본문 설명문)** | **14pt** | Regular | `descText` (#666) — 헤더 직하 배치 |
| 카드 헤더 | 11~13pt | Bold | 흰색 (배경 컬러 위) |
| 카드 본문 | 9~10pt | Regular | `gray700` |
| **본문 강조 키워드** | 본문과 동일 | Bold | **`accent`** |
| 푸터 텍스트 (좌·우) | 10.5pt | Bold | `headerBg` |
| 페이지 번호 | 8.5pt | Regular | `gray500` |

> 한글 가독성을 위해 본문 이상 크기에는 `charSpacing: -0.3 ~ -0.5` 적용 권장.

### 3-3. 거버닝 메시지 작성 원칙

헤더 직하(y ≈ 0.85")에 위치하는 **거버닝 메시지**는 슬라이드의 핵심을 한 문단으로 요약해, 청중이 시각 자료를 보기 전에 제안 메시지를 먼저 파악하게 한다. 시각 자료는 이 메시지를 뒷받침하는 보조 역할이다.

1. **구체성** — 추상 키워드 나열이 아니라 **방향·방법·기대 결과**를 구체적 명사·동사로 서술한다.
   - ❌ "다양한 방법으로 UX를 개선합니다." (모호)
   - ✅ "다양한 디바이스와 임직원의 상황/이용 맥락이 고려된 워크플로우 리디자인을 수행합니다."
2. **종결 어미 일관성** — 모든 거버닝 메시지는 **"~합니다" 체**로 통일. 명사형·음슴체·평어·개조식 금지.
3. **분량** — 1~2문장, 약 80~140자 (1~2줄 수렴).
4. **수량/위치** — 슬라이드당 1개, 헤더 직하·메인 콘텐츠 시작 전.
5. **강조 처리** — 메시지 안 핵심 키워드 1~2개에 한해 `accent` Bold 허용.
6. **폰트 사이즈 14pt 고정** — 강조 키워드는 14pt Bold. 슬라이드별 임의 가변 금지. pptxgenjs `fontSize: 14` 명시.
7. **자연스러운 줄바꿈** — 2줄 이상이면 **절 단위 또는 쉼표·접속 어미 직후**에서 명시적으로 줄바꿈한다. 어절 중간·조사 분리·강조 키워드 분절 금지.
   - 구현: run text에 `\n` 명시(방법 A) 또는 run에 `breakLine: true`(방법 B). 한 메시지 안에서는 한 방식으로 통일.
   - ✅ "운영의 모든 활동은 측정 가능한 데이터로 기록되어, ↵ 정해진 주기로 의사결정자에게 도달하고, ↵ 다음 주기에 동일 지표로 효과까지 다시 측정되는 4단 순환 보고 체계를 운영합니다."

### 3-4. 슬라이드 노출 금지 — 내부 메타데이터 8종 (장표화 검수 필수)

콘텐츠 초안(MD)에 포함된 **작성·검증용 메타데이터**가 슬라이드에 노출되면 청중에게 내부 작업 흔적으로 비쳐 신뢰도를 해친다. 장표화 단계에서 아래 8종을 **반드시 제거**한다.

| # | 표기 유형 | 예시 | 처리 |
|---|---|---|---|
| 1 | 목차 cross-reference 괄호 표기 | `(Ⅶ-3.3)`, `(부록-4.3)`, `(별첨2 §1.3)`, `(Appendix-A)`, 괄호 없는 `Ⅶ-3.1과 정합` | **전량 삭제**. 본문 어휘로 재서술. 부록 지칭은 "부록의 ○○ 참고" 같은 번호 없는 자연어로 |
| 2 | RFP·평가기준 직접 인용 마커 | `◀── [RFP §5.2]`, `[별첨2 §1.3]` | **전량 삭제**. 핵심 어휘는 거버닝 메시지·카드 헤더에 자연어로 흡수 |
| 3 | 평가 점수 매핑 표기 | `AX 15점 中 5점`, `★18점 핵심` | **전량 삭제** ("점수 노린다" 인상 차단) |
| 4 | 차별화 등급 표기 | 타이틀 접미사 `(★★★)` | **타이틀에서 삭제**. 강조는 시각 위계로 대체 |
| 5 | Phase 매핑·담당 메타 | `> **Phase 매핑**: …`, `> **담당**: …` | **헤더 블록 전체 삭제**. Phase는 타임라인 다이어그램으로 표현 |
| 6 | 리스크·작성 노트 표기 | `> **0점 리스크**: …`, `[작성 노트 …]` | **전량 삭제** |
| 7 | MD 버전·작성일·선행 참조 | `> **버전**: v0.1` | **전량 삭제**. 푸터 페이지 번호 외 메타정보 노출 금지 |
| 8 | MD 자기지칭 어휘 ⭐빈도 높음 | `본 꼭지`, `본 영역`, `본 슬라이드`, `본 챕터`, `본 절`, `본 항`, `본 MD`, `본 문서`, `본 페이지` | **전량 삭제 또는 재서술**. 필요 시 "위 그래프", "왼쪽 카드" 등 시각 위치 표현으로. ⚠️ `본 제안`·`본 컨소시엄`·`본 사업`은 자연어 자기지칭이므로 **허용** |

**판정 기준**: "이 표기가 청중에게 가치를 주는가?" — 애매하면 **제거가 기본값**.

**구현 체크리스트 (최종 검수, 매칭 0건 확인)**

- [ ] 로마숫자 cross-reference: `\([ⅠⅡⅢⅣⅤⅥⅦⅧⅨⅩ]-\d+(?:\.\d+)*\)`
- [ ] 부록·별첨 cross-reference: `\((?:부록|별첨\s*\d*|Appendix)[\s§-]*[\w\d.-]+\)`
- [ ] 괄호 없는 인용 키워드: `Ⅶ-`, `부록-`, `별첨`, `Appendix-` 잔존 0건
- [ ] MD 자기지칭: `본\s*(?:꼭지|영역|슬라이드|챕터|절|항|페이지|MD|문서)` (단 `본 제안`·`본 컨소시엄`·`본 사업` 허용)
- [ ] `RFP §`, `평가기준` 인용 마커 잔존 0건
- [ ] `★N점`, `N점 中`, `평가 가산점` 잔존 0건
- [ ] 타이틀 `(★)`~`(★★★)` 접미사 잔존 0건

## 4. 슬라이드 마스터 구조

```
┌─────────────────────────────────────────────────────────┐
│ 2. {중단원} > 2.1 {소단원}                {Part}. {Part명} │ ← 풀 폭 블랙 바
│   ↑ 12pt Regular  ↑ 16pt Bold (강조)       ↑ 11pt Medium │   (y: 0~0.55)
╭─────────────────────────────────────────────────────────╮ ← 라운드 카드 시작
│                                                         │   (y: 0.55, 상단 라운드)
│   {거버닝 메시지 — 회색 14pt, "~합니다" 체}              │   (y: 0.85 ~ 1.55)
│                                                         │
│ [메인 콘텐츠 영역 — 슬라이드 고유 콘텐츠]               │   (y: 1.95 ~ 6.95)
│                                                         │
│ {clientName}        - N -        [●] {proposerName}     │ ← 푸터 (y: 7.15)
└─────────────────────────────────────────────────────────┘
                  10" × 7.5" (4:3)
```

| 영역 | Y 좌표 | 역할 |
|---|---|---|
| 상단 블랙 바 (GNB) | 0 ~ 0.55" | 좌: 중단원(12pt R) > 소단원(16pt B) / 우: Part 명(11pt M) — 모두 흰색 |
| 라운드 카드 시작점 | 0.55" | 상단 양쪽 모서리 라운드 (`rectRadius: 0.25"`) |
| 거버닝 메시지 | 0.85 ~ 1.55" | 회색 14pt 1~2줄 — 헤더 직하 |
| 메인 콘텐츠 | 1.95 ~ 6.95" | 슬라이드 고유 콘텐츠 |
| 푸터 | 7.15 ~ 7.45" | 좌({clientName}) / 중(- N -) / 우(브랜드 점 + {proposerName}) |

## 5. 푸터 시스템

| 위치 | 컴포넌트 | 좌표 (x, y) |
|---|---|---|
| 좌하 | {clientName} 로고/텍스트 (`headerBg` 10.5pt Bold) | `0.3, 7.15` |
| 중앙 | 페이지 번호 "- N -" (`gray500` 8.5pt) | center, `y: 7.15` |
| 우하 | 브랜드 점(`brand`, 0.22") + {proposerName} 텍스트 | `8.78, 7.18` (점) / `9.05, 7.15` (텍스트) |

> **전략**: 파트너십을 강조하기 위해 양 끝단에 고객사·제안사를 배치하는 전형적인 제안서 포맷.

## 6. 반복 컴포넌트

### 6-1. 사이드 라벨 + 카드 그리드 (메인 패턴)

| 행 | 사이드 라벨 | 카드 헤더 | 카드 본문 보더 |
|---|---|---|---|
| As-Is | `gray100` 배경 + `gray500` 좌측 보더 | `gray700` 채움 | `gray300` |
| **To-Be (강조)** | **`accentLite` 배경 + `accent` 좌측 보더** | **`accent` 채움 + 흰 텍스트** | **`accent`** |
| 챕터 매핑 | `headerBg` 채움 + `accent` 좌측 보더 | 흰 배경 + `accent` 사각 마커 | `gray500` |

### 6-2. 화살표 (As-Is → To-Be)
- `pres.shapes.DOWN_ARROW`, 채움 `accent`, 크기 `0.28" × 0.24"`

### 6-3. 인용/결론 박스
- 배경 `accentLite` + 좌측 `accent` 보더 (`0.08"` 두께)
- 형식: `"통념"(회색 12pt)` + `가 아니라,` + `"제안 메시지"(accent Bold 13pt)`

### 6-4. 강조 키워드 (본문 내)
- 핵심 키워드만 `accent` Bold, 슬라이드당 1~3개로 제한 (남용 금지)

## 7. Win Theme 배지 (헤드라인 슬라이드 우상단)

제안의 메인 차별화 메시지를 4~6개의 Win Theme으로 정리해 클라이맥스 슬라이드에 배지로 배치한다. 메시지 자체는 프로젝트별로 정의한다.

- **배지 스타일 2종**: ① `accent` 채움 + 흰 텍스트 (최상위 메시지) ② `headerBg` 채움 + `accent` 좌측 보더 (보조 메시지)
- **사용 원칙**: 동일 메시지를 여러 슬라이드에 반복 노출해 클라이맥스 구조를 보강하되, 배지는 **슬라이드당 최대 1개**. 배지에 평가 점수는 표기하지 않는다 (§3-4 #3).

## 8. pptxgenjs 구현 표준 코드

### 8-1. 슬라이드 시작
```javascript
const pres = new pptxgen();

const slide = pres.addSlide();
slide.background = { color: "1A1A1B" };  // headerBg — 헤더 영역으로 자연 노출
```

### 8-2. 표준 헤더 + 라운드 카드 (모든 슬라이드 공통)
```javascript
// 1. 라운드 카드 (상단 양쪽만 라운드, 하단은 슬라이드 너머로 빠짐)
slide.addShape(pres.shapes.ROUNDED_RECTANGLE, {
  x: 0, y: 0.55, w: 10, h: 7.5,
  fill: { color: "FFFFFF" }, line: { type: "none" },
  rectRadius: 0.25,
});

// 2. 좌측 GNB — rich-text 2 run (12pt Regular 중단원 + 16pt Bold 소단원)

  { text: "1. {중단원명}  >  ", options: { fontSize: 12, bold: false } },
  { text: "1.5 {소단원명}", options: { fontSize: 16, bold: true } },
], {
  x: 0.4, y: 0, w: 7.4, h: 0.55,
  fontFace: "Pretendard", color: "FFFFFF",
  valign: "middle", align: "left", margin: 0, charSpacing: -0.2,
});

// 3. 우측 GNB — Part 명 (단일 run)
slide.addText("Ⅶ. {Part명}", {
  x: 7.85, y: 0, w: 1.85, h: 0.55,
  fontFace: "Pretendard", fontSize: 11, color: "FFFFFF",
  valign: "middle", align: "right", margin: 0, charSpacing: -0.2,
});

// 4. 본문 타이틀은 두지 않는다 — 헤더 16pt Bold 소단원이 대체.

// 5. 거버닝 메시지 — 헤더 직하 (y 0.85, h 0.7), 14pt 고정
slide.addText([/* governing runs — 절 단위 \n 줄바꿈 */], {
```
