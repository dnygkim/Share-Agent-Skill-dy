# dev-reading — 개발자료 해설 스킬(기획자용)

개발자에게 받은 API 명세 · DB 스키마/ERD · 기술문서를 넣으면 비개발 기획자 눈높이의 4단 해설(한눈에 · 풀어보기 · 용어 노트 · 기획자 체크포인트)과 개발자에게 그대로 보낼 질문 목록이 나오는 스킬

## 한눈에 보기

|:---|:---:|

| <sub>이럴 때 사용</sub> | <sub>개발자에게 받은 자료가 이해되지 않을 때 · 기획자 관점의 확인 포인트가 필요할 때 · 개발자 미팅 전 질문 준비</sub> |

## 이렇게 요청

| <div align="center"><sub>상황</sub></div> | <sub>요청 예시</sub> | <sub>나오는 것</sub> |
|:---|:---:|:---:|
| <sub>API 명세를 받았을 때</sub> | <sub>`이 API 명세 풀어줘`</sub> | <sub>엔드포인트별 「무엇을 주면 무엇이 나오는지」 해설 + 체크포인트</sub> |
| <sub>DB 구조 · ERD를 받았을 때</sub> | <sub>`ERD 해석해줘` · `이 DB 구조 뭔 뜻이야`</sub> | <sub>테이블 · 컬럼 · 관계 해설 + 삭제 정책 등 확인 질문</sub> |
| <sub>기술문서가 어려울 때</sub> | <sub>`개발자한테 받은 문서인데 이해가 안 가` · `이 기술문서 정리해줘`</sub> | <sub>목적 · 핵심 규칙 · 전제 정리 + 기획 가정과 다른 점</sub> |
| <sub>기획 관점이 필요할 때</sub> | <sub>`기획자 입장에서 이 자료 어떻게 봐야 해`</sub> | <sub>기획 · 일정 영향 · 빠진 항목 · 복사용 질문</sub> |
| <sub>파일로 남길 때</sub> | <sub>`파일로 만들어줘`</sub> | <sub>`{자료명}_해설_YYYYMMDD.md`</sub> |
| <sub>분량 조절</sub> | <sub>`요약만` · `자세히`</sub> | <sub>상세도를 바꾼 해설</sub> |

- 이미지 캡처 · 표 붙여넣기 · PDF/워드 파일 모두 입력 가능
- 영문 요청(`explain this API spec` · `decode this schema`)도 같은 동작

## 진행 단계

```
① 자료 감지 · 분류 → ② 원문 추출 → ③ 평이 번역 → ④ 기획자 관점 분석 → ⑤ 4단 출력
```

| <div align="center"><sub>단계</sub></div> | <sub>하는 일</sub> | <sub>사용자 할 일</sub> | <sub>결과물</sub> |
|:---|:---:|:---:|:---:|
| <sub>① 자료 감지 · 분류</sub> | <sub>API 명세 · DB 스키마/ERD · 기술문서 · 복합 판별 · 입력 게이트 적용(아래 표)</sub> | <sub>자료 첨부 · 붙여넣기 · 방대한 자료면 우선순위 지정</sub> | <sub>자료 유형</sub> |
| <sub>② 원문 추출</sub> | <sub>엔드포인트 · 테이블 · 항목 목록화(원문에 있는 것만) · 이미지 판독분 전체에 `[이미지 인식 기반 — 개발자 확인 필요]` 자동 부착</sub> | <sub>흐릿한 캡처면 선명한 이미지 · 텍스트 원본 재제공</sub> | <sub>원문 구조 목록</sub> |
| <sub>③ 평이 번역</sub> | <sub>기획자 언어로 번역 · 근거 위치 표기 · 불확실 항목 `[개발자 확인 필요]` · 도메인 용어는 원문 표기 + 추정 의미 병기</sub> | <sub>—</sub> | <sub>풀어보기 초안</sub> |
| <sub>④ 기획자 관점 분석</sub> | <sub>기획 · 일정 영향(빈 값 허용 · 삭제 정책 · 화면 영향) · 빠진 것(인증 · 에러 포맷 · 권한 분기 · 버전) · 개발자에게 보낼 질문 문장 작성</sub> | <sub>—</sub> | <sub>기획자 체크포인트</sub> |
| <sub>⑤ 4단 출력</sub> | <sub>한눈에 · 풀어보기 · 용어 노트 · 기획자 체크포인트 조립 · 출력이 잘리면 마지막 완료 섹션 표시</sub> | <sub>내용 확인 · 필요 시 `파일로 만들어줘` · 잘린 경우 `계속`</sub> | <sub>대화창 해설 또는 .md</sub> |

- 복합 자료(API + DB 등) = 유형별 섹션 분리 후 각각 4단 출력

입력 게이트 — 해설 대신 안내 후 정지

| <div align="center"><sub>상황</sub></div> | <sub>처리</sub> |
|:---|:---:|
| <sub>개발자료가 아닌 문서(회의록 · 기획서 · 요구사항)</sub> | <sub>「API 명세 · DB 스키마 · 기술문서 전용」 안내 후 정지</sub> |
| <sub>소스코드 · SQL 실행문 혼입(java · python 코드 · INSERT/UPDATE/DELETE)</sub> | <sub>해당 블록 해석 제외 · 「소스코드 범위 밖」 표기</sub> |
| <sub>방대한 자료(API · 테이블 수십 개)</sub> | <sub>앞부분만 임의 처리 대신 우선순위 질문으로 범위 축소</sub> |
| <sub>유형 불명확(잘린 텍스트 한두 줄)</sub> | <sub>추측 대신 자료 종류 먼저 질문</sub> |

|:---|:---:|
| <sub>한눈에</sub> | <sub>자료가 무엇인지 1~3문장 또는 개조식 요약 · 핵심</sub> |
| <sub>풀어보기</sub> | <sub>항목별 평이 번역 · 근거(「자료의 ○○ 기준」) · 불확실 항목 `[개발자 확인 필요 — 이유]` · 항목이 많으면 표</sub> |
| <sub>용어 노트</sub> | <sub>자료에 나온 전문용어 + 쉬운 뜻 + 왜 이렇게 하는지</sub> |
| <sub>기획자 체크포인트</sub> | <sub>기획 · 일정 영향 / 빠진 것(통상 있어야 하는데 없는 항목) / **개발자에게 바로 물을 질문**(복사용)</sub> |

- 출력 스타일: 이모지 · 아이콘 없이 개조식(명사형) · 표 허용 · 군더더기 수식어 제외
- 머리말: 자료 유형 표기 · 이미지 판독분은 `[이미지 인식 기반]` 표기

### 결과 예시

- 입력: 배송 상태 조회 API 명세(가상) 붙여넣기 + `이 API 명세 풀어줘`
- 결과 일부

> **한눈에**
> - 주문 번호로 배송 상태를 조회하는 API
>
> **기획자 체크포인트**
> - 택배사·송장번호 빈 값 가능 → "미정" 표시 처리 필요
> - 개발자에게 물어볼 질문: "취소·반품 상태도 이 API로 확인되나요?"

- 전체 예시: [samples/해설_예시.md](samples/해설_예시.md)

## 주의 · 함께 쓰기

- 확실한 것만 단정 · 추론과 짐작은 `[개발자 확인 필요]`로 분리
- 모든 해설에 근거 위치 표기 · 자료에 없는 내용을 「일반적으로는~」으로 메우기 금지
- 읽은 것(풀어보기)과 확인할 것(체크포인트) 분리
- 통상 있어야 하는데 빠진 항목(인증 방식 · 에러 응답 포맷 · 삭제 정책 등)은 지어내지 않고 누락으로 지적
- 「아마 ~일 것」 · 「보통 이런 경우엔」 · 「자료엔 없지만 일반적으로」 = 추정 신호 → 체크포인트로 분리
- 틀린 해설보다 확인 질문 목록이 기획자에게 유용 · `[개발자 확인 필요]`가 많은 결과도 정상
- 짝 분신 「개발 통역하는 나」(원본 리포 `personas/jieun/agents/jieun-dev-translator.md`, 이 리포 미포함)
  - 여러 자료를 이어서 보거나 「방금 그 API랑 이 ERD 연결해줘」처럼 대화를 이어갈 때 = 분신
  - 자료 하나를 빠르게 해설받을 때 = 이 스킬
