# meeting-minutes — 회의록 작성 스킬

회의 녹취록이나 메모를 넣으면 이해 차이 · 검토 사유 · 항목별 TO-DO까지 챙긴 표준 엑셀 회의록(회의 개요 · 회의 내용 · TO-DO · 이슈)과 확인 필요 목록이 나오는 스킬

## 한눈에 보기

| <div align="center"><sub>항목</sub></div> | <sub>내용</sub> |
|:---|:---:|
| <sub>목적</sub> | <sub>「누가 무엇을 다시 확인 · 정정 · 전달해야 하는지」가 보이는 회의록 · 단순 나열이 아닌 후속 책임 정리</sub> |
| <sub>이럴 때 사용</sub> | <sub>클로바노트 녹취록 정리 · 고객사 미팅 직후 회의록 공유 · 회의록을 처음 쓰는 경우(「녹취록 있으세요?」부터 단계별 안내)</sub> |

| <sub>녹취 없이 메모만</sub> | <sub>(메모 붙여넣기) `오늘 미팅 내용 회의록으로 만들어줘`</sub> | <sub>메모 기반 회의록 · 발언 단위 분석 일부 제외 사전 안내</sub> |
| <sub>회의록이라는 말 없이</sub> | <sub>`미팅 내용 정리해서 공유해야 해`</sub> | <sub>위와 같은 흐름</sub> |
| <sub>바로 받고 싶을 때</sub> | <sub>`초안 확인 없이 바로 만들어줘`</sub> | <sub>초안 검토 생략 · 확인 필요 목록은 반드시 전달</sub> |

## 진행 단계

```
① 준비물 확인 → ② 기본 정보 확인 → ③ 분석 · 초안 작성 → ④ 초안 검토(GATE) → ⑤ 엑셀 생성 → ⑥ 마무리 안내
```

| <div align="center"><sub>단계</sub></div> | <sub>하는 일</sub> | <sub>사용자 할 일</sub> | <sub>결과물</sub> |
|:---|:---:|:---:|:---:|
| <sub>① 준비물 확인</sub> | <sub>녹취록 유무 → 선택 재료(본인 메모 · 회의 자료 · 직전 회의록) 순서로 하나씩 질문</sub> | <sub>녹취록 · 메모 첨부</sub> | <sub>입력 자료</sub> |
| <sub>② 기본 정보 확인</sub> | <sub>프로젝트명 · 회의명 · 일자 · 작성자 · 참석자(양측 구분) · 근거문서를 원천 자료에서 추출해 채운 값 제시(사용자 직접 작성 불필요)</sub> | <sub>틀린 부분만 정정 · 원문에 없는 항목 답변</sub> | <sub>회의 개요</sub> |
| <sub>③ 분석 · 초안 작성</sub> | <sub>안건 영역별 묶음 · 이해 차이 · 자료 무효 · 검토 사유 · TO-DO 분해 · 이슈 기록(작성 원칙 3가지 적용)</sub> | <sub>—</sub> | <sub>마크다운 초안</sub> |
| <sub>**④ 초안 검토 (GATE)**</sub> | <sub>엑셀 전 대화창에 초안 표시 + 봐야 할 지점 안내(미정 항목 · 양측 입장 분리 안건)</sub> | <sub>**미정 항목 보완 · 이해 차이 해석이 사실과 맞는지 확인**</sub> | <sub>확정 초안</sub> |
| <sub>⑤ 엑셀 생성</sub> | <sub>초안 → JSON → `build_minutes.py`로 표준 템플릿 채우기(서식 · 병합 셀 보존, 행 자동 추가)</sub> | <sub>—</sub> | <sub>`[프로젝트명] 회의록_YYYYMMDD.xlsx`</sub> |
| <sub>⑥ 마무리 안내</sub> | <sub>값 검증 후 파일 위치 · 확인 필요 목록 · 다음 행동(공유 메일 정리 등) 안내</sub> | <sub>참석자에게 확인 필요 항목 확인</sub> | <sub>완성 회의록</sub> |

입력별 역할 — 같이 주면 품질 상승

| <div align="center"><sub>입력</sub></div> | <sub>필수 여부</sub> | <sub>효과</sub> |
|:---|:---:|:---:|
| <sub>녹취록</sub> | <sub>사실상 필수(없으면 메모로 대체)</sub> | <sub>회의 내용 · 할 일의 근거</sub> |
| <sub>본인 메모</sub> | <sub>권장</sub> | <sub>녹취에 안 잡힌 맥락 · 검토 사유 보완</sub> |
| <sub>회의에서 같이 본 자료(PPT/엑셀)</sub> | <sub>권장</sub> | <sub>「이 자료의 이 부분은 무효」 기록 가능</sub> |
| <sub>직전 회의록</sub> | <sub>선택</sub> | <sub>지난 결정이 뒤집힌 부분 감지</sub> |

- 메모만으로도 생성 가능 · 단 발언 단위 기록이 없어 「누가 어떻게 이해하고 있었는지」 분석은 제외 가능

## 산출물

엑셀 1시트(시트명 = 회의 날짜) · 표준 양식 `assets/회의록_템플릿.xlsx` 기반

| <div align="center"><sub>블록</sub></div> | <sub>칸</sub> |
|:---|:---:|
| <sub>회의 개요</sub> | <sub>제목 `[프로젝트명] 회의록` · 회의명 · 일자 · 작성자 · 참석자(양측 구분, 직급/직책 생략) · 근거문서</sub> |
| <sub>회의 내용</sub> | <sub>구분 · 항목(번호 목록) · 내용(상세) · 비고</sub> |
| <sub>TO-DO TASK</sub> | <sub>항목 · 영역(누가) · 내용(요청 형식 포함) · 요청일 · 완료희망일 · 완료일 · 담당자</sub> |
| <sub>ISSUE REPORT</sub> | <sub>항목 · 영역 · 내용 및 처리방안 · 현황 · 발생일 · 처리예정일 · 처리완료일</sub> |

- 참석자 구분 = 고객사/수행사 기본 · 사내 회의처럼 구도가 다르면 팀 · 부서 단위
- 이슈 = 프로젝트 진행을 막는 문제가 언급됐을 때만 기록

### 작성 원칙 3가지

| <div align="center"><sub>원칙</sub></div> | <sub>내용</sub> | <sub>표기</sub> |
|:---|:---:|:---:|
| <sub>1 서로 다르게 알고 있던 것</sub> | <sub>양측이 다르게 이해한 안건은 「누가 어떻게 알고 있었는지」 나눠 기록 · 회의에서 「그 자료는 무시하세요」라고 한 부분은 어떤 파일의 어떤 위치 · 사유까지 기록</sub> | <sub>`[이해 차이 확인]` · `[자료 일부 무효]`</sub> |
| <sub>2 「검토해볼게요」의 이유</sub> | <sub>「내부 논의 후 전달」 · 「검토해보겠다」 항목에 왜 검토하는지 배경 · 쟁점 병기 → 나중에 정확한 회신 유도</sub> | <sub>`검토 사유: …`</sub> |
| <sub>3 할 일은 하나씩</sub> | <sub>「정리해서 전달드릴게요」를 한 줄로 뭉치지 않고 전달물 하나 = TO-DO 한 행 · 담당자 · 기한 · 요청 형식까지 · 우리가 요청한 사항도 빠짐없이 등재</sub> | <sub>`- 형식: …`</sub> |

표기 통일

| <div align="center"><sub>상황</sub></div> | <sub>표기</sub> |
|:---|:---:|
| <sub>기한 · 담당자 미언급</sub> | <sub>`미정(확인 필요)`</sub> |
| <sub>발언자 불명</sub> | <sub>`화자 미상`</sub> |
| <sub>검토 사유 미언급</sub> | <sub>`검토 사유: 회의 중 미언급 — 확인 필요`</sub> |
| <sub>자료 일부 제외</sub> | <sub>`[자료 일부 무효]` 파일명 + 위치 + 사유</sub> |
| <sub>녹취 유실 · 불명확 구간</sub> | <sub>`녹취 불명확 — 원문 확인 필요`</sub> |

## 설치 · 단독 사용

```bash
cp -r skills/meeting-minutes ~/.claude/skills/meeting-minutes
```

- 리포 루트 기준 명령 · 스킬 일괄 설치는 원본 리포 `bash install-global.sh` · 공유 리포 `share/update.sh`
- 의존성: Python 3 + `openpyxl`(`build_minutes.py` 실행용 · `pip install openpyxl`) · `python3`이 없으면 `python`
- 실행은 Claude 담당 — 확정 초안을 `data.json`(임시 폴더)으로 변환 → 스크립트 실행 → 엑셀은 사용자 작업 폴더 저장
- 하네스 안에서: 이 스킬을 호출하는 하네스 미지정 · `sync-skills`가 전체 스킬을 `agent/proposal` · `agent/feature-spec-sb` · `agent/test-runner`의 `.claude/skills/`로 복사하므로 그 폴더 세션에서도 사용 가능

## 주의

- 초안 확인 없이 바로 엑셀 생성은 기본 금지 — 이해 차이 판단 · TO-DO 분해는 잘못 쓰면 되돌리기 어려운 해석 작업
- 이해 차이 · 검토 사유는 근거 발언 · 자료 위치를 먼저 확인한 뒤에만 기록 · 근거를 인용할 수 없으면 기록 제외
- 이해 차이가 없는 평범한 회의에 억지 차이 생성 금지
- 「맥락상 이 사람이 담당일 것」 · 「보통 일주일 뒤가 기한」 같은 추정 금지 → `미정(확인 필요)`
- 빈 칸 = 정보 부족의 정직한 표시 · 채우기 위한 추정 금지
- 녹취 유실 · 불명확 구간은 앞뒤 맥락으로 재구성 금지
- 이미지 스캔 등 텍스트를 읽을 수 없는 입력 = 시작 전 안내 · 진행 여부 확인
- 긴 녹취록 = 나눠 읽되 같은 안건 반복 등장 대비 최종 결론은 전체를 읽은 뒤 판단
- 스크립트 실패 시 마크다운 초안을 .md 파일로 저장해 분석 결과 보존
