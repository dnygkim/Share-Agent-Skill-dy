# Handoff — 컨텍스트 초기화 전 맥락 저장

사용자가 `/clear`로 컨텍스트를 비우기 전에, 다음 세션이 바로 이어받을 수 있도록
현재 작업 상태를 `<프로젝트 루트>/.claude/HANDOFF.md`에 기록한다.
`/clear` 뒤에는 SessionStart 훅이 이 파일을 자동으로 읽어 컨텍스트에 올린다.

## 절차

1. 프로젝트 루트(현재 작업 디렉터리)에 `.claude/` 폴더가 없으면 만든다.
2. 아래 양식으로 `.claude/HANDOFF.md`를 **덮어쓴다**(이전 핸드오프는 지운다).
3. 작성 후 사용자에게 한 줄로 알린다: "핸드오프 저장 완료. 이제 `/clear` 하셔도 됩니다."

## 작성 원칙

- 대화를 요약하지 말고 **다음 세션이 곧바로 일할 수 있는 정보**만 적는다.
- 파일 경로·명령·브랜치명·URL은 정확히 그대로 적는다. 추측으로 채우지 않는다.
- 사용자가 내린 결정(무엇을 하기로/하지 않기로 했는지)은 빠뜨리지 않는다.
- 전체 길이는 40줄 안팎으로 유지한다. 길어지면 "다음 할 일"을 우선 남긴다.
- 인자가 있으면(`/handoff <메모>`) "사용자 메모" 항목에 그대로 넣는다.

## 양식

```markdown
# HANDOFF — YYYY-MM-DD HH:MM

## 작업 목표
(이 세션에서 하려던 일, 1~2문장)

## 진행 상태
- 완료: ...
- 진행 중: ... (어디까지 됐는지)
- 막힌 것: ... (원인·시도한 것)

## 사용자 결정 사항
- ...

## 다음 할 일 (우선순위순)
1. ...
2. ...

## 관련 파일·명령
- `path/to/file` — 무엇인지
- `command` — 언제 쓰는지

## 사용자 메모
(있으면)
```

## 다음 세션에서 이 파일을 읽었을 때

- 첫 응답에서 "이전 핸드오프를 읽었다"고 한 줄로 알리고, **다음 할 일 1번부터** 바로 이어간다.
- 핸드오프 내용이 현재 코드·파일 상태와 다르면 파일이 우선이다. 다른 점을 짚고 진행한다.
- 작업이 끝나 더 이상 필요 없으면 사용자에게 `.claude/HANDOFF.md` 삭제 여부를 묻는다.
