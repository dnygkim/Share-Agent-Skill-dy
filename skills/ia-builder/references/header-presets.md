# 헤더 양식 프리셋 참조

IA의 Depth 구조 원칙(기본정의·계층)은 어디서나 같지만, **헤더행(컬럼)은
프로젝트·플랫폼·서비스마다 조금씩 다르다.** 기존 양식이 있으면 그 헤더를 따르고,
없으면 아래 프리셋 중 서비스 성격에 맞는 것을 제안한다.

## 프리셋 A — 기본형 (사이트 구조 및 기능정의)

에이전시 웹/앱 구축 프로젝트의 표준형. 기능정의까지 한 파일에 담는다.

| 컬럼 | 정의 — 무엇을 적는 칸인가 | 작성 규칙·예시 | 채움 단계 |
|---|---|---|---|
| Code | 화면 코드 | `1.1`, `A.3.2`, `H.1` | 골격 |
| Depth1~5 | 메뉴 계층 (한 칸씩 들여쓰기) | 해당 Depth 칸에만 이름 | 골격 |
| 페이지 정의/요구사항 | 화면 유형과 핵심 목적 | `유형 — 핵심 목적` 형태 | 디벨롭 |
| 세부 사항 | 화면 안 구체 요소 | 필드·검증·정렬·연동 콤마 나열 | 디벨롭 |
| Page | 화면 수 | 숫자, 맨 아래 총계 SUM | 디벨롭 |
| 개발구분 | 디자인/퍼블리싱/개발 ● | page-types.md 추천 기준 | 디벨롭 |
| 비고 | 구분 메모·2차 표시 | — | 수시 |

JSON: 기본 동작(`layout` 불필요). `columns`로 선택 컬럼만 지정.

## 프리셋 B — 플랫폼형 (비즈니스 플랫폼·SaaS)

플랫폼(사용자군)별로 시트를 나누고, 역할별 접근권한을 O 1칸으로 표시하는 양식.
**실전 예시 파일: `신승-비즈니스AI플래너_IA(메뉴구조도)_v0.01_260721.xlsx`** (이 폴더)
— 헤더 표기·Description 작성 수준·시트 구성을 참고할 때 이 파일을 연다.

예시 파일에서 볼 수 있는 이 양식의 특징:
- 시트 구성: `문서표지` → `변경이력` → 플랫폼별 IA 시트(`1.통합관리자`,
  `2.일반사용자(납세자)` …). 변경이력 컬럼은 `버전/일자/변경 내용/작성/변경 상세`.
  ※ 이 양식을 따를 때 부속 시트(표지·변경이력)도 예시 파일 구조에 맞춘다.
- Depth 라벨은 공백 포함 `Depth 0`~`Depth 4` → `labels`로 지정.
- 헤더에 정책 주석을 붙이기도 한다(예: `Description *개인정보 마스킹정책 별도 제공`)
  → 해당 시트의 `labels`로 붙인다.
- 역할 컬럼은 플랫폼(시트)마다 다르다 — 통합관리자 시트는 역할 칸 없음,
  일반사용자 시트는 `대표자/경리/인사/기본(조회)`.

| 컬럼 | 정의 — 무엇을 적는 칸인가 | 작성 규칙·예시 | 채움 단계 |
|---|---|---|---|
| No | Depth 경로 번호 | `0`, `0.1`, `0.1.1` — 상위번호.하위순번 | 골격 |
| Page/UI Type | 행의 성격 | `Page` `Conceptual Menu` `Popup` `Tab` 등 | 골격 |
| Depth 0~4 | 메뉴 계층 (0부터 시작) | 해당 Depth 칸에만 이름 | 골격 |
| 역할 컬럼(들) | 역할별 접근/사용 권한 | `O`=가능, 빈칸=불가 (역할당 1칸) | 디벨롭 |
| Description | 화면 정의·요구사항 | `- ` bullet 나열, 정책 주석(`*마스킹정책 별도 제공` 등) 포함 | 디벨롭 |

JSON 매핑:

```json
{
  "max_depth": 4,
  "depth_min": 0,
  "roles_style": "single",
  "labels": {"code": "No", "detail": "Description"},
  "layout": ["code",
             {"key": "ui_type", "label": "Page/UI Type", "width": 14, "align": "center"},
             "depths", "roles", "detail"],
  "sheets": [
    {"sheet_name": "1.통합관리자", "title": "Platform 1 - 통합관리자", "rows": []},
    {"sheet_name": "2.일반사용자", "title": "Platform 2 - 일반사용자",
     "roles": ["대표자", "경리", "인사", "기본(조회)"], "rows": []}
  ]
}
```

- 행 예: `{"depth": 0, "name": "로그인", "code": "0", "ui_type": "Page",
  "auth": {"대표자": "O"}, "detail": "- ID(이메일)·PW 입력"}`

## 프리셋 C — 관리자 권한형 (Admin CRUD)

Admin 화면에서 역할별로 등록/조회/수정/삭제를 구분해야 할 때. 기본형에
`roles`를 더하면 역할마다 C/R/U/D 4칸이 생긴다(기본 `roles_style: "crud"`).
자세한 권한 추천값은 `page-types.md` §3 참조.

## 컬럼 정의표 양식 (스키마 확정 때 사용자에게 제시)

새 양식을 파싱했거나 프리셋을 변형할 때, 생성 전에 이 표로 확인받는다:

| 컬럼(헤더 표기) | 정의 — 무엇을 적는 칸인가 | 작성 규칙·예시 | 채움 단계 |
|---|---|---|---|
| (파일에서 읽은 헤더명) | (데이터 몇 행을 보고 추론한 쓰임) | (실제 값 예시) | 골격/디벨롭 |

- **정의는 헤더명이 아니라 데이터에서 추론한다.** 같은 "Description"이라도
  프로젝트마다 요구사항 수준이 다르다 — 실제 채워진 행을 몇 개 읽고 판단.
- **채움 단계** — 구조 컬럼(번호·Depth·유형)은 골격 단계, 내용 컬럼(정의·권한·
  수치)은 디벨롭 단계. 사용자가 다르게 정하면 그걸 따른다.

## 채움 단계 기본 가이드

1. **골격(v0.1)**: No/Code · Depth · 유형(Page/UI Type) — 구조 확정용
2. **디벨롭 1**: Description(화면 정의·요구사항) — 내용의 중심
3. **디벨롭 2**: 권한(역할 O 또는 CRUD)
4. **디벨롭 3**: Page 수·개발구분·기타 수치 컬럼

단계 순서는 프로젝트 관행에 맞게 조정 가능. 각 단계 완료 시 검토를 받고 넘어간다.
