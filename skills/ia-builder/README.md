## 1. 무엇을 하나요

- 서비스(웹/앱)의 **메뉴 구조(사이트맵)와 기능정의서를 엑셀로 자동 생성**
- 서비스 설명만 주면 필요한 메뉴를 **1~5단계 트리**로 구성 (Depth 0 시작도 지원)
- 각 화면의 **페이지 유형·개발구분·페이지 수·역할별 권한**까지 채움
- 흔히 IA(Information Architecture, 정보구조)라 부르는 산출물
- 기획 초반, PRD·WBS보다 먼저 만드는 "서비스의 뼈대"

### 이 스킬의 두 가지 핵심 방식

**① 헤더 양식은 프로젝트를 따른다.**
IA의 Depth 구조 원칙은 어디서나 같지만, 헤더행(컬럼)은 프로젝트·플랫폼·서비스마다
조금씩 다릅니다. 기존 IA 파일이나 사내 양식을 첨부하면 Claude가 **헤더행을 읽고
각 컬럼의 정의·맥락·의도를 표로 정리해 확인받은 뒤, 그 양식 그대로** 만듭니다.
양식이 없을 때만 기본형 컬럼을 제안합니다.

**② 한 번에 다 채우지 않는다 — 골격 먼저, 컬럼별 순차 디벨롭.**
1차로 구조 컬럼(번호·Depth·유형)만 채운 골격 파일(v0.1)을 만들어 구조를 확정하고,
이후 Description → 권한 → Page 수 같은 내용 컬럼을 **그룹 단위로 순차** 채우며
단계마다 검토를 받습니다. 구조 검토와 내용 검토가 섞이지 않아 리뷰가 쉬워집니다.

## 2. 어떻게 쓰나요

Claude에게 **"OO 서비스 IA 만들어줘"** 또는 **"이 양식대로 IA 만들어줘"** 라고
요청하면, 아래 순서로 단계적으로 질문합니다 (한 번에 다 묻지 않음).

### 진행 순서

1. **프로젝트명 · 서비스 개요** — 기획서/PRD가 있으면 첨부 (먼저 읽고 반영)
2. **화면·플랫폼 구분** — 일반 사용자만인지, 관리자(Admin) 화면도 있는지.
   관리자가 있으면 Front/Admin 시트 분리, 플랫폼이 여럿이면(통합관리자/일반사용자 등)
   플랫폼별 시트 분리. 역할별 권한이 다르면 역할 목록 확인
3. **헤더 양식 확인** — 갈림길:
   - **기존 양식/IA 파일이 있으면** → 첨부. Claude가 헤더행을 파싱해
     **컬럼 정의표**(컬럼별 정의·작성 규칙·채움 단계)를 보여주고 확인받은 뒤
     그 양식을 그대로 재현
   - **없으면** → 넣을 컬럼을 선택지로 제안 (페이지 정의·개발구분·페이지 수·
     세부 사항·Tab·권한)
4. **메뉴 트리 초안** — 대분류부터 제시 → 빼고 더하며 확정
5. **골격 파일 생성 (v0.1)** — 번호·Depth·유형 등 구조 컬럼만 채운 파일
   → 구조 검토·확정
6. **컬럼별 순차 디벨롭** — Description(화면 정의) → 권한 → Page 수·개발구분
   순으로 채우며 단계마다 검토. 순서는 스키마 확정 때 조정 가능

### 파일 관리 방식 (시작할 때 확인)

| <div align="center"><sub>방식</sub></div> | <sub>설명</sub> | <sub>언제</sub> |
|:---|:---:|:---:|
| <sub>버전업 새 파일</sub> | <sub>단계마다 v0.1 → v0.2 … 새 파일 생성</sub> | <sub>기본값</sub> |
| <sub>정본 제자리 수정</sub> | <sub>정본 파일을 직접 수정, **수정 전 백업 필수**</sub> | <sub>프로젝트 규칙이 그럴 때</sub> |

버전 번호는 임의로 올리지 않습니다. 이미 있는 IA 파일을 디벨롭할 때도
**Depth 구조(골격)는 유지**하고 지정된 컬럼만 채우거나 수정합니다.

### 이렇게 말하면 됩니다

| <div align="center"><sub>상황</sub></div> | <sub>Claude에게</sub> |
|:---|:---:|
| <sub>새 서비스 기획</sub> | <sub>"프리랜서 매칭 플랫폼 IA 만들어줘"</sub> |
| <sub>화면 목록이 막막할 때</sub> | <sub>"쇼핑몰 앱 만드는데 어떤 화면 필요한지 사이트맵 짜줘"</sub> |
| <sub>기획서가 있을 때</sub> | <sub>(PRD 붙여넣고) "이거 보고 메뉴 구조 잡아줘"</sub> |
| <sub>사내/기존 양식이 있을 때</sub> | <sub>(엑셀 첨부하고) "이 양식대로 IA 만들어줘"</sub> |
| <sub>관리자 화면 포함</sub> | <sub>"사용자/관리자 화면 나눠서 정보구조도 그려줘"</sub> |
| <sub>기존 IA 디벨롭</sub> | <sub>(파일 첨부하고) "구조는 유지하고 Description만 채워줘"</sub> |

## 3. 만들어지는 결과

엑셀 시트: 표지 → 사용안내 → 개정이력 → 정보구조도(시트 여러 개 가능)

- **표지** — 프로젝트명·작성자·작성일·버전
- **사용안내** — 파일 보는 법 (컬럼 의미·행 색·권한 표시)
- **개정이력** — 버전·날짜·작성자·변경 내용
- **정보구조도** — 실제 IA 표. Front/Admin 또는 플랫폼별로 시트 분리

※ 기존 양식을 따를 때는 부속 시트(표지·변경이력) 구성도 그 양식에 맞춥니다.

### 헤더 양식 — 프리셋 2종 + 자유 양식

**기본형** (양식이 없을 때의 기본값)

| <div align="center"><sub>항상 포함</sub></div> | <sub>선택 포함</sub> |
|:---|:---:|
| <sub>Code(첫 열) · Depth1~5 · 비고</sub> | <sub>페이지 정의/요구사항 · 개발구분(디자인/퍼블/개발 ●) · Page 수+총계 · 세부 사항 · Tab/서브 플로우 · 권한(역할별 CRUD)</sub> |

**플랫폼형** (비즈니스 플랫폼·SaaS — 실전 예시: references의 신승 IA 파일)

| <div align="center"><sub>컬럼</sub></div> | <sub>내용</sub> |
|:---|:---:|
| <sub>No</sub> | <sub>Depth 경로 번호 (0, 0.1, 0.1.1 …)</sub> |
| <sub>Page/UI Type</sub> | <sub>행의 성격 (Page / Conceptual Menu / Popup / Tab …)</sub> |
| <sub>Depth 0~4</sub> | <sub>메뉴 계층 (0부터 시작)</sub> |
| <sub>역할 컬럼(들)</sub> | <sub>역할별 접근 권한 — 역할당 O 1칸 (시트마다 다를 수 있음)</sub> |
| <sub>Description</sub> | <sub>화면 정의·요구사항 ("- " bullet, 정책 주석 포함 가능)</sub> |

**자유 양식** — 위 프리셋이 아니어도, 엑셀을 첨부하면 그 헤더(컬럼 순서·이름·
Depth 시작 번호·권한 표시 방식)를 그대로 재현합니다.

### 표 규칙

- **Depth는 서비스에 맞게 유연** — 얕으면 1~2단계, 복잡하면 4~5단계, 억지로 안 맞춤
- **권한 표시 2종** — 역할별 CRUD 4칸(C=등록·R=조회·U=수정·D=삭제) 또는
  역할당 O 1칸, 양식에 맞게 선택
- **나중에 할 기능(2차)** 은 회색 행으로 표시
- **Page 수 총계**는 자동 합산(SUM 수식), 정보구조도 시트는 눈금선 꺼짐
- **내용 품질** — "게시판" 같은 한 단어가 아니라 "리스트 게시판 — 공지 목록·상세,
  상단 고정"처럼 기획자가 바로 쓸 수준으로 채움
