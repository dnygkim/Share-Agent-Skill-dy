## 1. 화면 분리 원칙

### 1.1 1화면 = 1상태

| 분리 기준 | 예시 |
|---|---|
| 페이지 전환이 일어나는 단위 | 번호 입력 → 인증번호 입력 |
| 완전히 다른 UI가 표시되는 분기 | 기존 회원 로그인 vs 신규 약관 동의 |
| 에러·차단 등 종료 상태 | 인증 차단 화면 |
| 프로세스 완료 상태 | 가입 완료 화면 |

### 1.2 에러·예외를 분리할지 판단

- **분리하지 않음** — 같은 화면에서 보여줄 수 있는 에러(인라인 에러, 필드 힌트, 토스트).
- **분리함** — 다른 화면으로 이동하는 에러(차단 화면, 서버 오류 전용 페이지).

### 1.3 화면 ID

```
기능 ID: A-01
화면 ID: A-01-001 ~ A-01-00N
```

**variant가 달라도 화면 분리 결과는 같아야 한다.** PC라서 화면을 합치거나 더 쪼개지 않는다.

## 2. Description 작성 규칙

마크업 형태(`<p class="desc-block">` + `<br>` + `<span class="lvl1|lvl2|...">`)는 `SKILL.md` §4.4에 있다.
여기서는 **무엇을 쓰고 무엇을 쓰지 않는가**를 정한다.

### 2.1 쓰지 말아야 할 것 ★

Description은 **위치 · 동작 · 내용 · 조건**만 기술한다. 아래는 기재 금지다.

| 금지 항목 | 예시 | 이유 |
|---|---|---|
| 색상값(HEX) | `#256ef4`, `#de3412` | 디자인 단계에서 확정할 사항. 기획 산출물의 결정 사항이 아님 |
| 디자인 토큰명 | `primary-50`, `gray-10`, `danger-50` | 위와 같음 |
| 픽셀 사이즈 | `44×44px`, `180px 고정 높이` | 디자이너가 결정. 와이어프레임은 비율·위치만 |
| 폰트 사이즈·굵기 | `font-size:16px`, `font-weight:700` | 위와 같음 |
| CSS 구현 코드 | `position:absolute; inset:0`, `rgba(0,0,0,.4)` | 구현 단계 결정 |
| HTML 속성값 | `type=number`, `type=date` | 입력 규칙은 의미로 표현 |

바꿔 쓰는 법:

| 이렇게 쓰지 말고 | 이렇게 쓴다 |
|---|---|
| `활성: primary-50(#256ef4), 미완: gray-10` | `현재 단계 활성 표시` (또는 해당 줄 생략) |
| `gray-20(비활성)` | `비활성` |
| `danger-50(#de3412) border + 텍스트` | `위험 액션 강조 스타일` |
| `AI 아바타(36×36px, 파랑 원)` | `좌측 AI 아바타` |
| `type=number, 1~120 범위` | `숫자 입력 (1~120, 정수)` |
| `position:absolute; inset:0 으로 캔버스 전체 커버` | `캔버스 전체 커버` |
| `딤 배경(rgba(0,0,0,.4))` | `딤 배경` |
| `주황 배경 카드로 쿠폰 목록 표시` | `적용 가능 쿠폰 목록 표시` |

**예외 — 콘텐츠·비즈니스 규칙은 써도 된다.** 디자인이 아니라 내용이기 때문이다.
입력값 범위(`1~120`, `소수점 1자리`), 글자수 제한(`최대 500자`), 개수(`3개 추천 카드`), 운영 시간·가격 같은 실제 데이터.

### 2.2 캔버스 문구를 그대로 인용한다 ★★

**캔버스에 보이는 모든 문구는 Description에 작은따옴표로 똑같이 인용한다.**
의미만 풀어 쓰거나 비슷한 문장으로 바꾸면 안 된다.

인용이 필요한 요소: 봇/사용자 메시지 본문, 다이얼로그 타이틀·본문, 알림 카드 타이틀·내용,
버튼 라벨(특히 다이얼로그 액션), placeholder, 에러·성공 메시지.

캔버스가 `현재 운영 시간입니다. 연결할까요?` 인데 Description에 `현재 연결 가능합니다.`라고 쓰면 불일치다.

**분기가 있는 화면**은 `1화면 = 1상태` 원칙상 캔버스에 한 상태만 그린다. 이때 Description은:

1. 화면 설명 문단에 **현재 그려진 상태를 명시**한다 — "현재 화면은 운영 시간 내 상태를 보여준다."
2. 분기별 항목은 이 형식으로 쓴다.
   - `현재 화면([분기명]): '[캔버스 문구 그대로]' 출력 → [동작]`
   - `[다른 분기명] 분기: '[해당 분기 문구]' 출력 → [동작]`
3. 캔버스에 그려진 분기는 반드시 **"현재 화면"** 으로 시작해 어느 쪽이 그려졌는지 드러낸다.

검증법: 캔버스에 보이는 텍스트를 한 줄씩 따라 읽으며 Description에 같은 문구가 인용돼 있는지 확인한다.

### 2.3 번호는 배지와 1:1 ★

Description의 번호 항목과 와이어프레임 넘버 배지는 **정확히 1:1**이어야 한다.
번호가 어긋나면 기획자·디자이너가 좌우를 대조하며 읽을 수 없게 된다.

- Description에는 있는데 배지가 없음 ❌
- 배지는 있는데 Description 항목이 없음 ❌

**시각적 컴포넌트가 없는 메타 정보를 번호 목록에 넣지 않는다.** 이게 번호 갭의 가장 흔한 원인이다.
아래는 번호 목록이 아니라 **상단 «화면 설명» 문단**으로 올린다.

| 메타 정보 | 예시 | 어디에 |
|---|---|---|
| 진입 조건·권한 | "관리자 권한 필수, 미보유 시 G-01 403" | 화면 설명에 한 문장 |
| 자동 상태 전이 | "파일 전송 → 청킹 → 임베딩 → 완료" | 화면 설명에 흐름 한 줄 |
| 닫기 방식(여러 개) | "✕ 버튼 / 배경 클릭 / ESC" | 화면 설명 또는 닫기 버튼 항목의 하위 |
| 예외·에러 처리 안내 | "API 실패 시 '...' 안내" | 화면 설명에 통합 |
| 빈 상태 안내 | "데이터 없을 시 '...' 표시" | 화면 설명에 한 문장 |
| 서버 검증(사용자에게 안 보임) | "중복 파일명 검사" | 관련 버튼 항목의 하위 |

번호 목록에는 **와이어프레임에 배지가 붙은 요소만** 남긴다.

## 3. HTML-to-Figma 호환

이 양식은 HTML to Figma 플러그인 임포트를 전제로 설계돼 있다. 아래를 지켜야 임포트 결과가 깨지지 않는다.

| 항목 | 규칙 | 안 지키면 |
|---|---|---|
| 볼드 유지 | Static Pretendard가 폰트 목록 1순위. `font-weight` 700/600/500/400 사용 | 볼드가 풀림. 사용자 PC에 [Static Pretendard](https://github.com/orioncactus/pretendard/releases) 설치 필요 |
| 텍스트 박스 통합 | 한 항목 = 하나의 `<p class="desc-block">`. `<br>`+`<span>`+`&nbsp;`로 계층 표현. `<div>` 분리·CSS `::before` 금지 | 한 항목이 줄마다 별도 텍스트 박스로 쪼개짐 |
| 로고 손상 방지 | 로고는 푸터의 `background-image`로 임베드. base64 문자열 수정·재편집 금지 | 로고가 깨지거나 잘림 |
| Auto Layout 호환 | 메타 헤더·Description 섹션·푸터를 단순 flex/block으로. 불필요한 wrapper 최소화 | Auto Layout 변환이 어긋남 |

앞의 세 가지는 `generate_sb.py`와 스타일 블록이 자동 처리하거나 검증한다(로고는 MD5로 검사).
**작성자가 실제로 신경 써야 하는 것은 Description을 `desc-block` 규칙대로 쓰는 것 하나**다.
