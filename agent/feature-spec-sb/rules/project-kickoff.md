# 프로젝트 착수 모드 — 신규 서비스 정의 (PRD → IA → 플로우차트 → SB)

> 이 분기는 원본 AX-Pilot의 `feature-spec`에는 없던 **신규 오케스트레이션**이다(2026-08-03 추가).
> PRD·SB 작성 엔진 자체는 원작자(황다혜 프로, AX-Pilot)의 설계를 그대로 쓰고,
> IA 생성은 이 모노레포의 `skills/ia-builder`(제작: 신지은)를 호출해 연결한 것이다.
>
> 이 분기는 `SKILL.md` §4의 공통 규칙(§4.2 골격 · §4.3 모달 · §4.4 Description · §4.5 screens.json)과
> §3의 PRD 작성 규칙을 상속한다. 여기 다시 적히지 않은 것은 원래 규칙을 따른다.

## P-1. 언제 이 분기를 타는가

기존 공통기능 ID(`A-02` 등)나 이미 있는 PRD 경로가 아니라, **완전히 새로운 서비스를 처음부터
정의**하려는 요청일 때만 이 분기를 탄다.

트리거: "OO 서비스 기획해줘", "새 프로젝트 시작", "신규 서비스 정의해줘", "OO 만들어줘"(신규
서비스 맥락 — 예: "온라인 문구점 만들어줘").

기능 ID가 언급되면 이 분기가 아니라 `SKILL.md` §3/§4 기본 모드로 간다.

## 전체 파이프라인

```
Step 0   서비스명(프로젝트명) 확인
Step 0.1 디바이스 확인 (PC / 모바일 웹 / 둘 다)
Step 0.2 작성자명 확인 (★ SKILL.md 공통 규칙)
Step 1   서비스 정의서 작성 (경량 — 서비스 전체 개요)
Step 2   IA 생성 — ia-builder 스킬 호출
Step 3   IA 화면별 플로우차트 생성 (+ 필요 시 §3 9섹션 PRD)
Step 4   화면별 SB 추출 (§4 그대로, 화면 분리는 IA 결과 사용)
```

각 Step은 앞 Step이 사용자 확정을 받아야 다음으로 넘어간다. 순서를 건너뛰지 않는다.

---

### Step 0: 서비스명 확인

```
[프로젝트 착수]
어떤 서비스를 만드시나요? 서비스명(프로젝트명)을 알려주세요.
```

답변을 프로젝트 슬러그(영문·숫자, 공백→하이픈, 예: "테스트커머스" → `test-commerce`)로
바꿔 이후 모든 산출물 경로에 쓴다. 슬러그를 못 정하면 사용자에게 영문 표기를 물어본다.

### Step 0.1: 디바이스 확인

```
[{서비스명}]
어떤 디바이스로 만드시나요?
  A) PC
  B) 모바일 웹 (MO WEB)
  C) 둘 다 (PC + 모바일 웹)

기본값은 둘 다입니다.
```

이 답을 **IA와 SB 양쪽에 재사용**한다 — Step 2·Step 4에서 같은 질문을 다시 하지 않는다.

- "둘 다"를 골라도 §4.0의 **"한 번에 한 variant만"** 규칙은 그대로 적용된다. Step 4에서
  한쪽을 다 끝낸 뒤 다른 쪽으로 넘어간다.
- 관리자(Admin) 화면 필요 여부는 여기서 함께 확인해도 되고, Step 1(대상 사용자)에서
  물어도 된다 — 어느 쪽이든 Step 2 IA에 전달되어 Front/Admin 시트 분리에 반영된다.

### Step 0.2: 작성자명

`SKILL.md` 상단 ★ 공통 규칙을 그대로 따른다. 이 값은 서비스정의서·PRD·SB 전 산출물에 재사용한다.

### Step 1: 서비스 정의서 (경량 PRD)

**`SKILL.md` §3의 9섹션 PRD와는 다른 문서다.** §3의 PRD는 공통기능 하나를 상세 정의하는
문서이고, 여기서는 **서비스 전체의 개요·목표·범위**만 짧게 정한다. Step 2의 IA가 서비스를
개별 기능으로 쪼갠 뒤, 그 각 기능에 대해서만 필요하면 §3의 9섹션 PRD를 따로 만든다(Step 3).

```markdown
# {서비스명} — 서비스 정의서

## 개요
- 서비스명: {서비스명}
- 한 줄 설명: {무엇을 하는 서비스인지}
- 디바이스: {PC | 모바일 웹 | PC + 모바일 웹}
- 작성자: {author} / 작성일: {YYYY-MM-DD}

## 목표
- {이 서비스가 해결하려는 문제 또는 달성하려는 목표}

## 대상 사용자
- {주 사용자층. 관리자(Admin) 화면이 필요하면 여기 명시 — IA의 Admin 시트 분리에 직결}

## 범위
- 포함: {1차 범위에 들어가는 것}
- 제외: {2차 이후로 미루는 것}
```

**한 줄 설명·대상 사용자·범위는 Step 2에서 ia-builder에 그대로 전달**한다 — ia-builder의
자체 시작 인터뷰가 같은 질문을 반복하지 않도록.

저장: `output/{slug}/00. 서비스 정의서.md`

### Step 2: IA 생성 — ia-builder 스킬 호출

Skill 도구로 `ia-builder`를 호출하되, Step 0·0.1·1에서 이미 확정된 정보를 프롬프트에 포함해
**ia-builder의 시작 인터뷰(0. 시작 인터뷰의 1·2·3번 — 프로젝트명·서비스 개요·대상 사용자/
플랫폼)를 반복 질문하지 않게** 한다.

```
{서비스명}의 IA를 만들어줘.
- 프로젝트명: {서비스명}
- 서비스 개요: {Step 1의 "한 줄 설명" + "목표"}
- 대상 사용자 / 플랫폼: {Step 1의 "대상 사용자"}, 디바이스는 {Step 0.1 답변}
- 작성자: {author}
```

ia-builder는 이 정보를 받은 상태로 "4. 헤더 양식 확인"부터(또는 그 이전 중 이미 답변된
항목은 건너뛰고) 진행한다. IA 파일 자체는 ia-builder의 규칙대로 **골격(v0.1) 먼저 → 컬럼별
순차 디벨롭** 순서를 따른다 — 이 흐름을 대신 건너뛰지 않는다.

저장: `output/{slug}/01. IA/{서비스명}_IA_v0.1_{YYYYMMDD}.xlsx` (ia-builder 기본 관례).
사용자가 다른 경로를 원하면 그대로 따른다.

**IA가 사용자 확정을 받기 전에는 Step 3으로 넘어가지 않는다.**

### Step 3: IA 화면별 플로우차트 생성

확정된 IA에서 화면(주로 Depth 최하위 행, `page_def`/`detail`이 채워진 행)을 훑어
**사용자 플로우 단위**로 묶는다. 한 메뉴 트리 노드 = 화면 하나지만, 여러 화면이 하나의
플로우(예: "일계부 등록 > 수입/지출 입력")를 이루면 플로우 하나로 묶어 처리한다. 이 판단은
IA의 Description·세부 사항을 근거로 한다.

플로우(기능)별로:

1. `SKILL.md` §8의 `flowchart-rules.md` 규칙으로 Mermaid를 작성해 프리뷰 → 승인받는다.
2. 승인된 플로우로 §3의 9섹션 PRD를 작성할지 사용자에게 확인한다.
   - 화면 요소가 단순하면(예: 단일 조회 화면) 생략하고 바로 Step 4로 가도 된다고 제안한다.
   - 작성하기로 하면 §3 Step 3부터 그대로 이어서 쓴다 — §3의 Step 0~2.5(작성자·프로세스
     입력·Mermaid 승인)는 이 단계에서 이미 대체됐으므로 반복하지 않는다.

여러 플로우가 있으면 플로우별로 화면 개수만큼 **한 번에 승인받는다** — 하나씩 따로 묻지
않는다(§3.5 체크리스트 검증과 같은 원칙).

저장: `output/{slug}/02. 공통 기능/{기능슬러그}/PRD/...` — §3의 저장 경로 규약
(`01. 공통 기능/{카테고리}/PRD/...`)을 프로젝트 슬러그 하위로 옮긴 것이다. 새 서비스의
기능이 기존 69개 공통기능(`guides/features-list.md`)과 성격이 겹치면 그 카테고리를
그대로 재사용해도 된다.

### Step 4: 화면별 SB 추출

`SKILL.md` §4 SB 모드를 그대로 따르되:

- §4.0의 작성자·variant 질문은 **생략**한다(Step 0.2·0.1에서 이미 확정됨).
- §4 Step 2 "PRD 분석 → 화면 분리"는 **IA가 이미 화면을 분리해 뒀으므로** IA의 화면
  목록을 그대로 화면 단위로 쓴다. Step 3(body HTML 작성)부터 §4를 그대로 따른다.

디바이스가 "PC + 모바일 웹"이면 §4.0 규칙대로 한쪽을 다 끝낸 뒤 다른 쪽을 진행한다.

저장: `output/{slug}/02. 공통 기능/{기능슬러그}/SB/...` — §4 저장 경로 규약과 동일한
패턴을 프로젝트 슬러그 하위에 둔 것이다.

---

## 요약 보고

Step 4까지 끝나면 서비스명, 산출물 목록(서비스정의서 1 · IA 1 · PRD N개 · SB 화면 M개)과
각 경로를 한 번에 정리해 사용자에게 보여준다.

## 전제 조건

`ia-builder` 스킬이 이 폴더에서 자동 로드되려면 리포 클론 후 한 번 동기화가 필요하다.

```bash
cd dykim-claude-agents-skills
./sync-skills.ps1        # 또는 bash ./sync-skills.sh
```

동기화 안 된 상태에서 이 분기 요청이 오면, Step 2에서 `ia-builder`를 호출하기 전에
동기화가 됐는지 먼저 확인하고, 안 됐으면 위 명령을 안내한다.
