# 판정 규칙 · 보류 사유 코드 · 기입 형식

## 1. 결과값 매핑

| 사용자 용어 | 엑셀 값(qa-master 드롭다운) | 뜻 |
|---|---|---|
| 정상 | `Pass` | 절차를 끝까지 수행했고 기대결과와 일치 |
| 오류 | `Fail` | 절차를 수행했으나 기대결과와 불일치(오류 화면 · 잘못된 값 · 이동 안 됨 · 콘솔 오류로 기능 중단) |
| 보류 | `Block` | 수행 자체가 막혔거나 판정할 수 없음(아래 사유 코드) |
| (범위 밖) | `미실행` | 이번 회차 범위에 없음 — 값 유지 |

- 드롭다운 값은 qa-master 정본 그대로. 한국어로 바꾸지 않는다.
- Block은 「실패」가 아니다. 선행 조건 문제로 **시도 자체가 막힌 것**(qa-master 정의). 수행했는데 결과가 틀리면 Fail.

## 2. 판정 원칙
1. **기대결과에 쓰인 것만 기준**. 기대결과에 없는 항목(디자인 어긋남 · 속도)은 Fail 근거가 아니다 → 비고에 「참고: …」로만 남긴다.
2. 기대결과가 `[확인 필요]`면 수행 후 **Block `EXPECT`** + 실제 결과에 관찰 내용 기록. Pass/Fail을 주지 않는다.
3. 절차에 없는 조작으로 우회해 Pass를 만들지 않는다. 절차대로 안 되면 Fail.
4. 애매하면 재수행 1회. 그래도 애매하면 **Block `UNSURE`**. 임의 Pass 금지.
5. 선행 TC Fail로 사전조건이 안 만들어지면 **Block `PRECOND`** + 비고에 원인 TC ID.
6. Fail의 「실제 결과」는 재현 가능하게: 표시 문구(따옴표) · 이동한 URL · HTTP 상태 · 콘솔 오류 첫 줄 · 입력값. 「안 됨」「이상함」 금지.
7. 「재현 절차」는 테스트 절차 그대로 하면 재현될 때 비워 두고, 다른 조작으로 발견했을 때만 쓴다(qa-master 정의).

## 3. 보류(Block) 사유 코드 — 비고 앞머리에 `[코드]`

| 코드 | 사유 | 비고 기입 예 |
|---|---|---|
| `MANUAL` | 자동화 불가 단계를 무인 모드에서 만남 | `[MANUAL] 절차 3 OTP 입력 — 수동 확인 필요` |
| `PRECOND` | 선행 조건 미충족 | `[PRECOND] TC-ORD-003 Fail로 주문 데이터 없음` |
| `NATIVE` | APP-WV 회차의 네이티브 기능 | `[NATIVE] 푸시 알림 — 실기기 수동 확인 필요` |
| `EXPECT` | 기대결과 `[확인 필요]` | `[EXPECT] 기대결과 미정 — 관찰: 빈 목록에 안내 문구 없음` |
| `UNSURE` | 재수행 후에도 판정 불가 | `[UNSURE] 간헐 로딩 — 재확인 필요` |
| `ACCESS` | 화면 접근 차단(권한 · IP · 점검) | `[ACCESS] 403 — 관리자 권한 계정 필요` |
| `TOOL` | 브라우저 도구 실패 반복 | `[TOOL] 클릭 미반응 3회 — 수동 확인 필요` |
| `DATA` | 테스트 데이터 없음(상품 · 쿠폰 등) | `[DATA] 품절 상품 없음 — 데이터 준비 필요` |

## 4. 엑셀 실행 컬럼 기입 형식

| 컬럼 | 기입 |
|---|---|
| 실행결과 | `Pass` / `Fail` / `Block` |
| 실제 결과 | Fail·Block 시 관찰 내용(§2-6 형식). Pass는 비워 둠(기대결과와 동일) |
| 재현 절차 | §2-7 |
| 발견 환경 | `{디바이스} · {브라우저 버전} · {OS} · {뷰포트}` + 계정 ID(비밀번호 금지) |
| 상태 | Fail → `신규`. 그 외 비움 |
| 결함 ID | 비움(결함 툴을 쓰는 프로젝트만 사용자가 연결) |
| 비고 | `증적: {TC ID}.png` · Block 사유 `[코드] …` · 수동 처리 `수동 처리: 절차 N(OTP)` · 참고 사항. 항목은 ` / `로 구분. 설계 시 적힌 비고가 있으면 그 뒤에 붙인다 |

## 5. 사용자 보고 표기
- 채팅·HTML에서는 「정상(Pass) · 오류(Fail) · 보류(Block)」 병기. 집계 순서 Pass → Fail → Block → 미실행.
- Fail 목록은 우선순위 상 → 중 → 하, 같은 우선순위면 TC ID 순.
