# 테스트 실행 에이전트 (Test Runner Harness)

이 폴더는 **qa-master가 만든 테스트케이스(TC) 엑셀을 받아 브라우저에서 직접 수행하고, 결과(Pass/Fail/Block)·증적을 기입**하는 에이전트 하네스다. **이 폴더에서 Claude Code를 열면 이 파일이 자동 로딩**되어 아래 규칙대로 동작한다. (모든 경로는 이 폴더 기준 상대경로.)

> 짝 스킬: `../../skills/qa-master`(TC 설계·엑셀 생성). qa-master가 **설계**, 이 하네스가 **실행**이다. 엑셀 양식(시트 3개 · 테스트케이스 19컬럼 · 실행결과 드롭다운 `Pass/Fail/Block/미실행`)은 qa-master 정본을 그대로 따르고 바꾸지 않는다.

## 이 에이전트가 하는 일
디바이스·엔진 확인 → TC 엑셀 로드(없으면 qa-master 모드 1로 추출) → **GATE(실행 계획 승인)** → 브라우저에서 시나리오 순서대로 TC 수행 + 전수 스크린샷 → 회차별 결과 엑셀 사본 + HTML 요약 리포트 → 완료 보고.

## 사용법 (사용자)
1. **프로젝트(Task)별로 폴더를 나눠** TC 엑셀(또는 TC가 없으면 기획서·화면설계서)을 `input/{slug}/`에 두거나 경로를 대화로 제공한다.
2. "이 TC 돌려줘 / PC에서 테스트 수행해줘 / 모바일 웹 회귀 테스트 해줘"라고 요청한다.
3. 인테이크(업무명 · 디바이스 · 엔진 · TC 범위 · 접속정보 · 수동 개입 모드)에 답한다. **접속정보(URL·테스트 계정·비밀번호)는 파일에 두지 않고 매 회차 대화로 입력**한다.
4. 실행 계획 GATE 승인 → 끝까지 무인 수행(자동화 불가 단계에서만 멈춰 묻는다) → `output/{slug}/`에 결과 엑셀·HTML·증적.

## 동작 규칙 (에이전트)

0. **★ 착수 절차 — 자료는 `input/{slug}/`을 가장 먼저 본다 (전역 검색 금지)**: "테스트 돌려줘/수행해줘/TC 실행" 류 요청이 오면 워크스페이스 전역을 헌팅하지 말고 **해당 프로젝트의 `input/{slug}/`(+대화로 준 경로)**를 확인한다.
   - TC 엑셀(qa-master 양식)이 있으면 → 정본으로 **바로 ORCHESTRATOR 파이프라인 착수**(시각 표시 후).
   - TC 엑셀은 없고 기획서·화면설계서만 있으면 → **qa-master 모드 1을 `Skill` 도구로 호출해 먼저 TC를 추출**하고(사용자 확인 후) 그 엑셀을 입력으로 삼는다. ※ 이 PC(dykim-win11)는 Python 미설치라 qa-master 모드 1(openpyxl)이 돌지 않는다 — 그때는 사용자에게 Python 설치 또는 다른 PC에서 추출한 엑셀 제공을 요청한다.
   - 둘 다 없고 경로도 안 줬으면 → **"input/{프로젝트}/에 TC 엑셀(또는 기획서)을 넣어주세요"**라고 되묻는다.
   - 이 폴더에서 도는 동안 모든 테스트 수행성 요청은 이 하네스로 라우팅한다(단순 질문·코드 수정 등 비산출물 작업은 예외).

1. **`ORCHESTRATOR.md`를 읽고 파이프라인으로 처리한다**: device-checker → tc-loader → **GATE(실행 계획 승인)** → runner → reporter.
   - **Dan Jr. 등급 조회(승인 게이트 공통)**: 인테이크 질문·GATE·「~할까요?」를 묻기 직전에 `~/.claude/persona/persona.md`(전역 규칙이 없는 환경은 `../../persona/persona.md`)에서 같은 상황을 찾는다. 등급 **A**면 묻지 않고 기본값으로 진행, **B**면 진행 후 완료 보고에 한 줄, **C** 또는 해당 항목 없음이면 묻는다. 건너뛴 게이트는 완료 보고에 「Dan Jr. 적용: D-01(A)」처럼 ID로 적는다. 실행 계획 GATE처럼 persona.md에 없는 결정은 그대로 사용자 승인.
   - 에이전트: `agents/{device-checker,tc-loader,runner,reporter}.md`. 각 에이전트는 자기 .md의 "참조 파일"만 읽는다.
   - **두뇌 = 메인 에이전트(나)**: TC의 테스트 절차는 자연어다. runner 단계에서 **내가 직접 브라우저 도구를 조작**하며 절차를 수행하고 기대결과와 대조해 판정한다. 서브에이전트에 넘기지 않는다(브라우저 세션·판정 맥락이 끊긴다).
   - **모델 티어링**: 판정(runner)은 현재 세션 모델, 기계적(load·write·report 스크립트)은 Node 스크립트.

2. **인테이크 — 한 번에 하나씩 순차 질문** (파이프라인 착수 직전): 산출물 1줄 선언 후 아래 순서로 묻는다. 한꺼번에 답하면 수용하고 남은 것만 이어 묻는다. "알아서"면 괄호 안 기본값으로 진행.
   - ① **업무명 / 프로젝트명** — 파일명 앞머리(전역 파일명 규칙 「업무 산출물」 트랙, 공백 없이). **처음 쓰는 업무명은 반드시 확인**(Dan Jr. F-02 · C). 공식 산출물(납품)이면 프로젝트코드-단계코드(`TE`) 트랙으로.
   - ② **TC 엑셀 확정** — `input/{slug}/`의 어떤 파일이 정본인지. 없으면 qa-master 추출 여부.
   - ③ **★ 디바이스 — 이번 회차 1개** (PC / MW / APP). 회차 = 디바이스 1개. 여러 디바이스면 회차를 나눠 반복한다. **APP은 웹뷰·하이브리드 화면만 MW 프로필로 대체 수행하고(`APP-WV`), 네이티브 기능(푸시·카메라·생체인증·앱 결제 등)은 Block + 「네이티브 수동 확인」으로 기록**한다. 디바이스별 프로필(뷰포트·UA·브라우저)은 `references/device-profiles.md`.
   - ④ **엔진** — claude-in-chrome(기본 · 지금 연결된 Chrome, 로그인 세션 그대로) / Playwright(반복·회귀 · Safari(WebKit) 확인 · 모바일 디바이스 프로필 정밀 에뮬레이션). 기준은 `references/device-profiles.md` §3.
   - ⑤ **TC 범위** — 기본 = 시나리오 ID 순서로 전체. 좁히려면 대분류 · 우선순위 · TC ID 범위로 지정.
   - ⑥ **접속정보** — 테스트 대상 URL · 테스트 계정 ID/PW · 필요한 사전 데이터. **파일에 저장하지 않고 이 세션에서만 쓴다**(run.json에도 URL만 남기고 계정은 ID만, 비밀번호는 기록 금지).
   - ⑦ **수동 개입 모드** — 기본 = **유인(그 자리에서 묻고 대기)**: OTP · 실결제 · 메일 수신 확인 · 실물 기기 등 자동화 불가 단계를 만나면 사용자에게 처리를 요청하고 「계속」을 받은 뒤 이어서 수행. 사용자가 「무인」을 고르면 해당 TC는 Block + 「수동 확인 필요」로 기록하고 다음 TC로.
   - ⑧ **★ 스타일 확인 — HTML 리포트 추출 전에 「기본 스타일로 추출할까요?」를 한 번 묻는다.** 기본값은 하우스 스타일(정본 = `~/.claude/house-style/house-style.css`, 없으면 `../../global-house-style/house-style.css`). "기본으로/네/알아서"면 하우스 스타일. CI 적용을 답하면 HEX를 확정해 정본 §2b 방식으로 얹는다. **확인 질문 없이 진행되는 경우에도 스타일을 임의로 고르거나 추출을 보류하지 않는다** — 하우스 스타일로 작성한다.

3. **★ GATE(실행 계획 승인)이 유일한 사전 분기점**: tc-loader가 「회차 ID · 디바이스/프로필 · 엔진 · 대상 TC 수(시나리오별) · 제외 TC · 접속 URL · 예상 소요」를 표로 제시 → **사용자 승인 후에만** runner로 넘어간다. 승인 뒤에는 끝까지 멈추지 않는다(수동 개입 단계 제외). 중간 보고를 원하면 사용자가 GATE에서 「대분류마다 보고」를 지정할 수 있다.

4. **★ 판정 규율** (정본 = `references/result-rules.md`):
   - 사용자 용어 **정상 → `Pass` · 오류 → `Fail` · 보류 → `Block`**. 엑셀 드롭다운 값은 qa-master 그대로.
   - **기대결과에 쓰인 것만 판정 기준**으로 삼는다. 기대결과가 `[확인 필요]`면 수행은 하되 Block + 「기대결과 미정」. 기대결과를 지어내서 Pass/Fail을 주지 않는다.
   - Fail은 「실제 결과」에 무엇이 어떻게 달랐는지 구체적으로(표시된 문구 · 이동한 URL · 콘솔 오류), Block은 「비고」에 보류 사유 코드를 쓴다.
   - 선행 TC가 Fail이라 다음 TC의 사전조건이 안 만들어지면 그 TC는 Block + 「선행조건 미충족(TC-xxx Fail)」.
   - 화면 상태가 애매하면 재수행 1회. 그래도 애매하면 Block + 「판정 보류(재확인 필요)」 — 임의로 Pass 주지 않는다.

5. **★ 증적 전수 저장**: 모든 TC의 **마지막 절차 수행 직후 화면**을 `output/{slug}/evidence/{run_id}/{TC ID}.png`로 저장한다. Fail은 오류 화면을 추가로 `{TC ID}_fail.png`. 저장 방법은 엔진별로 다르다 — Playwright는 `page.screenshot`, claude-in-chrome은 `scripts/capture_window.ps1`(Chrome 창 캡처). 엑셀 「비고」에 증적 파일명을 적는다.

6. **★ 브라우저 창은 서브모니터에 새 창으로** (전역 규칙 2026-10-28): claude-in-chrome·Playwright 모두 사용자의 기존 창에 탭을 끼우지 않고 **새 창을 서브모니터**(`[System.Windows.Forms.Screen]::AllScreens`에서 `Primary=False` Bounds 조회)에 띄워 그 창의 탭만 쓴다. 회차가 끝나면 그 창을 닫는다. 서브모니터가 없으면 주 모니터에 새 창으로 진행하고 완료 보고에 한 줄.

7. **★ 시각 표시(시작·완료)**: 파이프라인 착수 시와 최종 보고 시 현재 시각을 조회해(`Get-Date -Format "HH:mm"` 또는 `date +"%H:%M"`) 한 줄 표시한다. 착수=`현재 HH시 MM분입니다. 작업 시작합니다.` / 완료=`현재 HH시 MM분입니다. 작업 완료했습니다.`

8. **★ 스크립트로만 쓰고 읽는다**: 엑셀 읽기 `scripts/load_tc.mjs`, 회차 초기화 `scripts/init_run.mjs`, 결과 엑셀 `scripts/write_results.mjs`, HTML 리포트 `scripts/build_report.mjs`, Playwright 수행 `scripts/pw_run.mjs`. 엑셀 셀을 손으로 고치지 않는다. node는 이 PC에서 PATH에 없으므로 `"C:\Program Files\nodejs\node.exe"` 전체 경로로 부른다(`scripts/README` 참조).

9. **★ 비밀값 규율**: 비밀번호·OTP·토큰은 run.json · 엑셀 · HTML · 로그 어디에도 쓰지 않는다. 증적 스크린샷에 비밀번호 입력 화면이 들어가면 마스킹 상태(●●●)인지 확인하고, 평문이 보이면 그 장은 저장하지 않고 비고에 「증적 생략(비밀값 노출)」.

10. **완료 보고** (Dan Jr. R-01 형식): 한 것 → 결과 집계(Pass/Fail/Block/미실행 · 시나리오별) → Fail 목록(증적 경로) → 수동 확인 목록 → 「다만」 예외(건너뛴 TC · 접근 불가 화면 · 서브모니터 없음 등) → 산출물 경로. HTML 리포트는 내부망 URL(R-09)을 함께 준다 — 절차는 `../proposal/CLAUDE.md` 3c와 같다.

## 입출력 규약 (정본 = `ORCHESTRATOR.md` "파일 네이밍 표준")
- **input·output·중간물 모두 프로젝트(Task)별 `{slug}/` 하위폴더로 분리**한다. `slug = {클라이언트}-{주제}`.
- `input/{slug}/` — TC 엑셀(qa-master 양식) 또는 기획서. 접속정보 파일 금지.
- `_workspace/{slug}/` — `tc.json`(엑셀 파싱본) · `runs/{run_id}/run.json`(회차 실행 기록, 정본) · `runs/{run_id}/plan_*.json`(Playwright 플랜).
- `output/{slug}/` — 결과 엑셀 사본 · HTML 리포트 · `evidence/{run_id}/*.png`. 회차마다 새 파일(덮어쓰지 않음).

## 표기 규칙
한국어. 명사형 종결. 결과값은 영문 `Pass/Fail/Block/미실행` 그대로(사용자 보고에서는 「정상/오류/보류」를 병기).
