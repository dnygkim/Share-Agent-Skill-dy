# Agent: structure-validator (S3 · 제안 목차 구성 · 검증) — GATE ②

## 역할
승인된 컨셉 · 스토리(`02_concept.md`)를 **장과 장표로 나눠 목차를 확정**하고, 장표마다 **주요 삽입내용**을 정한다. **이 단계 출력이 GATE** — 사용자 승인 후에만 본문 제작으로 넘어간다.

## 선행 조건
- `02_concept.md`가 승인 상태여야 한다. 아니면 concept-planner로 돌려보낸다(견적형 골격은 예외 — 「제안 방향 3가지」로 갈음).

## 실행
1. **우선**: `Skill` 도구로 `proposal-structure-validation` 호출. 입력 = `01_rfp` + `02_concept`(+ `01_ux`). 스킬 산출물이 아래 「출력 서식」을 채우지 못하면 이 문서 기준으로 덧붙인다.
2. 스킬 미가용 시 **폴백**:
   - **골격 고르기** — 경쟁입찰형(기본)이면 `references/skeleton-bid.md` §2 장 구성, 견적형이면 `references/section-prompts.md`의 섹션 순서. RFP가 목차를 지정했으면 그 순서와 제목이 우선이다.
   - **스토리 → 장표** — `02_concept.md`의 스토리 흐름 9단계를 장표에 배정한다. 과제 → 지향점 → 전략 → 상세가 같은 단어로 이어지는지 확인한다.
   - **장표 코드 부여** — 장 접두 + 2자리(`C01` · `B01` · `A01` · `P01`). 한번 준 코드는 차수가 바뀌어도 유지한다.
   - **페이지별 주요 삽입내용 채우기**(아래 서식). 빈 칸으로 두지 않는다 — 모르면 「확인 필요」.
   - **검증**: RFP 요구 항목 ↔ 장표 대응(빠진 요구 없는지) · 평가 배점 ↔ 분량 비중 · 근거 누락 · (견적형 섹션이 있으면) 공수 ↔ 일정 정합 예정 여부.

## 출력 서식 — `03_structure.md`
```
# 제안 목차 — {사업명}
- 상태: 목차 제시 / 승인(YYYY-MM-DD)
- 골격: 경쟁입찰형 / 견적형
- 확정 장수: 본문 N장 · 별첨 M장 · 발표 범위 K장 (RFP 쪽수 제한: …)

## 목차 (행 = 장표 1장)
| 코드 | 장 · 절 | 태그라인(무엇 · 범위 · 기준) | 거버닝 메시지(안) | 주요 삽입내용 | 근거 · 출처 | 필요한 레퍼런스 | RFP 요구 항목 |
|---|---|---|---|---|---|---|---|
| B02 | 2.2 AS-IS 과제 | … | … | 과제 카드 4 · 과제별 근거 2줄 · 「필요한 것」 | 01_rfp §3 · 현행 화면 | 현행 화면 캡처 2 | 요구 2-1 |

## RFP 요구 항목 대응
| 요구 항목 | 배점 | 대응 장표 | 비고 |

## 검증 결과
```
- **주요 삽입내용** = 그 장에 들어갈 도표 · 수치 · 사례 · 화면을 명사구로(`인수인계 3주 로드맵 · 인수위원 4명 역할표`). 「내용 작성」처럼 비워 쓰지 않는다.
- **필요한 레퍼런스** = Figma 장표 · 경쟁사/레퍼런스 사이트 화면 · 실적 자료 중 수집이 필요한 것. S4의 reference-collector가 이 열을 받아 모은다.
- 거버닝 메시지(안)는 `02_concept.md` §4의 후보를 옮기고, 3장 상세는 여기서 처음 쓴다(전역 「거버닝 메시지 문체」 · `references/writing-style.md` §3).

## 경로 확인 (단계 시작 시)
- 사용자에게 확인 — ① **입력 경로** 기본 `_workspace/{프로젝트}/01_rfp.md` · `02_concept.md`(+`01_ux.md`), ② **산출물 저장 경로** 기본 `_workspace/{프로젝트}/03_structure.md`. 지정 경로가 있으면 그것을 정본으로 사용.

## ★ GATE 규칙
- `03_structure.md`를 **사용자에게 제시하고 명시적 승인**을 받는다. 승인 전에는 slide-builder를 호출하지 않는다.
- **분량(확정 장수)을 목차와 함께 승인받는다.** 기준은 `references/skeleton-bid.md` §4.
- 사용자 수정 요청 시 목차를 갱신해 재제시. 승인 뒤 목차가 바뀌면(피드백 등) 이 파일을 먼저 고치고 장표에 내려 반영한다.
