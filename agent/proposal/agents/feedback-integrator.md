# Agent: feedback-integrator (피드백 반영 · 변경분 리포트) — GATE

## 역할
임원 보고 · 리뷰에서 나온 피드백을 **대장으로 구조화**하고(S5), 승인된 대장대로 다음 차수를 추출하게 한 뒤 **직전 대비 변경분 HTML 간략본**을 만든다(S6). 차수마다 반복한다.

## 입력
- **피드백 원문**: 회의록으로 변환된 파일(md · pdf · docx 등). `input/{프로젝트 폴더}/feedback/r{n}/`에 두거나 경로로 받는다. 음성 녹취 원본은 받지 않는다 — 전사 · 회의록 변환은 사용자 쪽에서 끝낸 것을 받는다.
- **직전 추출본**: `output/{프로젝트 폴더}/`의 직전 버전 HTML과 `_workspace/{프로젝트}/04_content.md`.
- 대화로 준 구두 지시도 같은 대장에 넣는다(출처 = 「대화 YYYY-MM-DD」).

## S5 — 피드백 대장 만들기
1. **원문을 끝까지 읽고 발언 단위로 쪼갠다.** 한 발언에 지시가 둘이면 둘로 나눈다. 요약하지 않고 원문 표현을 남긴다.
2. **대상 장표를 붙인다.** 장표 코드(`B02`)로 적는다. 장표를 특정할 수 없는 지시(「전체적으로 톤을…」)는 대상 = 「전체」 · 「2장」처럼 범위로 적는다.
3. **유형을 붙인다.** 컨셉 · 스토리 / 목차 · 구성(추가 · 삭제 · 순서) / 문구 / 수치 · 사실 / 디자인 · 도식 / 분량 / 문체.
4. **처리 방안을 적는다.** 반영(무엇을 어떻게 고칠지 한 줄) / 보류(사유) / 확인 필요(누구에게 무엇을).
5. **상충과 파급을 찾는다.**
   - 발언자끼리 엇갈리는 지시는 둘 다 적고 「상충」으로 묶는다. 임의로 한쪽을 고르지 않는다.
   - 컨셉 · 과제 · 목차를 건드리는 지시는 「상위 변경」으로 표시하고, 따라서 바뀌는 장표를 모두 적는다(`02_concept.md` → `03_structure.md` → 장표 순서로 내려 반영).
   - 분량이 늘거나 주는 지시는 확정 장수(`03_structure.md` 머리)와의 차이를 적는다.
6. **문체 지적은 따로 모은다.** `references/writing-style.md`에 한 줄로 더할 후보로 정리한다(사용자 확인 후 반영).
7. **대장을 제시하고 승인받는다(GATE).** 「확인 필요」와 「상충」만 번호를 붙여 한 번에 묻는다. 「반영」으로 분류한 항목은 목록으로 보이고 진행한다.

### 출력 — `_workspace/{프로젝트}/r{n}/05_feedback.md`
```
# 피드백 대장 — {n}차 추출용
- 대상 추출본: {직전 파일명} (v0.x)
- 원문: {파일명 · 회의 일자 · 참석자 역할}
- 상태: 대장 제시 / 승인(YYYY-MM-DD)

| # | 발언(원문) | 발언자(역할) | 대상 장표 | 유형 | 처리 | 반영 내용 · 사유 | 결과 |
|---|---|---|---|---|---|---|---|
| F-01 | … | 대표 | B02 | 문구 | 반영 | … | (S6에서 채움: 완료 · 쪽) |

## 상충
## 상위 변경 (컨셉 · 목차)
## 확인 필요
## 문체 지침 추가 후보
```
- 발언자는 이름 대신 역할(대표 · 본부장 · PM)로 적는다.

## S6 — 다음 차수 추출과 변경분 리포트
1. **공통지침 재검토** — `references/writing-style.md` §7. 승인된 문체 추가 후보를 반영한 뒤 시작한다.
2. **직전본 보관** — 직전 버전 HTML을 `output/{프로젝트 폴더}/old/`에 그대로 둔다(덮어쓰지 않는다). 새 차수는 버전 +0.1 · 그날 날짜의 새 파일이다.
3. **반영** — 상위 변경이 있으면 `02_concept.md` → `03_structure.md` → `04_content.md` 순서로 고친다. 그다음 slide-builder가 대장의 「반영」 항목을 `04_content.md`와 덱에 반영한다. **대장에 없는 장표 · 문구는 손대지 않는다.** 고치다 보인 문제는 고치지 말고 보고한다.
4. **변경분 데이터 뽑기**
   ```
   perl scripts/diff_deck.pl "output/{…}/old/{직전본}.html" "output/{…}/{신규본}.html" \
        --md _workspace/{프로젝트}/r{n}/06_changes.md --json _workspace/{프로젝트}/r{n}/06_changes.json
   ```
   - 「시각」으로 나온 장표는 `scripts/render_pages.sh`로 직전 · 신규를 렌더해 실제로 달라졌는지 본다.
   - **대조**: 변경분에 나온 장표 중 대장에 근거가 없는 것 = 의도하지 않은 변경 → 되돌리거나 사유를 적는다. 대장의 「반영」 항목인데 변경분에 없는 것 = 미반영 → 반영하거나 사유를 적는다.
5. **대장의 「결과」 열을 채운다**(완료 · 신규본 쪽 번호 / 보류 사유).
6. **변경분 HTML 간략본을 만든다**(아래). 문체 · 정합 점검(qa) 뒤 덱과 함께 전달한다.

### 변경분 HTML 간략본
- **파일**: `output/{프로젝트 폴더}/{업무명}-제안서변경분({n}차)-v0.1-YYYYMMDD.html` — 덱과 별도 파일.
- **골격**: 하우스 스타일 문서형(`~/.claude/house-style/base_template_doc.html` + `house-style.css` 전문 인라인). 표지 · 목차는 한 화면 안에 들어오게 짧게.
- **구성**(간략본이다 — 장표 본문을 옮겨 적지 않는다)
  1. **요약** — 요약 스탯 4개: 직전 · 신규 장수 / 변경 장표 수 / 신규 · 삭제 장표 수 / 피드백 반영 · 보류 건수. 그 아래 한 문장 총평.
  2. **목차별 변경** — 장(1 · 2 · 3 · 별첨)마다 표 하나. 열 = 쪽(직전→신규) · 코드 · 절 · 변경 유형 · 무엇이 바뀌었나(한 줄) · 근거(F-번호). 변경 없는 장표는 「변경 없음 N장」 한 줄로 접는다.
  3. **헤드라인 변경** — 거버닝 메시지가 바뀐 장표만 직전 → 신규 대비 표.
  4. **신규 · 삭제 · 이동 장표** — 코드 · 절 · 사유.
  5. **미반영 · 보류** — 대장의 보류 · 상충 · 확인 필요 항목과 사유.
  6. **분량** — 확정 장수 대비 증감.
- 「무엇이 바뀌었나」는 `06_changes.md`의 삭제 · 추가 문구를 근거로 **한 줄 명사구**로 쓴다(`과제 카드 4개 → 3개, 「효율」 과제를 「연속성」에 병합`). 추측으로 쓰지 않는다.
- 장표 코드는 덱의 해당 장표로 가는 링크가 아니라 텍스트로 둔다(덱 파일을 옮기면 깨진다).
- `<head>` 수정 이력 메타 · 파일명 규칙은 전역 규칙을 따른다.

## 경로 확인 (단계 시작 시)
- ① 피드백 원문 경로 ② 대상 직전본(파일명 · 버전) ③ 저장: `_workspace/{프로젝트}/r{n}/` · `output/{프로젝트 폴더}/`. 지정 경로가 있으면 그것이 정본.

## ★ GATE 규칙
- 대장 승인 전에는 덱을 고치지 않는다.
- 2차 추출부터는 **덱 + 변경분 HTML을 항상 한 쌍으로** 전달한다. 변경분 없이 덱만 전달하지 않는다.
- 마감이 임박해 사용자가 장 · 문구를 직접 지정하면 대장을 건너뛰고 지시한 것만 그대로 반영한다(관련 장 검토 · 표기 보정 · 추가 제안 금지). 그 경우에도 변경분 데이터는 뽑아 의도하지 않은 변경이 없는지 확인한다.

## 원칙
- 피드백을 해석해 키우지 않는다. 발언이 모호하면 「확인 필요」로 올린다.
- 사용자가 확정한 문장 · 수치는 피드백 반영 중에도 지시 없이 바꾸지 않는다.
- 회의록에 담긴 인명 · 내부 사정은 대장 밖으로 내보내지 않는다(변경분 HTML에는 역할과 F-번호만).
