## 2. 장표 한 장의 해부 (공통)

위에서 아래로. 문구 규칙은 `writing-style.md` §1.

| 자리 | 기준 | 합격선 |
|---|---|---|
| 헤더 | 「고객 × ETRIBE」 로고 · 장 pill 또는 코드박스 · 크럼 | 덱 전체 한 형식. 다른 덱에서 가져온 장도 이 덱 헤더 · 서체로 다시 입힌다 |
| 태그라인 | 절 번호 + 무엇 · 범위 · 기준 | GS형: 태그라인 = **전제**, 거버닝 = **결론** 짝도 허용(「이용자 대부분이 검색으로 도달」 → 「검색 결과에서 정확히 노출되지 않는 구조」) |
| 거버닝 메시지 | 20–40자 한 문장 · 강조 1구절 | 「~으로」로 끝나는 미완결 · 두 문장 · 영문 전용 · 강조 2구절 불합격 |
| 리드 (선택) | 거버닝 아래 1문장 | 양식에 리드 자리가 있을 때만. 고객에게 말을 거는 합니다체 1문장, 항목은 명사구(`writing-style.md` §2) |
| 본문 블록 | 패턴 1개 (`design-system.md` §4) | 카드 · 표 · 흐름 · 대비 · 화면+콜아웃 중 하나를 주로, 둘 이상 섞으면 위계를 나눈다 |
| 근거 캡션 | 소제목 선 오른쪽 회색 | 기간 · 표본 · 출처 · 기준일 (`GA4 90일 · 실사용자 기준`) |
| 결론 바 | 판단 + 함의 한 문장 · 60자 이내 | 논증 장표는 필수, 목록 · 표 장표만 생략 가능 |
| ※ 단서 | 푸터 바로 위 오른쪽 | 약속 · 추정 · 범위에는 확정 시점과 주체(`고객사 협의로 착수 시 확정`) |
| 푸터 | 좌 copyright(연도 통일) · 우 쪽번호 | 쪽번호 연속 · 중복 없음 |

**시각 합격선**
- **그룹마다 하나만 강조** — 셰브론 핵심 1단계 · 카드 1장 · 표 1행 · 막대 1개만 강조색(메리츠 거의 전 장). 강조는 반전 · 굵기 · 배지로 만들고, CI Primary 1색 + 경고용 레드 외 색 0개.
- 팔레트 밖 색 금지 — 6색 카드 · 4색 단계 바 · 갈색 · 녹색 박스(2025 덱 · GS 일부)는 불합격.
- 박스 모서리는 양식을 따른다. 하우스 기본 · 디자인파트 1600 양식은 r=0, 배지 · 칩만 pill. 고객 · 주관사 양식이 둥근 카드면 그 값으로 덱 전체 통일.
- 서체 위계(1600×900 기준): 거버닝 44px/800 · 소제목 20px/800 · 본문 13–16px · 큰 숫자 44–60px · 각주 12–13px. **본문 최소 10pt(1280 기준 13px)** — 7–8pt 표는 별첨으로 내린다.
- 아이콘은 한 계열(라인 · 원형 배경 중 하나). 인물 일러스트 · 이모지 아바타 · 손글씨체 · 장식 사진 장 금지.

## 3. 장표 유형별 합격선

「반드시」가 하나라도 빠지면 보완필요. 예문은 최종본에서 확인한 형태.

### 3-1. 앞부분 — 표지 · 목차 · 소개 · 실적

| 장표 | 레이아웃 | 반드시 | 불합격 예 |
|---|---|---|---|
| 표지 | CI 풀블리드 또는 고객 자산 사진 + 오버레이, 제목 2–3줄 | **컨셉 한 줄**(컨셉어를 그림 · 도식으로 함께 시각화하면 가산) · 사업명 · 날짜 · 양사 로고 | 사업명만 (MG · 계룡 · 롯데 · 수협) |
| 목차 · 간지 | 좌 대형 INDEX / 간지 = 장 번호 · 제목 · 절 목록 + 현재 장 표시 | 별첨 목록 · 절 번호가 본문 크럼과 같음 | 목차 문구 ≠ 실제 장 |
| 회사 개요 | KPI 타일 4–5(마지막 반전) · 프로필 표 · 조직 · 인원 막대 · 결론 바 | 설립 · 인원(기준월) · 신용등급(기관 · 평가일) · 매출(기간 · 단위) | 연혁 나열 · 영문 슬로건 장 · 숫자 기준 없음 |
| 실적 | 요약 스탯 4 + 사례 카드 4(스크린샷 · 기간 대형 숫자 · 발주사/범위/성과 키 · 하단 so-what 한 줄) / 별첨 표 7열 | **이번 사업과 닮은 점 한 줄**, 가장 가까운 1건만 강조, 고객 업종 · 계열사로 걸러 배지(`B2C청약` · `공제`) | 로고 월 · 「130여 개 이상」 |

### 3-2. 개요 — 이해 · 과제 · 지향점 · 전략 · 지표

| 장표 | 레이아웃 | 반드시 | 불합격 예 |
|---|---|---|---|
| 사업 이해 | 스탯 타일 3 + 반전 목표 타일 / 배경 n카드 → 목표 n카드 화살표 / 범위 3행 표(기간 · 범위 · 투입) | 기간 · 인력 · M/M · 채널/시스템 수량 · 목표 한 줄, 배경 n ↔ 목표 n 대응 | RFP 문장 복사 |
| AS-IS 진단 · 과제 | n열(분류 / 고객 목소리 2줄 / 근거 불릿 2 / ▼ / 「필요한 것」) → 합류선 → 결론 바 · 또는 숫자 카드 4(가장 심한 1장 틴트) | **카드마다 숫자 1개 이상**(단계 수 · 소요시간 · 횟수 · 0건) + 측정 기준 · 일자 · 방법 각주, 경쟁사 비교는 배수(`× 2.3배`) | 진단 용어만 · 측정일 없는 비교 · 출처 없는 「전 세계 60%」 |
| 여정맵 · 타깃 | 페르소나 카드 → Before · On · After 3단 + 감정곡선 + PAIN 마커 | 타깃 속성(연령 · 디지털 숙련도) · 단계별 행동 문장 · 페인 n개가 다음 장 과제와 같은 이름 | 전략에서 3유형을 세우고 상세는 2타깃(체인 끊김) |
| 벤치마크 | 3열 비교 · 마지막 열 「반면교사」 허용 | 서비스명 링크 · 캡처 일자 · 이번 사업에 가져올 것 한 줄 | 캡처만 나열 |
| 컨셉 · 지향점 | 반전 밴드(컨셉 문장 + 플랫폼/전략명) + 기둥 3–4(이름 · 현재/TO-BE 행 · 불릿 3) | 표지 컨셉어 재등장 · 현재↔TO-BE 대구 · 받치는 수단 | 추상 슬로건 · 영문 2단어만 |
| 전략 체계 | 표: 과제(고객 목소리) → 전략명(1개 강조) → 실행 3 → **근거(과거 수행 사업명)** / 또는 성공요소 n × 전략 3 × Action 9 | 과제 ↔ 전략 1:1, **근거 열** | 과제와 무관한 전략 · 근거 없는 전략 |
| 목표 지표 | 지표 행(이름 + 산식 / 액션 / 주기 칩) + 반전 「최종 목표 지표」 | 산식 · 주기 · **기준선 확정 시점** | 「50% 단축」 근거 없음 |

### 3-3. 상세 — 수행 방안 · 화면 · 구조

| 장표 | 레이아웃 | 반드시 | 불합격 예 |
|---|---|---|---|
| 상세 수행 (일반) | 소제목 + 얇은 선 + 우측 근거 캡션 · 셰브론(핵심 1단계 강조) · 카드 그리드 · 우측 반전 패널 · ※ 단서 | 절차 · 담당 · 산출물 · 시점(D-n · 주 · 월) 또는 수량(명 · M/M · 건) 하나 이상, 산출 근거 박스(`203행 → 중복 제거 → 176건`) | 동작 없는 원칙 장 |
| UI 개선안 | 좌 주요 화면 2–3(와이어/목업) · 우 개선사항 3(✓ 카테고리 + AS-IS 한 줄 / TO-BE 한 줄) · 또는 현행 캡처(빨간 박스) │ 개선 화면(번호 콜아웃 ↔ 번호 목록) + 측정 지표 · 준법 태그 + 핵심 원칙 바 | **콜아웃 번호 = 목록 번호**, 화면 안 실제 문구 · 데이터, 「예시」 리본, 측정 지표 | `Icon` · `Img` 자리표시 잔존 · 콜아웃 없는 캡처 · 읽히지 않는 화면 |
| 화면 흐름 | 꺾쇠 단계(메인 → 상세 → 기능) + 단계마다 말풍선 주석 1 | 단계 수 변화(29단계 → n단계) | 주석 없는 흐름 |
| 메인 화면안 | 타깃별 모듈 배치 와이어 + 모듈 ID(A-1 · B-3) 범례 | 타깃별 모듈 순서의 근거 | — |

## 4. 문장 — 최종본에서 확인한 형태 (writing-style 보강)

`writing-style.md`가 정본이다. 아래는 이번 학습으로 더한 것이고, §5 · `check_style.pl`에 반영했다.

**잘 쓴 형태 (따라 쓴다)**
- 동작 하나를 쓴 거버닝: `‘보상금 청구 완결’ 한 가지에 집중하는 UX` · `러닝체인지 전후 집중 인력 운영` · `계산하려고 생각하지 않게 하는 선택 정보 우선 배치`
- 고객 목소리 ↔ 「필요한 것」 짝: `담당자가 바뀌면 처음부터 다시 배웁니다` ↔ `사람이 바뀌어도 기록이 남는 운영`
- 카드 하단 so-what 고정 자리: 「메리츠 적용」 띠 · 사례 카드 굵은 한 줄 · 「To Do」
- AS-IS/TO-BE 줄 대비 — TO-BE 끝 명사구만 굵게: `필수/선택 항목 구분 표시로 **입력 오류 사전 예방**`
- 한글 키워드 + 영문 서브 쌍은 덱 전체 같은 표기로 고정(`직관성 Intuitive`)
- 약속형 거버닝 · 결론 바는 인력 · 인수인계 · 일정 · 관리 · 맺음에 몰린다(메리츠 30장 중 7장). 사용자 결정(2026-11-10)대로 예외로만 쓰고 완료 보고에 코드로 적는다.

**버릴 형태 (최종본에 남은 반례)**
- 「A를 통한 B 확보 · 구축 · 강화 · 마련」 수단→목적 연쇄 — 2025 덱 헤드라인 대부분, MG 텍스트에 「통한/통해」 80회. 거버닝에는 0회, 본문도 장당 1회 이하. 동작 문장으로 다시 쓴다(`안정화 백업 인력 운용을 통한 품질 연속성 확보` → `결원이 생기면 본사 인력이 먼저 메우는 운영`).
- 「A가 아닌/아니라 B」 남발 — 한 덱 6회 이상(수협). **덱 전체 3회 이하**.
- 같은 꼬리말 반복 — 불릿 3개가 모두 「…부담 존재」. 끝말을 바꾸거나 표로 묶는다.
- (n/m) 분할 장이 같은 거버닝 — 장마다 그 장의 결론을 따로 쓴다.
- 근거 없는 최상급 · 절대어 — `업계 최고 · 최초 · 유일 · 완벽 · 무결점 · Zero · 원천 차단 · 원천 봉쇄`. 수치 · 조건으로 바꾼다.
- 1인칭 · 2인칭 — 「우리는 · 우리가」 · 「여러분」 편지체(2025 덱). 회사명 3인칭.
- 은유 장 · 영문 슬로건 장 · 태도 선언(`OUR ATTITUDE…` · `태도로 일합니다` · `100%를 120%`) — 고객 데이터가 없는 장은 쓰지 않는다.
- 띄어쓰기 · 오탈자 — `제한 된 · 일관 된 · 강화 합니다` · `Greeting Massage`. 
- 명칭 흔들림 — 컨셉어(`Zero-Friction UX` → `Zero-Step`) · 플랫폼명(`워크플랫폼 / 워크 플랫폼`) · 고객사명(`GS칼텍스 / GS 칼텍스`) · 사업명(표지 · 헤더 · 파일명)을 덱 전체 한 표기로.

## 5. 완성도 점검표 (qa · 추출 직후)

자동(`check_style.pl` · `check_slides.py`)으로 잡는 것과 사람이 보는 것을 나눴다. 하나라도 걸리면 `r{n}/qa.md`에 장표 코드와 함께 적는다.

**수치 · 근거**
- [ ] 같은 수치가 덱 전체에서 같다 — 인원(카드 158 ↔ 결론 바 160) · 사이트 수 · 기간 · M/M · 매출 추세 문구 ↔ 표
- [ ] 모든 수치에 단위 + 기준(기간 · 표본 · 출처 · 기준일)
- [ ] 진단 카드마다 숫자 1개 이상 · 효과 주장은 수치나 범위 + 산출 근거
- [ ] 전략 표에 근거(과거 수행 사업) 열

**화면 · 구조**
- [ ] 캡처 · 와이어의 콜아웃 번호 = 목록 번호, 화면 글자가 읽힌다
- [ ] `Icon` · `Img` · `00` · `B0X` · `{…}` 자리표시 0
- [ ] 와이어 · IA · 일정 · 아키텍처에 범위 단서(예시 · 협의 · 조정 가능 · P2) · RFP 기본 / 보완 제안 / 확장 배지

**형식**
- [ ] 쪽번호 연속 · 중복 없음 · 목차 문구 = 장 제목 · 크럼 = 목차 절 번호
- [ ] 사업명 · 고객사명 · 컨셉어 · 영문 섹션 라벨이 덱 전체 한 표기(짝 장표 라벨 동일)
- [ ] 푸터 연도 통일 · 숨은 텍스트 상자 · 겹친 제목 0 · 다른 덱에서 온 장의 헤더 · 서체 통일
- [ ] 강조색은 그룹마다 1개 · 팔레트 밖 색 0 · 본문 최소 크기 준수
- [ ] 제목이 약속한 내용이 장 안에 있다(「성공 요건 및 기대효과」인데 기대효과 없음 = 불합격) · 하단 절반이 빈 장 없음

**스토리**
- [ ] 표지 컨셉어 → 지향점 → 전략 → 상세 → 맺음이 같은 명사로 이어진다 · 맺음 장 있음
- [ ] 과제 n ↔ 전략 n ↔ 상세 n ↔ 기대효과 이름 일치(타깃 유형 수 포함)
- [ ] 정형 관리 장마다 고객 고유 항목 1개 이상 · 범용 소개 장(제품 브로슈어 · 파트너 로고 월) 없음
- [ ] 회사 소개 비중 20% 이하 · 조견표(평가 목차 지정형이면 평가항목 ↔ 쪽)

**발표 요약본을 따로 만들 때**
- [ ] 제출본에서 옮긴 장의 문구가 같다(`긴급 출동` → `고장 출동`처럼 바뀐 말 없음) — `perl scripts/diff_deck.pl <제출본> <발표본>`
- [ ] 크럼 · 코드 경로만 줄이고(`3.2.1.1 … (1/2)` → `01 … (1/2)`) 거버닝은 그대로
- [ ] 발표본에만 넣는 장(간지 · 맺음 · Q&A · 요약 1장)을 목차 비고에 표기

## 6. 이 문서를 고치는 방법

- 새 최종본이 드라이브에 올라오고 사용자가 「기준 업데이트」를 지시하면 §0 표에 한 줄 더하고, 바뀐 합격선만 §1–§5에 반영한다. 사용자가 확정한 결정(약속형 예외 · CI 기본 등)은 이 문서로 바꾸지 않는다.
- 문장 규칙이 바뀌면 `writing-style.md`를 먼저 고치고 여기에는 참조만 남긴다.
