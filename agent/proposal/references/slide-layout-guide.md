## 0. 도식을 고르는 순서

1. **거버닝 메시지를 먼저 쓴다.** 도식은 그 한 줄의 근거를 보이는 그림이다. 거버닝이 바뀌면 도식도 다시 고른다.
2. **내용의 성격을 하나 정한다** — 수치 · 이슈 · 전환 · 계층 · 결합 · 흐름 · 순환 · 비교 · 일정 · 화면. §2 표에서 그 성격의 도식을 고른다.
3. **한 장에 주 도식 하나, 보조 하나까지.** 둘 이상이면 위계를 나눈다(주 = 넓은 면, 보조 = 오른쪽 좁은 열 또는 아래 줄).
4. **흐름 방향은 하나** — 위 → 아래 또는 왼쪽 → 오른쪽. 「흐름이 안 읽혀」(AR01) · 「지금은 안 읽혀」(방문자 유형)는 방향이 둘 이상이거나 층이 섞인 장에서 나왔다(§5).
5. **결론 바 한 줄로 닫는다.** 목록 · 표만 있는 장도 FunETF에서는 거의 전 장에 결론 바를 두었다.

## 1. 장표 한 장의 골격 (1600×900 · 로고 락업형)

| 자리 | 구성 | 규격 |
|---|---|---|
| 상단 줄 (높이 32) | 왼쪽 로고 락업 = Primary 짧은 막대(30×5) + 고객 로고 + `×` + ETRIBE / 오른쪽 장 pill(Primary 옅은 면 · Primary 글자 16px/800) + 절 이름(17px) | 표지 · 간지 · 맺음 빼고 전 장 같은 자리 |
| 태그 줄 | `절.장표 번호` + 단계 뱃지(단계 체계가 있는 덱만) + 주제 | 19px 회색. 번호 칸 58px · 뱃지 최소 86px · 뱃지와 주제 간격 9px 고정 — 장을 넘겨도 시작점이 같아야 한다 |
| 거버닝 메시지 | 한 문장 · 강조 1구절(Primary) | 44px/800 · 행간 1.22 · 글자 간격 -.045em |
| 본문 | 주 도식 1 + 보조 1 | 거버닝 아래 38px부터 · 블록 간격 16 · 남는 높이는 본문이 채운다(§5 「여백」) |
| 결론 바 | 검정 전폭 띠 · 흰 글자 23px/800 · 강조 구절은 Primary 밝은 단계 | 높이 66 이상. 이끄는 말이 필요하면 2줄형(위 작은 줄 15px · 흰색 60% — 「그래서 {고객사}에 필요한 것은」) |
| 푸터 | 왼쪽 copyright · 오른쪽 쪽 번호 15px/800 | 쪽 번호는 `scripts/deck_edit.py`로만 |

**태그 줄 규칙** (11/17–11/19 사용자 결정)
- 메리츠 방식 — 장표마다 `0.0.0 주제`, 한 장뿐인 절은 `0.0 절 이름`, 같은 주제가 여러 장이면 `(1/n)`(예 `2.7.3 메인 화면 개선 (1/2)`), 별첨은 `별첨 N · 주제`.
- 주제는 목차 절 이름과 같은 말. 단계 이름을 주제에 겹쳐 쓰지 않는다 — 「{단계명} 그룹별 과제」 → 뱃지 `{단계명}` + 「그룹별 과제」.
- 태그 줄 끝에 기준일 · 근거 · 산출물 나열 · 동그라미 번호를 붙이지 않는다.

**단계 뱃지** — 단계 체계(예 유입 · 전환 · 재방문 · 확산)를 세운 덱에서만. 사각 라인 · 단계 색 글자, 그 단계 장 전체(그룹별 과제 · 과제 상세 · 화면)에 붙인다.

## 3. 화면 예시(와이어) — 「메리츠에 들어간 와이어처럼」 (11/19)

- 구역 머리말 = **「UX/디자인 개선방안 예시」** + 작은 안내 「과제 코드 = 적용 위치 · 상세 디자인은 착수 후 확정」.
- **화면 크기는 장마다 같게** — 2장이면 230×436, 3장이면 205×388(휴대폰 비율). 한 덱 안에서 섞지 않는다.
- **표시는 화면 가장자리 마커 + 오른쪽 짧은 설명** — 점선 구역으로 감싸지 않는다. 마커는 번호가 아니라 **과제 코드 칩**(`C-1`), 설명은 2–6자(「필터 저장」), 한 화면에 4–6개. 같은 과제가 여러 번이면 화면 순서대로.
- 마커가 다른 요소(닫기 X 등)를 가리키는 것처럼 보이지 않게 높이를 맞춘다. 위치는 **피그마 원본 화면과 대조**한다(「와이어프레임이 위치 정확한지」).
- 와이어 구역 바탕 = 그 단계 색의 옅은 면. 화면 테두리는 남긴다(§4-1 강조선 금지의 예외).
- 화면 아래 캡션 = 화면 이름(「ETF 검색 목록」 · 「저장할 때 로그인」).
- 과제 상세에 없는 기능을 화면에 그리지 않는다(「원래 화면으로 복귀」 표시 삭제 사례). 긴 화면은 **중간 생략 표시**로 한 화면에 잇는다.
- 실제 진단 · 시연 화면에는 단서 한 줄 — `※ 화면은 ETRIBE GEO의 실제 진단 화면이며 진단 대상 정보는 표시하지 않았습니다`.
- **시연 영상은 자동 재생하지 않는다** — 썸네일 버튼 → 레이어 재생(× · 바깥 · Esc로 닫기, 레이어가 열린 동안 키보드는 영상에만).

## 4. 면 · 선 · 색 (스타일)

### 4-1. 면과 선

- **본문 면은 플랫(그림자 없음) · 직각.** 뉴모피즘 · 그림자는 표지 · 목차 · 간지 · 맺음에만 쓴다(FunETF 5차 「뉴모피즘 버리지 못하겠어. 표지 · 간지 · 목차 같은 부분 제외하고 상세 슬라이드에는 컬러를 좀 더 활용」).
- **강조선 금지** (7차 「박스에 불필요하게 라인으로 강조처리 된 부분 모두 제거 · AI로 작성한 티가 나」) — 카드 위 색 줄 · 상자 왼쪽/위 색 줄 · 결론 바 위 줄 · 컨셉 밴드 왼쪽 줄 · 2px 색 테두리 · 짙은 패널 테두리 → **1px 회색 선으로 바꾸거나 선을 지운다**.
- **남기는 선** — 점선 상자(지원 · 협업 표시) · 연표 · 일정표 축선 · 제목 밑줄(과제 머리 위 2px 검정 줄) · 칩 테두리 · 화면 목업 테두리.
- 단계를 묶을 때 색 상자(머리 띠 · 옅은 바탕 · 확산 상자)로 감싸지 않고 **선 괄호 + 글자**로 묶는다(퍼널 K02 11/19).
- **모든 장의 바탕색은 같게**(6차 「배경컬러는 전체 동일하게」) — 표지 · 간지만 다른 바탕을 쓰지 않는다. 바탕이 연회색이면 선 · 옅은 면을 한 단계 진하게.

### 4-2. 색의 역할

| 색 | 쓰는 곳 | 쓰지 않는 곳 |
|---|---|---|
| 블랙(ink) | 글자 · **강조 면**(결론 바 · 목표 타일 · 확약 카드 · 연혁 판) | — |
| Primary(고객 CI) | 거버닝 강조 구절 · 장 pill · 번호 배지 · 핵심 지표 · 이트라이브 몫 열 · 핵심 층 1개 | 장마다 넓은 면을 Primary로 채우기(5차 「강조하는 내용은 블랙이 들어가는데 지금은 너무 블루톤만」) |
| 청록(Secondary) | **AI 표식 한정** — AI 칩 · AI 몫 · AI 단계 | 일반 강조 |
| 레드 | **문제 · 경고 · 점선 경고 상자 한정** | 장식 · 강조 |
| 단계 색 n | 단계 체계가 있는 덱의 단계 뱃지 · 단계 판 · 과제 코드 칩 · 와이어 바탕 | 단계와 무관한 강조 |

- 강조의 기본은 **블랙 면**, Primary는 글자와 작은 면. 한 그룹에서 강조는 하나(`slide-quality-bar.md` §2).
- 기준 덱은 단계 4개에 청록 · CI Primary · 짙은 남색 · 보라를 썼다 — 그 덱 전용 값이다. 덱마다 CI 계열에서 새로 정하고 사용자 확인을 받는다.

### 4-3. 글자 크기 (1600×900)

거버닝 44/800 · 태그 줄 19 · 카드 제목 18–20/800 · 본문 13.5–15 · 큰 숫자 34/900(목표 숫자 50 이상) · 각주 12–12.5 · 결론 바 23/800. **본문 최소 13px** — 그보다 작아지면 내용을 덜거나 장을 나눈다.
