## 2. 컬러 — 기본은 하우스 스타일, CI 는 요청받았을 때만

**하우스 스타일이 기본값이고, HTML 추출 전 인테이크에서 「기본 스타일로 추출할지」를 한 번
확인받은 뒤 추출한다**(하네스 `CLAUDE.md` §2③ · 스킬 단독 실행 시 `SKILL.md` 3).
확인 없이 진행되는 경우에도 이 문서에 정의된 기본값(하우스 스타일)으로 작성한다 — 임의 스타일 금지·보류 금지. 값의 정본은
`../../../global-house-style/house-style.css` §2 토큰(= `~/.claude/house-style/house-style.css`)이고,
덱은 그 값을 `template/slide-tokens.css` 로 받아 쓴다. 여기에 값을 다시 적지 않는다.

팔레트는 warm paper(`#F1EDE5`) + near-black ink(`#14130F`) 2톤이다.
**강조는 색이 아니라 반전**(ink 배경 + paper 텍스트)이나 명도·굵기 단계로 만든다 —
원색 포인트를 임의로 추가하지 않는다.

| 덱 변수 | 용도 | 기본값(house 토큰) |
|------|------|-----------|
| `--ci-main` | 헤더바 배경, 표 헤더, 강조 박스 = 반전 블록 | `--ink` |
| `--ci-point` | 강조선, 뱃지, 핵심 수치·키워드 | `--ink` (색이 아니라 굵기로 드러남) |
| `--ci-sub` | 서브 박스 테두리, 아이콘, 보조 강조 | `--ink-2` |
| `--ci-bg` | 슬라이드 기본 배경 | `--paper` |
| `--ci-subbg` | 카드 배경, 표 교대 행 | `--surface` |

### CI 컬러 적용 — 옵트인
클라이언트 CI 적용은 **사용자가 명시적으로 요청했을 때만** 얹는다. 묻지 않고 임의로 켜지 않고,
과거 산출물·다른 프로젝트의 CI 를 재사용하지도 않는다. 요청받으면 `template/slide-tokens.css`
맨 아래 `[CI 오버라이드]` 블록의 주석을 풀어 위 5개 값을 갈아끼운다. 이때 **배경 · 선 · 보조 글자도
CI 색상 계열의 저채도 중립색으로 함께 바꿔** 웜 베이지가 CI 색과 따로 놀지 않게 한다(2026-10-22 지시 —
값 예시 · 웜 rgba 덮을 목록은 정본 `house-style.css` §2b). 레이아웃은 건드리지 않는다.

**CI 컬러 확인 방법 (우선순위 순)**
1. 클라이언트 제공 브랜드 가이드라인 PDF
2. 클라이언트 공식 웹사이트 CSS (개발자 도구 → Computed → color/background-color)
3. 클라이언트 담당자에게 HEX 코드 직접 확인
4. 위 3가지 불가 시 `[CI 확인 필요 — 임시 적용]` 표기 후 제출 전 수정

CI 적용을 요청받았는데 끝내 HEX 를 확정하지 못하면, **중립 팔레트를 새로 만들지 말고**
하우스 기본값으로 렌더링한 뒤 `[CI 확인 필요]`로 표기한다.

### 고정 텍스트 컬러 (가독성 보장, 변수화 금지)
| 역할 | 기본값 | 적용 위치 |
|------|--------|-----------|

## 3. 슬라이드 공통 포맷

- **크기(작업 사이즈)**: 착수 시 사용자에게 확인해 확정한다 — 기본 와이드스크린 16:9(33.87cm × 19.05cm / 1280×720px 환산). 디자인파트·클라이언트 양식이 있으면 그 규격(예: 피그마 장표 1600×900, 콘텐츠 영역 x64~1536 · y211~834)이 정본. 확정 전 골격 생성 금지, 덱 전체가 한 규격을 따른다
- **방향**: 가로

### 슬라이드 구조 (매 슬라이드 공통)
```
[상단 헤더바] — {CI_메인컬러} 배경, 높이 약 8%
  좌: 프로젝트명 (흰색 볼드)
  우: 섹션 카테고리명 (흰색 일반)
  하단 {CI_포인트컬러} 강조선 포함
[본문 영역]
  대제목: 한글, 굵게, 28~36pt (핵심 키워드 {CI_포인트컬러} 강조)
  설명문: 14~16pt, 1~2줄
  컨텐츠 블록: 아래 레이아웃 패턴 중 1개
[하단 푸터]
  좌: 클라이언트 로고 × 수주사 로고 / 우: 페이지 번호
```

## 5. 포맷별 렌더링 가이드

### pptx (내장 pptx 스킬 사용)
- `/mnt/skills/public/pptx/SKILL.md`를 먼저 읽고 그 지침에 따라 .pptx 생성
- 16:9 슬라이드 마스터에 헤더바·푸터를 공통 적용
- 레이아웃 패턴을 도형·표·SmartArt로 구현. 컬러는 변수 치환값 직접 적용

### HTML (단일 .html, 슬라이드 덱 형태)
- 1슬라이드 = 1280×720px 고정 비율 컨테이너(`<section class="slide">`)
- 컬러는 `template/slide-tokens.css` 의 `:root` 토큰을 골격 `<style>` 에 **인라인**한다
  (자기완결 단일 파일 원칙 — 외부 `.css` 를 link 하지 않는다). 교체는 그 1곳에서만 한다
- 키보드 좌우 이동 또는 스크롤 스냅으로 슬라이드 네비게이션
- 브라우저 인쇄(Ctrl+P)로 PDF 변환 가능하도록 `@media print` 페이지 분할 적용
- **HTML 이 최종 제출 포맷이고 디자인파트 양식(1600×900 장표)이 있을 때**는 위 미리보기 골격 대신 `template/deck_1600_template.html`(스테이지 핏 · cover/일반/s-fig/s-emb 4종 · 코드박스 헤더 · 푸터 번호)을 쓰고, 피그마 장표 벡터 취합·편집·검수·백업 절차는 `references/deck-production-playbook.md`를 따른다. 팔레트는 양식 값을 쓰되 박스 r=0 · 강조는 배지만 · 레드는 경고에만.

### Figma (`use_figma` 디자인 프레임)
- 16:9 프레임(1280×720)을 슬라이드 수만큼 생성
- **품질 편차 주의**: 정교한 표·다이어그램은 결과가 불안정할 수 있음. 생성 후 사용자 검토·수동 보정 필요함을 반드시 고지
- 표·복잡 IA 구조가 중심인 슬라이드는 pptx/HTML 우선 권장하고, Figma는 카드형·2분할형·표지 등 레이아웃 단순 슬라이드에서 강점
- 생성 전 대상 슬라이드 수와 패턴을 사용자에게 확인
