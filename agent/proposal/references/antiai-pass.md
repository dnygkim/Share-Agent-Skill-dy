# im-not-ai 1차 윤문 — AI 티 제거 → 하우스 문체 (S4 · S6 문구 작성 직후)

> 2026-11-20 신설(사용자 지시 「분석을 거쳐 제안서를 작성할 때 문장이 AI가 작성한 것처럼 보이지 않도록 im-not-ai 스킬을 1차로 적용」).
> 제안서 문구를 쓴 직후 **im-not-ai(humanize-korean v2.4.x)로 AI 티를 먼저 걷어 내고**, 그 위에 `writing-style.md`(하우스 문체)와 `check_style.pl`을 **2차**로 건다.
> 근거 = FunETF 취합본 시험 2회(2026-11-20 · 장표 문구 1,124줄 중 1차 45줄 · 2차 67줄 교정, 문자 변경률 0.6%). 이 시험의 전 · 후가 `writing-style.md` §4-1 「용어의 표현」이 됐다.
> 스킬 원본 = `../../skills/im-not-ai/`(epoko77-ai/im-not-ai 백업 · 주간 동기화). 이 문서는 그 스킬을 제안서 장표 문구에 거는 방법만 정한다.

## 0. 순서 한눈에

```
slide-builder 문구 작성 ─▶ ① extract ─▶ ② humanize-korean ─▶ ③ apply ─▶ ④ 하우스 문체 2차 ─▶ 사용자 확정
 04_content.md / 덱        장표 문구 → 줄 단위     진단 → 윤문 → (finalize)   줄마다 검증 후 반영   check_style · §4-1     diff.md 전 · 후 표
```

| 차례 | 담당 | 고치는 것 |
|---|---|---|
| **1차 · im-not-ai** | humanize-korean 스킬 | AI 티 — 「~로 이어지다 · 잇다 · 연결」 반복, 추상어 나열(가치 · 기반 · 새로운 기준), 당위 종결 연쇄(~해야 합니다 ×N), 대구 · 경구 메아리, 번역투(~을 통해 · ~에 있어), 「~하는 시대 / 중요한 시기」 여는 공식, 좌향 수식 겹침 |
| **2차 · 하우스 문체** | `check_style.pl` + `writing-style.md` | ㅁ 명사형 어미 · 호칭 · 대시, 용어의 표현(§4-1 쉬운 동사 · 한자어 명사 끝), 거버닝 형식(§1 · 전역 거버닝 규칙), 본문 연결어미 쉼표 |

- 둘이 어긋나면 **하우스 문체가 우선**이다(§4 표).
- 1차는 문체만 고친다. 내용 추가 · 삭제 · 장표 구성 변경은 윤문 범위 밖(피드백 대장으로).

## 2. 실행

### 준비 (PC마다 한 번)
- **스킬 설치**: `claude plugin marketplace add epoko77-ai/im-not-ai` → `claude plugin install humanize-korean@im-not-ai --scope user`. 설치 뒤 **새 세션부터** 스킬 · 에이전트(humanize-diagnostician · humanize-monolith · humanize-finalizer)가 잡힌다. 공유 리포를 받은 PC는 `skills/im-not-ai/install.sh`로도 된다.
  - 작성자 PC는 설치 완료 상태이고 토요일 01:00 예비 동기화 때 플러그인도 함께 갱신된다.
- **Python 3**(`python -X utf8`) — 추출 · 반영 스크립트와 스킬의 정량 점수 · 게이트가 쓴다.
- 스킬이 안 잡히는 세션(설치 전 · 다른 도구)은 §5 폴백.
- **원본 갱신 · 호환 점검(자동)**: 원본 주간 동기화(금 23:00 클라우드 · 토 01:00 작성자 PC 예비)가 리포 백업 `skills/im-not-ai/`(폴백이 읽는 폴더)와 작성자 PC 플러그인을 최신으로 맞추고, 새 원본을 반영할 때마다 `python -X utf8 scripts/antiai_units.py doctor`로 이 문서 · 스크립트가 기대는 파일 12개 · 인자/표기 9개를 점검해 결과를 커밋 메시지와 릴리즈노트에 남긴다. 「호환 점검 경고」가 나오면 `antiai_units.py`(DEPS · CONTRACT · TESTED)와 이 문서를 원본에 맞춘다. 다른 PC 플러그인은 `claude plugin update humanize-korean@im-not-ai`로 직접 갱신.

### ① 추출 — 장표 문구 → 줄 단위
```
python -X utf8 scripts/antiai_units.py extract _workspace/{프로젝트}/04_content.md --project _workspace/{프로젝트}
python -X utf8 scripts/antiai_units.py extract "output/output-{프로젝트 폴더}/<덱>.html" --project _workspace/{프로젝트} --codes B02,B05
```
- 출력 = `_workspace/{프로젝트}/antiai/{YYYY-MM-DD-NNN-TAG}/` — `01_input.txt`(한 줄 = `[NNNN] 문구`, 장표 사이 빈 줄) · `units.json` · `meta.json`. 마지막 줄 `RUN_DIR=`가 ②의 run 폴더다.
- 대상: 거버닝 · 본문 항목 · 표 칸 · 결론 바 · 카드 문장(한글 6자 이상).
- 제외: 표지 · 목차 · 간지, `04_content.md` 머리말 · 태그라인 · 작업 메모 줄(레이아웃 · 레퍼런스 · 근거 · 비고 · 자기검증 · 출처), 「카드1 진단:」 같은 줄머리 라벨, 덱의 header · footer · nav(로고 락업 · 장 이름 · 쪽 번호), 조견표 등은 `--skip-codes`.
- 강조(`**…**` · `<b>` · `<em>` · `<span>`)는 `⟦n⟧…⟦/n⟧`, 줄바꿈 · 인라인 코드 · 링크는 `⟦n/⟧` 표식으로 넘어간다 — 코드 · 링크 안 글자는 스킬이 볼 수 없어 바뀌지 않는다.

### ② 윤문 — `humanize-korean` 스킬
`Skill` 도구로 `humanize-korean`을 부르고, 인자에 아래를 그대로 적는다.

```
입력 = {RUN_DIR}/01_input.txt (이미 저장한 파일). run 폴더 = {RUN_DIR} 그대로 사용, _workspace/{run_id}는 새로 만들지 않는다.
장르: 리포트 (shim --genre report)
강도: 기본 (S6 변경분은 「가볍게」)
아래 [제안서 보존 지침]을 진단 · 윤문 · finalize 콜에 같이 넘김.
strip_injected_commas 는 --all 없이 (거버닝 · 결론 바 쉼표는 하우스 기준).
{references/antiai-pass.md §3 블록 전문}
```

- 산출 = 같은 폴더 `final.md`(+ `00_metrics.json` · `02_diagnosis.md` · `09_finalize.json`).
- 게이트(`verify_gates.py`) **exit 2(문자 변경률 50% 이상)면 채택하지 않는다** — 스킬 규칙대로 1회 롤백 재실행, 재차 2면 ③으로 가지 않고 사용자에게 보고.
- 덱 전체(1,000줄 안팎)는 반복 라벨 탓에 어휘 다양성 점수가 낮아 heavy가 잡히는 게 보통이다(FunETF 5–8분 · LLM 3콜). 「변경 없음」이 대부분인 게 정상 결과다.

### ③ 반영 — 줄마다 검증 후 되돌려 넣기
```
python -X utf8 scripts/antiai_units.py apply {RUN_DIR} --keep 0012,0040 --who {담당자}
```
- 원본 제자리 갱신 + 직전본 `<이름>_prev.<확장자>` 백업. 덱 HTML은 `<head>` 수정 이력 한 줄과 `revision` 메타 날짜가 자동으로 들어간다.
- **자동 원문 유지** — 아래 중 하나라도 걸린 줄은 윤문안을 버리고 원문을 둔다.

  | 사유 | 기준 |
  |---|---|
  | 표식 순서 | `⟦n⟧ ⟦/n⟧ ⟦n/⟧` 개수 · 번호 · 순서가 원문과 다름(강조 · 줄바꿈 깨짐) |
  | 수치 | 숫자 토큰 묶음이 원문과 다름 |
  | 영문 토큰 | 영문 단어(서비스명 · 약어 · 개념명) 묶음이 원문과 다름 |
  | ㅁ 명사형 어미 | 원문에 없던 「~함 · ~됨 · ~음 · ~없음 · ~씀 · ~듦」 끝이 새로 생긴 줄 |
  | 확정 · 지정 유지 | `--keep`로 지정한 ID(사용자 확정 문장 · 컨셉 원문) |
  | 원본 변경 | 추출 뒤 그 줄이 바뀜. 원본 파일이 바뀌었으면 apply 자체가 멈춘다 → 다시 extract(또는 `--force`) |

- 산출 = run 폴더의 `diff.md`(장표 · 전 · 후 표 + 자동 원문 유지 목록 · 사유) · `diff.tsv` · `apply.json`. 먼저 `--dry-run`으로 표만 보고 반영해도 된다.

### ④ 2차 — 하우스 문체
- `perl scripts/check_style.pl <원본>` → [위반] 0건. [주의] 「표현」 건은 `writing-style.md` §4-1로 한 건씩 판단.
- 거버닝 메시지는 전역 거버닝 규칙(20–40자 · 상태 묘사 · 대비 한 문장)으로 다시 읽는다 — 1차 윤문이 거버닝을 서술문으로 풀었으면 명사구로 되돌린다.
- **사용자 확정 요청** 때 `diff.md`의 교정 표(전 · 후)를 같이 보인다. 줄이 많으면 장표별 대표 줄 10개 안팎 + 전체 표 경로.

## 3. 제안서 보존 지침 (②에서 스킬 콜에 그대로 넘기는 블록)

`{ }` 자리만 채워 넘긴다.

```
[제안서 보존 지침 — proposal 하네스]
- 문서: IT 서비스 사업 제안서 장표 문구. 장르 리포트. 격식은 줄마다 다른 설계된 혼재 — 줄마다 원래 격식을 그대로 둔다.
  · 라벨 · 카드 제목 · 항목 · 표 칸 = 명사구 종결 유지(「~부재」「~관리」「~필요」). 「~함 · ~임 · ~음 · ~됨 · ~둠 · ~씀 · ~듦 · ~않음」 어미를 새로 만들지 않는다.
  · 본문 문장 · 결론 바 = 합니다체 유지. 한다체 · 해요체로 바꾸지 않는다. 해요체 UI 문안(푸시 · 알림 · 버튼 예시)은 그대로.
- 줄 구조: `[NNNN] 문구` 1줄 = 장표 텍스트 요소 1개. ID 유지, 병합 · 분할 · 재배열 금지, 빈 줄 그대로. 고칠 데가 없는 줄은 원문 그대로가 정답이다.
- 표식: ⟦n⟧…⟦/n⟧(강조) · ⟦n/⟧(줄바꿈 · 코드 · 링크)는 개수 · 번호 · 순서 그대로. 강조한 개념은 같은 표식 안에 남긴다. 빈 표식 쌍도 그대로.
- 거버닝 메시지(장표 대제목): 「현상, 결론」 · 「A가 아니라 B」 · 「A에서, B로」 · 짝 장표 대구는 하우스 스타일의 의도된 대비다. 틀과 그 안의 쉼표는 살리고, 걸린 어휘 · 어미만 고친다. 명사구 끝 유지, 서술문으로 풀지 않는다.
- 불릿 · 표를 문장으로 풀지 않는다(개조식이 제안서 형식).
- 손대지 않는 줄: 컨셉 문장 · 컨셉 키워드 {02_concept.md 한 줄 컨셉 · 키워드}, 사용자 확정 문장 {ID 목록}, 템플릿 반복 라벨 · 장 머리말 · 캡션.
- Do-NOT: 숫자 · 날짜 · 비율 · 금액 · 인원, 회사 · 서비스 · 제품명, 영문 약어 · 개념명, 과제 · 장표 코드, 「 · 」 구분자, 화살표(→ ↔), 「」 따옴표, URL · 도메인, 출처 줄, 준법 · 고지 문구, [미검증] · [정책 확인 필요] · [추가 제안] · [CI 확인 필요] 플래그.
- 과윤문 경계: 지배 패턴에 걸리지 않은 줄은 「변경 없음」. 화면 · 기능 · 수치 · 도구 이름을 구체적으로 쓴 실행 장표는 거의 손대지 않는다.
- 하우스 문체가 따로 고치는 것(2차): 한자어 서술 → 쉬운 동사, 항목 끝 한자어 명사, 본문 연결어미 쉼표. 1차에서 걸리면 같은 방향으로 고쳐도 되지만 일부러 찾지 않는다.
```

## 4. im-not-ai와 하우스 문체가 어긋날 때 (하우스 우선)

| 항목 | im-not-ai 판단 | 하우스 문체 | 처리 |
|---|---|---|---|
| 불릿 · 개조식 | 불릿 과다를 AI 티로 봄 | 개조식 · 명사구 끝이 제안서 형식 | 불릿 유지(§3 지침) |
| 거버닝 대비 틀 | D-7 「X에서, Y로」 · C-8 대구를 AI 티로 봄 | 거버닝 규칙의 대비 · 짝 장표 대구 | 틀 유지, 같은 대구가 여러 장에 메아리치는 줄만 정리 |
| 연결어미 쉼표 | C-11 제거 | 본문 제거는 같음(§4-1 ③). 거버닝 · 결론 바 안 쉼표는 기준 미정 | `--all` 없이 — 새로 쓴 문장만 제거 |
| 명사형 끝 | 격식 보존(원래 어미 유지) | ㅁ 어미 금지 → 명사구 | ③ 자동 원문 유지 + ④ check_style |
| 당위 종결 | I-4 연쇄를 2개 이하로 | 같은 방향. 결론 바 약속형(~하겠습니다)은 하우스 예외 규칙 | 하우스 예외 유지 |
| 한자어 서술 · 「~하여」 | 어휘 점검 일부 | §4-1 ① 쉬운 동사 | 2차에서 마무리 |
| 영문 개념어 | B 계열 영어 인용 과다 | RFP · 컨셉 용어는 의도된 표기 | ③ 영문 토큰 검증으로 원문 유지 |

## 5. 폴백 (스킬이 안 잡히는 세션)

- 런타임 에이전트 3종은 `../../skills/im-not-ai/agents/humanize-{diagnostician,monolith,finalizer}.md`를 지시문으로 넘겨 일반 에이전트로 돌린다.
- Python이 없으면 정량 점수 · 게이트 없이 진행하지 말고 1차 윤문을 건너뛴 뒤 완료 보고에 적는다(게이트 없는 윤문은 과윤문을 못 잡는다).
- 폴백으로 돌렸으면 완료 보고에 「im-not-ai 폴백 실행」 한 줄.
