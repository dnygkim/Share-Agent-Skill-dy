## 2. 고객사 CI — 로고 Primary 컬러 기본 적용

**제안 하네스의 HTML 산출물은 고객사 로고의 Primary 컬러를 기본으로 입힌다**(2026-11-11 사용자 지시 — 전역 규칙
「CI 옵트인」에 대한 이 하네스의 상시 지시). S1 보고서 · 덱 HTML · 변경분 HTML 모두 같다(덱은 `references/design-system.md` §2).

### 2-1. ★ 대표 사이트 · 로고 확인 — 못 찾으면 먼저 묻는다
추출 전에 **고객사 대표(공식) 사이트**와 **로고**를 확정한다. 확인 순서:
1. RFP · 회의록 · 브리핑에 적힌 고객사 · 서비스 URL
2. 클라이언트명으로 공식 도메인 조회 — 공개 도메인만, **RFP · 입찰 조건은 검색어에 싣지 않는다**(Dan Jr. W-12)
3. 대표 사이트 헤더의 로고(인라인 SVG · 로고 이미지)

아래 중 하나라도 해당하면 **추정해서 진행하지 않고 사용자에게 먼저 묻는다** — 답을 받기 전에는 HTML을 추출하지 않는다.
- 대표 사이트를 찾지 못함 · 후보가 둘 이상(그룹사 ↔ 계열사, 회사 ↔ 서비스 브랜드, 국문 ↔ 글로벌 사이트)
- 사이트가 열리지 않음(차단 · 로그인 벽 · 리뉴얼 중) · 다른 회사로 바뀐 도메인
- 로고를 찾지 못함 · 로고가 래스터 이미지뿐이라 색을 특정하기 어려움 · 로고와 사이트 대표색이 다름
- 사업 대상 서비스(예 FunETF)와 발주사(예 삼성자산운용) 중 어느 CI를 쓸지 모호함

질문 형식(한 번에 한 질문):
> 「{클라이언트명}」 대표 사이트 · 로고를 확인하지 못했습니다({이유}). ① 대표 사이트 URL 또는 로고 파일을 알려 주시거나
> ② 후보 {A} · {B} 중 하나를 골라 주세요. ③ 확인 없이 진행하면 하우스 기본 스타일 + `[CI 확인 필요]`로 추출합니다.

- 사용자가 ③을 고르거나 「알아서」라고 하면 하우스 기본값으로 추출하고 `[CI 확인 필요]`를 표기한다. 중립 팔레트를 새로 만들지 않는다.
- 비대화형 실행(질문 불가)도 ③과 같다 — 완료 보고 첫 줄에 「CI 미확인 — 하우스 기본으로 추출」을 적는다.

### 2-2. Primary 값 추출 (우선순위)
1. 대표 사이트 공통 CSS의 브랜드 변수(`:root { --color-primary… }`, `--brand…`) — 예 삼성자산운용 `samsungfund.com` gemein.css `--color-primary-blue #1454FF`
2. 헤더 로고 SVG의 `fill` 중 주 색
3. 고객 제공 브랜드 가이드라인 PDF
4. 사이트 주요 CTA · GNB 활성색(개발자 도구 Computed)
- 과거 산출물 · 다른 프로젝트의 CI를 재사용하지 않는다. 값은 매번 실측하고 출처를 CSS 주석 · 수정 이력에 남긴다.
- 확정하면 추출 전에 한 줄로 알린다: 「{클라이언트명} CI Primary `#HEX`({출처})로 추출합니다」. 사용자가 다른 색을 지정하면 그 값이 정본.

### 2-3. 적용 범위 (골격 `2b. CI 오버라이드` 블록)
- `--accent` · `--warn` = Primary. 토프바 · 반전 블록(`.thead` · `.closing` · `.node.key` · `.totop`) · 강조선(h2 · 표지 · `.concept` · 표 머리) · LNB 활성 · PART 번호 · `a.ext` hover · 그래프 `.key` 막대.
- 바탕 · 선 · 보조 글자(`--paper` · `--paper-2` · `--line` · `--line-2` · `--ink-2` · `--ink-3`)를 Primary 색상 계열(쿨/웜)의 저채도 중립색으로 함께 바꾼다. 사이트에 그레이 팔레트가 있으면 그 값을 쓴다. `--ink`는 거의 검정 유지.
- 정본에 웜 페이퍼 `rgba(241,237,229,…)`로 박힌 반전 글자 · 반투명 바탕은 흰색 rgba로 덮는다(골격에 목록 포함, 정본 §2b와 같다).
- **토프바 로고**: 대표 사이트 헤더의 워드마크 SVG를 흰색 단색(`fill="#FFFFFF"`)으로 바꿔 `.logo` 앞에 둔다(높이 17px). SVG가 없으면 클라이언트명 텍스트.
- 인쇄: 토프바 · PART 번호는 `print-color-adjust:exact`.

- 섹션 수는 RFP에 맞춘다. PART Ⅲ은 RFP 중점 과제 수만큼, 구축 · 리뉴얼 사업은 PART Ⅱ에 UX · 여정(`01_ux.md`)을 넣는다. 번호는 0부터 연속, PART Ⅳ는 PART Ⅲ 다음 번호.
- **섹션 패턴**: `h2`(번호) → `.concept`(거버닝 한 줄 + `.sub` 근거) → 그래프 · 표 → `h3`(id `sNN-n`) 하위. 목차 · LNB에 h3까지 건다.
- **그래프**: 하우스 스타일 §23(`.hbars` · `.cols` · `.ms` · `.gbar.mk`) · §21 간트. 계열 하나, 강조 막대만 `.key`(= Primary). **같은 수치는 표로도 남긴다**(표가 정본). `.chart-cap` = 무엇 · 출처 · 기준일, `.chart-note` = 함의 한 줄.
- **표기 태그**: `보완 필요`(RFP 미기재) · `추정` · `미검증` · `벤더 주장` · `Q번호`(발주처 질의) · `내부 확인` — 목차 아래 범례와 같게.
- **착수 시 대조**: 이트라이브 실적표(메리츠화재 2027 제안 브리핑 「레퍼런스」 장)와 고객사 수행 이력을 먼저 대조해 §0 핵심 판단 · PART Ⅳ 「수행 이력 · 실적 연결」에 반영한다(현 운영사 여부를 놓치지 않는다).
- **문체**: 거버닝 = 전역 「거버닝 메시지 문체」, 본문 = 명사형 종결 · 개조식(`references/writing-style.md`). 외부링크 = `CLAUDE.md` 5a.
