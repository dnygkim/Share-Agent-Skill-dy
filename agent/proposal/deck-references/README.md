## 쓰는 법 (proposal 에이전트)

- **작업 시작(Phase 0)**: 이 README 「학습 이력」 맨 위 줄과 네 파일 머리의 「이번 주 추가」를 먼저 읽는다.
- **S2 컨셉**: `expressions.md` §1 표지 · 컨셉 카피 · §6 맺음 — 컨셉 한 줄 · 회수 문장 후보를 쓸 때.
- **S3 목차**: `diagrams.md` — `03_structure.md` 페이지별 삽입내용에 「도식」 후보를 적을 때. 같은 도식이 연달아 세 장 넘게 이어지지 않게 고른다.
- **S4 초안 · HTML**: 네 파일 전부 — `04_content.md` 장표마다 「레이아웃」 줄(도식 · 인포그래픽)과 문구, HTML 골격의 색 역할 · 라벨 체계.
- **qa**: 덱 전체에서 도식 · 인포그래픽 종류가 한두 가지로 쏠리지 않았는지, 「버릴 표현」이 남지 않았는지.
- **규칙 문서가 우선**: 문장 = `../references/writing-style.md`, 도식 · 면/선/색 = `../references/slide-layout-guide.md`, 장표 합격선 = `../references/slide-quality-bar.md`, 토큰 = `../references/design-system.md`. 이 폴더는 실제 제안서에서 모은 **사례 · 패턴**이다. 어긋나면 규칙 문서를 따른다.
- **그대로 베끼지 않는다**: 예시는 구조만 빌려 그 건의 내용 · 근거로 새로 쓴다. 출처가 여러 건인 패턴일수록 검증된 형태다(줄 끝 R-번호 수).
- **규칙 승격**: 같은 패턴의 출처가 3건 이상 쌓이면 예약 작업이 「규칙 승격 후보」로 보고한다 → 사용자 확정 후 규칙 문서에 옮긴다.

- **학습 밖**: RFP · 회의록 · 피드백 · 견적 · 공수 · 이력서 · 음성 · 압축 파일, `00. 공수 및 영업대응, 기타` 폴더.

## 공개 원칙 (공유 리포가 public)

- 고객사명 · 서비스명 · 상품명 · 인명 · 내부 도구명 · 수치 · 금액 · 일자 · 배점은 `{고객사}` `{서비스}` `{수치}` 같은 자리 표시로 바꿔 쓴다. 출처는 R-번호와 업종 · 시기만.
- 색은 역할 · 단계 · 쓰임만 적고 HEX(고객 CI)는 적지 않는다. 이미지 · 스크린샷 · 원문 파일은 넣지 않는다(텍스트 패턴만).
- `scripts/deckref_tool.py check`가 커밋 전에 금지 패턴(이메일 · 전화 · 금액 · data URI · 드라이브 링크 · 거부 목록 이름)을 막는다. 파일 ID · 제목 · 건 이름은 비공개 `_state.json`에만 둔다.
