## 1. 진단 · 이슈

- **원인 · 체감 · 영향 3열 행** — 열 머리 「주요 발생 요인 | 현업 체감 | 방지 시 영향」, 행 = 주제 3개(아이콘 · 주제 · 부제), 체감 칸은 라벨 + 현업 한 줄, 영향 칸 앞 화살표(→) · 하단 POINT · 현황 진단 · [R-0002]
- **딜레마 3장 묶음** — 개요 장(딜레마 3개 번호 카드) → 딜레마마다 「질문형 문제 장 → 원인 · 영향 장 → 고려사항 장」 · 같은 번호 원문자(①②③)로 이어 읽힘 · 사업 이해 · 리스크 · [R-0001, R-0006]
- **안 · 밖 대비** — 왼쪽 INSIDE(내부 의존 · ↺ 반복 고리) / 오른쪽 OUTSIDE(외부 자극 · 리스크 표지) 두 판, 가운데 대비 · 매너리즘 · 외부 역량 필요 · [R-0001]
- **배경 ↔ 목표 같은 순서 짝** — 배경(문제) N개와 목표 N개를 같은 순서로 위아래 또는 좌우에 짝지음(4 → 4, 3 ↔ 3), 가운데 겹친 원 3개로 짝을 잇거나 맨 아래 결론 바 1줄 · 제안 배경 · 목적 · [R-0010, R-0013, R-0015]
- **5 Why 사다리 → 원인 3카드** — 표 5행(WHY 질문 | 확인할 구조적 원인), 아래 CAUSE 01–03 카드, 머리에 「제안 단계 가설 · 인수 후 검증」 표기 · 근본 원인 · [R-0006]
- **사실 · 해석 · 방향 3열** — 열 머리 「RFP에서 확인한 사실 | 우리가 읽은 위험 | 설계 방향」, 행 4개, 아래 정보 성격 각주 · 사업 이해 · [R-0006]
- **문제 3열 + 주체별 영향 띠** — 위 문제 열 3개(이름 + 불릿 3), 아래 영향 띠 3칸(고객 · 현장 · 운영)에 주체별 결과 2줄 · 현행 분석 · [R-0015]
- **이슈 카드 4장 + 「그래서」 결론** — 이용 단계 순(메뉴 → 첫 화면 → 자료 → 문의)이나 2×2로 카드 4장(두 글자 라벨 · 체감 문장 · 큰 수치 · 원인 2줄), 아래 결론 한 줄 또는 ✓ 2줄 · 핵심 이슈 · [R-0005, R-0007]
- **「지금 {고객사}는」 4요인 카드** — 번호 4장(규모 · 사업 확장 · 전환 과제 · 기념 시점), 카드마다 불릿 + 미니 KPI, 하단 ✓ 한 줄 + 설계 방향 · 목적 · 배경 · [R-0007]
- **이용자 유형별 AS-IS 여정** — 이용자 유형 하나당 1장, 가로 3구간(Before · On Site · After), 제목에 「{무엇}은 있지만, {어디}에 닿는 길이 없는 여정」 · 사용자 여정 · [R-0007]
- **사용자 유형 열 + 이슈 ↔ 방향 4행** — 왼쪽 AS-IS 사용자 유형(주 · 부 이용자), 오른쪽 이슈 4개마다 TO-BE 방향 한 줄 · slide-layout-guide 「진단 결과 ↔ 개선 짝 줄」 변형 · 현행 분석 · [R-0013, R-0015]
- **문제 콜아웃 화면 → 개선 목록 + 목업** — 왼쪽 현재 화면 캡처와 문제 콜아웃 4–6개, 오른쪽 개선 방향 3줄과 개선 목업 · 가독성 · 정보 소비 개선 · [R-0011]
- **Pain Points 3카드 + 대상 규모 띠** — 카드 3개 가로(원인 + 결과 한 구), 아래 띠 한 줄에 적용 대상 규모 · 현안 장 · [R-0008]

## 2. 전략 · 강점

- **이유 카드 4열** — 번호(01–04) · 두 글자 라벨 · 2줄 주장 · 이미지 자리 · 근거 2–3줄 · ✓ 핵심 포인트(수치) 순서로 같은 높이 4장 · 제안사 특장점 · [R-0002]
- **과업 · 전략 카드 → 상세 장** — 개요 장에서 번호 카드 3–5개(전략 · 키워드 · 한 줄) → 카드마다 상세 장 1장씩 같은 번호 머리 · 전략 → 과제 구조 · [R-0001, R-0010]
- **4층 · 4단 계단** — 아래에서 위로 4단(이슈 → 해결 방향 → 전술 → 목표, 또는 기초 → 컴포넌트 → 패턴 → 흐름, 또는 표준화 → 정비 → 허브화 → 확산), 단마다 항목 3–4개 · slide-layout-guide 「3층 계단」의 4단 변형 · 구축 · 디자인시스템 · 확산 전략 · [R-0012, R-0013, R-0015]
- **2층 + 연결층 적층** — 아래 기반층 · 가운데 연결층(공통 기록) · 위 엔진층, 행마다 구성 | 작동 결과, 위로 향하는 화살표(경험이 위층을 키움)와 아래로 향하는 화살표(재사용이 기반 강화) · 전략 구조도 · [R-0006]
- **과제 추적표** — 행 = 전략 과제 3–5개, 열 = 「과제 · 실행 방법 · 근거 실적」 또는 「문제 → 과제 → 전략 → 모듈 → 확인할 성과」, 행 끝에 핵심 메시지 태그 · 운영 전략 요약 · [R-0005, R-0006]
- **범위 4블록 + 연계 시스템 칩** — 사업 범위 4영역(제목 + 정의 + 세부 3–4줄) 2×2, 하단 대상 시스템 한 줄과 유관 시스템 칩 격자 · 제안 범위 · [R-0010]
- **사분면 역량 + 가운데 대상** — 역량 영역 4개 2×2(한 줄 + 근거 2줄), 가운데 고객 사업명 · 회사 역량 · [R-0015]
- **컨셉 인용 + 두 채널 → 통합 루프 + 3열** — 위 따옴표 컨셉 한 줄, 가운데 앱 · 웹이 통합 경험 루프로 모이는 그림, 아래 키워드 3열 · UX 전략 개요 · [R-0011]
- **UI 가이드 3묶음** — 기능(사용성 · 시나리오) / 비주얼(아이콘 · 일러스트) / 구조(버튼 · 배치 · 입력) 3묶음, 묶음마다 역할 한 줄 · UI 가이드 활용 · [R-0011]
- **역할별 같은 화면 3장** — 같은 화면을 역할 3개 버전으로 나란히, 화면마다 번호 콜아웃, 아래 역할별 우선 정보 2줄 · 권한별 맞춤 홈 · [R-0009]
- **IA 이용 대상 구역 메뉴 트리** — 1단계 메뉴 열 × 2단계 목록, 메뉴 묶음을 이용 대상 구역으로 나눠 색 띠, 외부로 나가는 메뉴는 → 표지 · 정보 구조 · [R-0013]
- **두 진입 경로 수렴** — 사용자 유형 3개 → 입력 경로 2개(메뉴 선택 / 자연어 입력) → 같은 기능, 둘레에 원리 카드 3개 · 챗봇 · 상담 방안 · [R-0014]

## 3. 프로세스 · 흐름

- **재투입 순환 4단계** — 01 도구 투입 → 02 반복 공수 절감 → 03 남는 공수 → 04 고도화 재투입 ↺(처음으로 되돌아오는 화살표), 단계 수를 늘린 순환(자산화 7–9단계 ↺)도 같은 형식 · 효율화 · AX · [R-0001, R-0006]
- **단계 소요 흐름** — STEP 1(소요 1일) → STEP 2(소요 3–5일) → STEP 3(반영) · 단계 상자 위에 소요 기간, 화살표 사이 산출물 · 처리 절차 · 패스트트랙 · [R-0001]
- **N단계 파이프라인 + 산출물 · 검증 기준 2줄** — 번호 단계 상자 가로 ▶, 상자 아래 「산출물」 「검증 기준」, 위 띠에 단계 묶음 라벨 · 단계 소요 흐름의 변형 · 구축 · 이관 · 보안 · [R-0007]
- **도구 체인 흐름** — 입력(회의 음성 등) → 도구 A → 도구 B → 산출물(초안) · 단계 이름 위 큰 % 단축률과 짝 · 직무별 AX 적용 · [R-0001]
- **퍼널 + 기능 매핑** — 유입 → 전환 → 활성화 3단 가로 퍼널, 각 단 아래 해당 신규 기능 번호(①②③), 여정 단계 아래 운영 영역 · AI 적용 지점을 붙인 변형도 · 성장 전략 · [R-0001, R-0005]
- **목업 + 번호 콜아웃 목록** — 왼쪽 화면 1–3장에 원문자 콜아웃(①–⑨), 오른쪽 「주요 구현 방안 · 개선 내용」에 같은 번호 목록, 마지막 번호는 기대 효과 · 기능 상세 장 대부분이 같은 판형 · 화면 설계 · 기능 개선 · [R-0009, R-0010, R-0011]
- **상태 흐름 주체 레인** — 신청인 / 담당자(또는 내부 앱 / 고객 앱) 레인을 위아래로 두고 같은 열에 단계 · 상태 안내를 맞춤, AS-IS / TO-BE 두 줄로 놓고 TO-BE에만 상태 칩(접수 → 처리 중 → 완료)과 알림 아이콘 · 업무 절차 개선 · 연동 흐름 · [R-0013, R-0014]
- **상태 스테퍼 + CTA 짝** — 진행 상태 약 7단을 가로 스테퍼로, 바로 아래 단계마다 나오는 버튼 라벨을 1:1로 맞춘 행, 현재 단계만 강조 · 업무 진행 화면 · [R-0009]
- **3레인 업무 프로세스** — 행 = 기간계 → 관리자 → 사용자 화면 3레인, 열 = 케이스 2개(일반 · 특수), 레인 사이 아래 방향 화살표, 코드 매핑 예시 상자 · 관리 기능 · 연동 설계 · [R-0010]
- **가로 흐름 + 실제 문구 목업** — 위 5–6단 가로 흐름(선택 → 안내 → 신청 → 조건 충족 시 발송 → 진입), 아래 흐름별 팝업 · 메시지 목업 2–3개 · 알림 · 전환 유도 기능 · [R-0010]
- **채널 수렴 단계 흐름** — 채널 2줄(비대면 / 대면)이 앞 1–3단계는 따로 가다 특정 단계부터 한 줄로 합쳐져 끝까지, 구간 머리 라벨 2개(특화 구간 · 공통 구간), 번호는 이어서 셈 · 통합 프로세스 · [R-0015]
- **배포 전 관문 고정 단계** — 요청 → 기획 → 디자인 → 퍼블리싱 → QA · 심의 → 배포 · 측정, QA 칸만 관문 표시, 아래 「관문 통과 없이 배포 없음」 + 「배포 뒤 지표 → 다음 요청으로 환류」 · 운영 프로세스 · 품질 · [R-0005]
- **요청 종류별 두 갈래 흐름** — 위 줄 긴급(우선순위 조정 → 즉시 처리 → 결과 공유), 아래 줄 추가(접수 → 협의 → 인력 배정 → 수행 · 확인) · 일정 · 추가 업무 대응 · [R-0005]
- **실증 5단계 → 결과 3타일 → 적용 원칙 4** — 위 가로 5단계(수집 → 라벨링 → 분류 · 확인 → 적용 → 전후 비교), 가운데 결과 타일 3개, 아래 「{고객사} 적용 원칙」 카드 4개 · PoC · 레퍼런스 · [R-0005]
- **판정 문턱 3갈래 분기** — 검증 결과를 문턱 3구간(진행 / 조건부 진행 / 중단)으로 나누고 구간마다 다음 행동을 화살표로, 위에 판단 기준 표 · PoC · 시범 적용 · [R-0014]
- **처리 파이프라인 + 사용자 확인 꼬리** — 대괄호 단계 상자 4개(입력 → 변환 → 검색 → 판정) 가로, 아래 줄 업로드 → 자동 분류 → 사용자 최종 선택 → 완료, 쌓인 데이터가 앞으로 돌아오는 고리 · AI 기능 흐름 · [R-0014]
- **배정 규칙 트리 + 예외 칩** — 분류 기준 → 업체 → 팀 카드(담당 범위 · 근무 요일 · 처리량) 자동 배정 줄, 옆에 수동 배정 예외 칩 4개 · 대량 처리 운영 · [R-0014]
- **이슈 감지 → 해결 가능 · 불가 분기** — 과제 전달 → 요건 분석 → 진행 줄 아래 일일 점검의 이슈 감지 갈래, 해결 가능이면 실무 조직, 불가면 지원 요청 → 품질 조직 보고 · 이슈 대응 · [R-0012]
- **단계마다 검토 · 재작업 되돌림** — ①요건 → ②설계 → ③디자인 → ④배포, 단계 사이마다 되돌림 화살표, 끝에 회고 → 다음 과제 · 「가로 n단계 + 되돌림」 변형 · 스프린트 절차 · [R-0012]
- **회고 3칸 → 원형 순환** — 왼쪽 성과 분석 · 이슈 도출 · 과제 선정 3칸 세로 → 오른쪽 5노드 원형 순환 · 반복 개선 · [R-0012]
- **세로 ▼ 작업 절차 + 오른쪽 번호 상세** — 왼쪽 4단계 세로(셋팅 ▼ KPI 선정 ▼ 이벤트 설계 ▼ 대시보드), 오른쪽 같은 번호 상세 박스 + SAMPLE 화면 · 데이터 · 측정 체계 · [R-0007]
- **요청 경로 세로 3단 + 매핑 표** — 1 요청 유입 ▼ 2 변환 ▼ 3 정상 표출, 옆에 「구분 | 기존 | 신규 | 처리 방식」 표 · 주소 이관 · [R-0007]
- **외부 연동 왕복 레인** — 레인 4개(사용자 · 앱 · 중계 사업자 · 외부 기관) 가로, 요청 → 전달 → 결과 → 완료를 지그재그 왕복 화살표, 위에 앱 전환 요약 상자 · 인증 · 연계 · [R-0009]
- **저장 · 조회 2줄 쌍방향** — 위 줄 저장(촬영 → 전송 → 처리 → 보관, 오른쪽), 아래 줄 조회(요청 → 다운 → 화면, 반대 방향), 같은 상자를 위아래로 공유 · 파일 처리 · [R-0009]
- **망 구간 존 구성도** — 외부망 → DMZ → 내부망(채널계 · 기간계) 열을 존으로 나누고 서버 · 중계 API 배치, 화살표 두 종류(필요할 때 가져오기 / 정기 이관), 이번 범위만 점선 「신규 개발 영역」 · 인터페이스 · 연동 구성도 · [R-0009, R-0013]
- **레거시 As-Is · 어댑터 · To-Be 3열 브리지** — 왼쪽 기존 시스템, 가운데 변환 계층(번호 3기능), 오른쪽 신규 계층, 열 사이 ▶ 라벨 · 레거시 연계 · [R-0007]

## 4. 비교 · 전환

- **등식형 전후** — 「BEFORE {기존 투입} vs AFTER {적용 후 절감} = {연간 합계}」 — 세 상자를 vs · = 기호로 잇고 결과 상자만 강조 · 효과 정량화 · [R-0001]
- **선택지 × 같은 항목 비교** — 선택지 N개를 열로, 같은 평가 항목 3개를 행으로 반복 · 마지막 행(또는 마지막 「반면교사」 열)만 강조, 하단 시사점 ✓ · 기능 제안 · 구현 방식 · 벤치마크 · [R-0001, R-0007, R-0009]
- **전후 화면 짝** — BEFORE / AFTER 화면 두 장을 같은 크기로 좌우, 바뀐 곳 번호 표시, 문제점 1–3 ↔ 개선 1–3 번호 대응 · 기능 제안 · [R-0001, R-0008]
- **채널 짝 화면** — 앱 화면(하단 탭바)과 웹 화면(대체 내비)을 같은 크기로 좌우, 대응 요소를 가운데 라벨로 연결 · 전후 화면 짝의 채널 대응 변형 · 웹 · 앱 일원화 · [R-0011]
- **단계 타일 전후 + 처리 범례** — AS-IS 번호 타일 N개와 TO-BE 번호 타일 N개를 위아래로, 타일 색을 범례 3종(삭제 · 유지 · 부분 통합)으로 구분 · 프로세스 단축 · [R-0011]
- **가짜 · 진짜 대비 두 판** — 왼쪽 「FALSE {가치}」, 오른쪽 「TRUE {가치}」, 같은 4행 짝, 아래 「첫 번째 · 두 번째 {가치}」 두 줄 · 개념 재정의 · [R-0006]
- **AS-IS → 개선 방향 → 하나로 수렴** — 왼쪽 AS-IS 4항목 ↔ 오른쪽 개선 방향 4항목, 아래 수렴 띠에 칩 4개 · 좌우 2판 변형 · 개선 방향 · [R-0015]
- **공통 컴포넌트 열 → 현지 템플릿 N열** — 왼쪽 공통 컴포넌트 번호 목록 → 오른쪽 지역별 템플릿 열 N개에 같은 번호를 순서만 바꿔 배치 · 다국어 · 글로벌 확산 · [R-0012]

## 5. 일정 · 운영 체계

- **분기 반복 타임라인** — Q1 → Q2 → Q3 → Q4 각 칸에 같은 정례 활동과 담당 역할 · 정례 거버넌스 · [R-0001]
