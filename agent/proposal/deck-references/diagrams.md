## 1. 진단 · 이슈

- **원인 · 체감 · 영향 3열 행** — 열 머리 「주요 발생 요인 | 현업 체감 | 방지 시 영향」, 행 = 주제 3개(아이콘 · 주제 · 부제), 체감 칸은 라벨 + 현업 한 줄, 영향 칸 앞 화살표(→) · 하단 POINT · 현황 진단 · [R-0002]
- **딜레마 3장 묶음** — 개요 장(딜레마 3개 번호 카드) → 딜레마마다 「질문형 문제 장 → 원인 · 영향 장 → 고려사항 장」 · 같은 번호 원문자(①②③)로 이어 읽힘 · 사업 이해 · 리스크 · [R-0001, R-0006]
- **안 · 밖 대비** — 왼쪽 INSIDE(내부 의존 · ↺ 반복 고리) / 오른쪽 OUTSIDE(외부 자극 · 리스크 표지) 두 판, 가운데 대비 · 매너리즘 · 외부 역량 필요 · [R-0001]
- **배경 ↔ 목표 같은 순서 짝** — 배경(문제) N개와 목표 N개를 같은 순서로 위아래 또는 좌우에 짝지음(4 → 4, 3 ↔ 3), 가운데 겹친 원 3개로 짝을 잇거나 맨 아래 결론 바 1줄 · 제안 배경 · 목적 · [R-0010, R-0013, R-0015, R-0021]
- **5 Why 사다리 → 원인 3카드** — 표 5행(WHY 질문 | 확인할 구조적 원인), 아래 CAUSE 01–03 카드, 머리에 「제안 단계 가설 · 인수 후 검증」 표기 · 근본 원인 · [R-0006]
- **사실 · 해석 · 방향 3열** — 열 머리 「RFP에서 확인한 사실 | 우리가 읽은 위험 | 설계 방향」, 행 4개, 아래 정보 성격 각주 · 사업 이해 · [R-0006]
- **문제 3열 + 주체별 영향 띠** — 위 문제 열 3개(이름 + 불릿 3), 아래 영향 띠 3칸(고객 · 현장 · 운영)에 주체별 결과 2줄 · 현행 분석 · [R-0015]
- **이슈 카드 4장 + 「그래서」 결론** — 이용 단계 순(메뉴 → 첫 화면 → 자료 → 문의)이나 2×2로 카드 4장(두 글자 라벨 · 체감 문장 · 큰 수치 · 원인 2줄), 아래 결론 한 줄 또는 ✓ 2줄 · 핵심 이슈 · [R-0005, R-0007]
- **「지금 {고객사}는」 4요인 카드** — 번호 4장(규모 · 사업 확장 · 전환 과제 · 기념 시점), 카드마다 불릿 + 미니 KPI, 하단 ✓ 한 줄 + 설계 방향 · 목적 · 배경 · [R-0007]
- **이용자 유형별 AS-IS 여정** — 이용자 유형 하나당 1장, 가로 3구간(Before · On Site · After), 제목에 「{무엇}은 있지만, {어디}에 닿는 길이 없는 여정」 · 사용자 여정 · [R-0007, R-0022]
- **사용자 유형 열 + 이슈 ↔ 방향 4행** — 왼쪽 AS-IS 사용자 유형(주 · 부 이용자), 오른쪽 이슈 4개마다 TO-BE 방향 한 줄 · slide-layout-guide 「진단 결과 ↔ 개선 짝 줄」 변형 · 현행 분석 · [R-0013, R-0015]
- **문제 콜아웃 화면 → 개선 목록 + 목업** — 왼쪽 현재 화면 캡처와 문제 콜아웃 4–6개, 오른쪽 개선 방향 3줄과 개선 목업 · 가독성 · 정보 소비 개선 · [R-0011]
- **Pain Points 3카드 + 대상 규모 띠** — 카드 3개 가로(원인 + 결과 한 구), 아래 띠 한 줄에 적용 대상 규모 · 현안 장 · [R-0008]
- **이슈 5열 + 경로 전후 행** — 가로 이슈 카드 #1–#5(문제 명사구 · 키워드 꼬리 · Problem 3줄), 아래 행에 이슈마다 「[AS-IS] 경로 → [TO-BE] 경로」 한 쌍, TO-BE 경로 강조 · IA · 메뉴 현행 분석 · [R-0018]
- **업무 열 × 필요 서비스 행 × 해시 키워드 바닥 행** — 열 = 주요 업무 4, 행 = 고객 과제 · 필요 서비스, 맨 아래 행 = 열마다 「# {키워드}」 1개가 결론 · 개편 키워드 도출 · [R-0018]
- **장소 × 시점 업무 행태 표** — 열 = 장소 5(집 · 자리 · 회의실 · 방문 · 이동), 행 = 시점 3(업무 전 · 중 · 후), 칸마다 업무 라벨 + 비교급 한 줄, 맨 아래 결론 바 · 업무 행태 분석 · [R-0022]
- **원인 범주 3행 → 발생 이슈 → 대처** — 행 = 원인 범주 3, 열 = 원인 | 발생 이슈 2줄 | 대처 방안 2줄, 가로 →, 맨 아래 예외 경로 한 줄 · 인력 이탈 방지 · 리스크 장 · [R-0021]
- **계승 자산 · 문제 2묶음 → 정비 → 목적 수렴** — 왼쪽 위 「검증된 자산」 4행, 왼쪽 아래 「분산 · 복잡성」 3행, 가운데 「정비」 노드, 오른쪽 목적 5항으로 모이는 → · 재구축 제안 배경 · [R-0023]
- **여정 단계별 화면 AS-IS / TO-BE 3열 표** — STEP 1–4(탐색 · 보류 · 구매 · 구매 후) 묶음마다 「화면명 | AS-IS 문제점 | TO-BE 개선 포인트」 · 커머스 현행 사용성 분석 · [R-0020]
- **분석 3갈래 → 키워드 3 수렴** — 트렌드 · 이용 환경 · 현행 분석 3열 요약 → 키워드 3 + 방향 3줄로 모음 · 인사이트 정리 · [R-0020]
- **진단 6카드 → 같은 6행 4열 해결 표** — 앞 장 문제 카드 6(번호 · 과제 라벨 · 현상 · 구조적 원인 · 관찰 근거), 다음 장 같은 6행 × 「관찰된 현상 › 구조적 원인 › 설계 대응 › 확인할 변화」 · 현행 진단 → 해결 방향 · [R-0016]
- **수집 → 탐색 → 질문 3 흐름** — ① 수집 타일 4(자료 종류 · 건수) › ② 탐색 주제 칩 + 조회 막대 › ③ 이용자 질문 3개(질문 원문 + 근거 규모) · 인사이트 도출 · [R-0017]
- **AARRR 5단 현황 + 강화 · 약화 POINT** — 인지 · 방문 · 이용 · 재방문 · 추천 5단 가로, 단마다 수치 1, 아래 강화 POINT · 약화 POINT 짝 카드 · 고객 여정 진단 · [R-0017]
- **추이 그래프 + 원인 분해 3** — 위 주간 추이 + 음영 기간 번호(①–⑤), 아래 원인 카드 3(외부 국면 · 서비스 출시 · 보상 단독), 카드마다 큰 지수 1 · 성과 원인 진단 · [R-0017]

## 2. 전략 · 강점

- **이유 카드 4열** — 번호(01–04) · 두 글자 라벨 · 2줄 주장 · 이미지 자리 · 근거 2–3줄 · ✓ 핵심 포인트(수치) 순서로 같은 높이 4장 · 제안사 특장점 · [R-0002, R-0021]
- **과업 · 전략 카드 → 상세 장** — 개요 장에서 번호 카드 3–5개(전략 · 키워드 · 한 줄) → 카드마다 상세 장 1장씩 같은 번호 머리 · 전략 → 과제 구조 · [R-0001, R-0010]
- **4층 · 4단 계단** — 아래에서 위로 4단(이슈 → 해결 방향 → 전술 → 목표, 또는 기초 → 컴포넌트 → 패턴 → 흐름, 또는 표준화 → 정비 → 허브화 → 확산), 단마다 항목 3–4개 · slide-layout-guide 「3층 계단」의 4단 변형 · 구축 · 디자인시스템 · 확산 전략 · [R-0012, R-0013, R-0015, R-0020, R-0022]
- **2층 + 연결층 적층** — 아래 기반층 · 가운데 연결층(공통 기록) · 위 엔진층, 행마다 구성 | 작동 결과, 위로 향하는 화살표(경험이 위층을 키움)와 아래로 향하는 화살표(재사용이 기반 강화) · 전략 구조도 · [R-0006]
- **과제 추적표** — 행 = 전략 과제 3–5개, 열 = 「과제 · 실행 방법 · 근거 실적」 또는 「문제 → 과제 → 전략 → 모듈 → 확인할 성과」, 행 끝에 핵심 메시지 태그 · 운영 전략 요약 · [R-0005, R-0006, R-0016]
- **범위 4블록 + 연계 시스템 칩** — 사업 범위 4영역(제목 + 정의 + 세부 3–4줄) 2×2, 하단 대상 시스템 한 줄과 유관 시스템 칩 격자 · 제안 범위 · [R-0010]
- **사분면 역량 + 가운데 대상** — 역량 영역 4개 2×2(한 줄 + 근거 2줄), 가운데 고객 사업명 · 회사 역량 · [R-0015, R-0019, R-0020]
- **컨셉 인용 + 두 채널 → 통합 루프 + 3열** — 위 따옴표 컨셉 한 줄, 가운데 앱 · 웹이 통합 경험 루프로 모이는 그림, 아래 키워드 3열 · UX 전략 개요 · [R-0011]
- **UI 가이드 3묶음** — 기능(사용성 · 시나리오) / 비주얼(아이콘 · 일러스트) / 구조(버튼 · 배치 · 입력) 3묶음, 묶음마다 역할 한 줄 · UI 가이드 활용 · [R-0011]
- **역할별 같은 화면 3장** — 같은 화면을 역할 3개 버전으로 나란히, 화면마다 번호 콜아웃, 아래 역할별 우선 정보 2줄 · 권한별 맞춤 홈 · [R-0009, R-0020]
- **IA 이용 대상 구역 메뉴 트리** — 1단계 메뉴 열 × 2단계 목록, 메뉴 묶음을 이용 대상 구역으로 나눠 색 띠, 외부로 나가는 메뉴는 → 표지 · 정보 구조 · [R-0013]
- **두 진입 경로 수렴** — 사용자 유형 3개 → 입력 경로 2개(메뉴 선택 / 자연어 입력) → 같은 기능, 둘레에 원리 카드 3개 · 챗봇 · 상담 방안 · [R-0014, R-0022, R-0023]
- **관계 3단 순환 + 단계별 장벽 → 해법** — 원형 3단(형성 → 활성화 → 확장 ↺), 가운데 「순환 = 지속 관계」, 단계마다 속마음 라벨 · 핵심 UX 2 · 「{장벽}: {해법}」 3줄 · UX 추진 방향 · [R-0018]
- **3대 과제 → 3가치 축 → 목적 · 효과** — 위 과제 3열, 가운데 가치 축 3(일관성 · 연속성 · 확장성), 아래 「#목적」 + 효과 #1–#3, 세로 3층을 같은 열로 · 추진 목표 장 · [R-0018]
- **단계 열 × 4관점 행 매트릭스** — 사용 단계 4열(진입 → 관심 확장 → 패턴 형성 → 인식 전환) × 행 4(사용자 상태 · 필요 가치 · 전략 · 이해) + 오른쪽 목표 태그 4, 다음 장 컨셉 문장과 겹쳐 회수 · UX 목표 · [R-0022]
- **커스터마이징 3층** — 기본 구조 · 탐색 구조 · 개인 맞춤 3층 + 층마다 대응 장치(메뉴 구조 · 분류 필터 · 내 타임라인) 짝 · UX 방향 · [R-0022]
- **관점 원 셋 + 가운데 공통 목표** — 비즈니스 · 운영 대행 · 사용자 관점 원 3개를 겹치고 원마다 목표 한 줄, 겹친 가운데 공통 목표 · 운영 목표 장 · [R-0021]

## 4. 비교 · 전환

- **등식형 전후** — 「BEFORE {기존 투입} vs AFTER {적용 후 절감} = {연간 합계}」 — 세 상자를 vs · = 기호로 잇고 결과 상자만 강조 · 효과 정량화 · [R-0001]
- **선택지 × 같은 항목 비교** — 선택지 N개를 열로, 같은 평가 항목 3개를 행으로 반복 · 마지막 행(또는 마지막 「반면교사」 열)만 강조, 하단 시사점 ✓ · 기능 제안 · 구현 방식 · 벤치마크 · [R-0001, R-0007, R-0009, R-0020]
- **전후 화면 짝** — BEFORE / AFTER 화면 두 장을 같은 크기로 좌우, 바뀐 곳 번호 표시, 문제점 1–3 ↔ 개선 1–3 번호 대응 · 기능 제안 · [R-0001, R-0008, R-0020]
- **채널 짝 화면** — 앱 화면(하단 탭바)과 웹 화면(대체 내비)을 같은 크기로 좌우, 대응 요소를 가운데 라벨로 연결 · 전후 화면 짝의 채널 대응 변형 · 웹 · 앱 일원화 · [R-0011]
- **단계 타일 전후 + 처리 범례** — AS-IS 번호 타일 N개와 TO-BE 번호 타일 N개를 위아래로, 타일 색을 범례 3종(삭제 · 유지 · 부분 통합)으로 구분 · 프로세스 단축 · [R-0011, R-0016, R-0018]
- **가짜 · 진짜 대비 두 판** — 왼쪽 「FALSE {가치}」, 오른쪽 「TRUE {가치}」, 같은 4행 짝, 아래 「첫 번째 · 두 번째 {가치}」 두 줄 · 개념 재정의 · [R-0006]
- **AS-IS → 개선 방향 → 하나로 수렴** — 왼쪽 AS-IS 4항목 ↔ 오른쪽 개선 방향 4항목, 아래 수렴 띠에 칩 4개 · 좌우 2판 변형 · 개선 방향 · [R-0015]
- **공통 컴포넌트 열 → 현지 템플릿 N열** — 왼쪽 공통 컴포넌트 번호 목록 → 오른쪽 지역별 템플릿 열 N개에 같은 번호를 순서만 바꿔 배치 · 다국어 · 글로벌 확산 · [R-0012]
- **메뉴 트리 좌우 비교 + 진단 · 재편 3줄** — 왼쪽 AS-IS 1 · 2단계 트리, 오른쪽 TO-BE 트리, 트리마다 아래 Key Features 3줄(AS-IS = 진단, TO-BE = 재편 원칙)을 같은 순서로 · IA 개편안 · [R-0018]
- **모듈 코드 그리드 → 화면 콜아웃** — 모듈 그룹 4 × 3(코드 A-1–D-3) 그리드로 콘텐츠 정의, 다음 장 화면 목업 위 같은 코드 콜아웃 + 범례, 회원 상태 3단 × 노출 모듈 칩 표로 개인화 · 모듈형 메인 설계 · [R-0018]
