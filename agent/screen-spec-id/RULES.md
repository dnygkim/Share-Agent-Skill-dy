# 변환 규칙 정본 — 메뉴구조도(IA) → 화면명세서

> 2026-07-13 사용자 승인 완료 / 2026-07-15 단계별 진행·공통영역·채번규칙 프로젝트별 정의 추가 / 2026-07-20 출력 양식 선택(STEP 1) 도입.
> 이 파일이 채번·변환 규칙의 **기본값 정본**이며, `scripts/generate_spec.py`가 이 규칙을 구현한다.
> 채번규칙은 STEP 3에서 프로젝트별로 확정하며, 조정분은 config의 `id_rule`에 기록한다 (이 문서는 기본값).
> 출력 양식은 STEP 1에서 `samples/` 기본양식 2종 중 선택한다 (config `template`, 기본 타입2).

## 1. 입력 (IA 엑셀)
- 시트별 채널 구성 (예: `01. FO통합`, `02. FO리조트체인`, `03. BO Admin`)
- 헤더 행 자동 탐지: `No.` 셀이 있는 행
- 인식 컬럼: `No.` / `구분`(통합·기존·신규) / `Depth 0~N`(계단식 트리) / `화면타입` / `기능`(Static·Dynamic) / 나머지 컬럼은 비고 소스
- 계단식 트리 복원: 각 행의 노드 = 가장 깊은 Depth 셀, 상위 경로는 이월(carry-over)

## 2. 시트 매핑 (실행 시 자동 제안 → 사용자 승인)
| IA 시트 | 출력 시트 | 업무구분 | 채널 |
|---|---|---|---|
| FO 통합류 | FO_Global | FO | PW + MW (쌍) |
| FO 체인류 | FO_Chain | FO | PW + MW (쌍) |
| BO Admin류 | BO_Admin | BO | PW 단독 (+채널/코드 컬럼) |

## 3. 화면ID 채번 (기본값 — STEP 3에서 프로젝트별 확정)
```
{업무구분}-{구분}-{채널}-{대분류}-{일련번호5자리}   예: FO-SB-PW-BR-00012
```
- 프로젝트별 조정 가능 항목 (config `id_rule`): `format`(세그먼트 구성·구분자), `seq_digits`(일련번호 자릿수), `suffixes`(화면타입 접미사 문자)
- **구분**: 기본 `SB`(스토리보드)
- **채널코드**: PC WEB=`PW`, MO WEB=`MW`, APP=`MA`
- **대분류(2자리)**: Depth 1 메뉴 기준(시트별 `category_key_depth`로 조정). 코드는 에이전트가 영문명과 함께 자동 제안 → 사용자 승인 후 config에 확정 → `규정` 시트에 기록
- **일련번호**: `(업무구분, 대분류)` 단위로 1부터 순차 채번, **시트를 넘어 이어짐** (샘플 근거: FO_Global MA-00005 다음 FO_Chain MA-00006)
- **PC/MW 쌍**: 동일 일련번호 공유
- **접미사**: Popup=`P1…` / Layer=`L1…` / Tab=`T1…` / Bottom Sheet=`B1…` — 소속 페이지(같은 대분류의 직전 Page) 번호 뒤에 타입별 순차 채번

## 3-1. 공통영역 (STEP 4에서 정의)
- **정의**: 특정 메뉴에 속하지 않고 서비스 전반에서 쓰이는 영역 — 로그인·회원가입·마이페이지·알림·검색·어권/통화선택·약관/정책·사이트맵·GNB/푸터 유틸 등. 시트별 config `common_menus`(대분류 메뉴명 목록)로 지정한다.
- **채번**: 공통영역도 각자의 대분류 코드로 채번한다. 일련번호가 대분류 단위로 독립이므로 메뉴 영역과 번호가 충돌하지 않는다.
- **추출 순서**: 프리뷰(`--preview`)와 검토 보고에서 공통영역을 먼저, 메뉴별 상세를 나중에 보고한다. `규정` 시트의 코드표에는 공통영역 메뉴명에 `(공통)`을 표기한다.
- **프리뷰 관용**: `--preview` 모드에서는 코드 미정의 대분류를 오류 대신 `(코드미정)`으로 표시한다 (채번 미소비). 본 생성(-o)에서는 기존대로 오류로 중단한다.

## 4. 행 처리
| IA 행 | 처리 |
|---|---|
| `Page` | ID 채번, 채널별 본수 1 |
| `Layer`·`Popup`·`Tab`·`Bottom Sheet` | 직전 Page ID + 접미사 채번, 본수 1 |
| 화면타입 공란 | **Page로 간주** (BO 시트 대부분 공란인 실측 근거) |
| 상위 그룹 메뉴(화면 없음) | `Menu` 행, ID `-`, 본수 0, 회색 배경 |
| `Internal/External Link` | 행 유지, ID `-`, 본수 0 |
| `구분`·`기능`·기타 컬럼 | `비고`란에 `[통합/Dynamic] …` 형식으로 이관 |

- 본수 = 해당 채널 ID가 채번되면 1, 아니면 0. 시트 합계는 SUM 수식.
- ID 중복은 생성 시점에 검증하며 중복 발견 시 생성 중단.

## 5. 출력 (화면명세서 xlsx)
출력 레이아웃은 STEP 1에서 선택한 양식을 따른다. 아래는 **기본양식(샘플타입2, 스크립트 네이티브)** 기준이며,
샘플타입1(목록·작업관리형)·기타 양식 선택 시에는 채번 결과를 해당 양식 레이아웃으로 변환 생성한다 (CLAUDE.md STEP 6).

1. `표지` — 프로젝트명·문서번호·단계·작성일·버전
2. `개정이력` — Ver 0.1 신규 1행 (사유: IA 기반 자동 추출)
3. `규정` — ID 생성규칙 + 접미사 규칙 + **확정된 대분류 코드매핑표**
4. 채널별 명세서 시트 — 샘플과 동일 골격: 타이틀(2행) / Last Updated·본수 Total(3~4행) / 헤더(5행) / 데이터(6행~). 컬럼: `No. / 상태 / 수정일 / [채널/코드] / 채널별 화면ID·본수 / 화면타입 / 화면명 / Depth 0~N / 비고`

## 6. 범위 한계 (중요)
이 에이전트는 **초기 버전(v0.x) 명세서 생성**까지 담당한다. 설계 진행 중 추가되는
Popup·Tab·Bottom Sheet(샘플 기준 전체 행의 약 60%가 사후 추가분)는 이 문서를 기반으로
설계 단계에서 수기 관리한다. IA에 이미 존재하는 Layer/Popup은 자동 채번된다.
