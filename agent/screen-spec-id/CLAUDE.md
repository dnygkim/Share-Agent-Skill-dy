# 화면명세서 자동생성 에이전트 (IA → 화면명세서)

이 폴더는 **메뉴구조도(IA) 엑셀에서 화면명세서 엑셀을 자동 생성**하는 에이전트 하네스다. 이 폴더에서 Claude Code를 열면 이 파일이 자동 로딩되어 아래 규칙대로 동작한다. (모든 경로는 이 폴더 기준 상대경로.)

## 이 에이전트가 하는 일
IA 엑셀(채널별 시트 + Depth 트리)을 입력받아 **6단계**로 진행한다:
① 출력 양식 선택 → ② IA 파싱 → ③ 채번규칙 정의 → ④ 공통영역 화면ID 추출 → ⑤ 메뉴별 상세 화면ID 추출 → ⑥ **화면명세서 초기 버전(v0.x) xlsx** 생성.
각 단계는 사용자 승인 후 다음 단계로 넘어간다. 채번·변환 규칙 기본값 정본은 `RULES.md`, 기본양식 2종은 `samples/`.

## 사용법 (사용자)
1. IA 엑셀을 `input/`에 두거나 경로를 대화로 알려준다.
2. "이 IA로 화면명세서 만들어줘"라고 요청한다.
3. 어떤 양식으로 만들지 선택한다 — 샘플타입1(목록·작업관리형) / 샘플타입2(표준 채번형, 기본) / 기타(사용자 제공 양식).
4. 단계별 제안(채번규칙 → 공통영역 → 메뉴별 코드표)을 검토·승인한다.
5. 결과는 `output/{프로젝트}_화면명세서_v0.1_{YYYYMMDD}.xlsx`.

## 동작 규칙 (에이전트) — 단계별 진행, 각 단계 승인 게이트

**공통 원칙**: 각 STEP 종료 시 결과를 보고하고 사용자 승인("승인"·"다음"·"진행" 등)을 받은 뒤에만 다음 STEP으로 넘어간다. 사용자가 "한 번에 진행해줘"라고 명시하면 STEP 3·4의 보고를 연속으로 수행하되 승인은 각각 받는다. 질문은 한 번에 하나씩, 추론 가능한 것은 묻지 않는다.

**Dan Jr. 등급 조회(승인 게이트 공통, 2026-10-22)**: 각 STEP의 승인·「~할까요?」를 묻기 직전에 `~/.claude/persona/persona.md`(전역 규칙이 없는 환경은 `../../persona/persona.md`)에서 같은 상황을 찾는다. 등급 **A**면 묻지 않고 기본값으로 진행, **B**면 진행 후 완료 보고에 한 줄, **C** 또는 해당 항목 없음이면 지금처럼 묻는다. 건너뛴 게이트는 완료 보고에 「Dan Jr. 적용: F-01(A)」처럼 ID로 적는다. 채번규칙·코드표 승인처럼 persona.md에 없는 결정은 그대로 사용자 승인.

### STEP 0 — 입력 확인
**★ 자료는 `input/`을 가장 먼저 본다 (전역 검색 금지)**. input/이 비어 있고 경로도 없으면 "input/에 IA 파일을 넣어주세요"라고 되묻는다.

### STEP 1 — 출력 양식 선택 (승인 게이트)
1. `samples/`의 기본양식 2종을 **비교표로 제시**하고 어떤 양식으로 생성할지 질문한다:
   - **샘플타입1** (`samples/화면명세서-샘플타입1.xlsx`) — **목록·작업관리형**: 단일 시트에 화면목록(순번·화면코드 PC/MO·depth·본수) + 기획/디자인/퍼블리싱/프로그래밍 공정률 블록, `기준` 시트 포함. 화면목록과 일정·진척 관리를 한 문서로 겸할 때.
   - **샘플타입2** (`samples/화면명세서-샘플타입2.xlsx`) — **표준 채번형 (기본 권장)**: 개정이력·규정 + 채널별 시트(No./상태/수정일/채널별 화면ID·본수/화면타입/화면명/Depth 0~N/비고). `generate_spec.py`가 직접 생성하는 네이티브 양식.
   - **기타** — 사용자가 양식 파일 경로를 주면 구조를 분석해 적용.
2. 선택 결과를 config `template`(`"type1"`/`"type2"`/`"custom"`)에 기록한다. 사용자가 답하지 않으면 타입2를 권장 이유와 함께 다시 묻고, **임의로 진행하지 않는다**.
3. 타입1·기타 선택 시에도 STEP 2~5(파싱·채번)는 동일하게 진행하며, 레이아웃 차이는 STEP 6에서 반영한다.

### STEP 2 — IA 파싱·구조 보고
`python scripts/parse_ia.py input/{IA}.xlsx -o _workspace/{slug}/parsed.json`
- slug = `{고객}-{주제}` 1회 확정. 중간물은 항상 `_workspace/{slug}/` 하위.
- 시트별 행수·화면타입 분포·대분류 후보를 요약해 보고한다.

### STEP 3 — 화면ID 채번규칙 정의 (승인 게이트)
1. 프로젝트명·문서번호를 확인(질문)한다.
2. **채번규칙을 표로 제안**한다 — RULES.md 기본값 기준: ID 포맷(`{업무구분}-{구분}-{채널}-{대분류}-{일련번호}`), 구분코드(SB), 채널코드(PW/MW/MA), 일련번호 자릿수(5), 화면타입 접미사(P/L/T/B). IA에서 관찰된 채널 구성·시트 매핑(IA 시트→출력 시트/업무구분/채널)도 같은 표에 포함.
3. 사용자가 조정하면 config의 `id_rule`·`sheets`에 반영. 승인된 내용을 `_workspace/{slug}/config.json`으로 저장 (스키마: `references/config-schema.md`).

### STEP 4 — 공통영역 화면ID 추출 (승인 게이트)
1. parsed.json의 대분류 후보 중 **공통영역 후보를 제안**한다 — 특정 메뉴에 속하지 않고 서비스 전반에서 쓰이는 영역: 로그인·회원가입·마이페이지·알림·검색·어권/통화선택·약관/정책·사이트맵·GNB/푸터 유틸 등.
2. 승인되면 해당 시트의 `common_menus`에 기록하고, **공통영역 대분류의 코드표**(영문명+2자리 코드)를 제안·승인받아 `codes`에 반영.
3. `python scripts/generate_spec.py _workspace/{slug}/parsed.json _workspace/{slug}/config.json --preview` 실행 → 결과 JSON의 `common` 목록을 **대분류별 표**(화면명·화면타입·채널별 화면ID)로 보고. 이 시점에 메뉴 대분류 코드가 미정이어도 프리뷰는 `(코드미정)`으로 표시하고 진행된다.
4. 공통영역 채번 결과 승인 후 STEP 5로.

### STEP 5 — 메뉴별 상세 화면ID 추출 (승인 게이트)
1. 나머지(비공통) 대분류의 코드표를 제안·승인받아 `codes`에 반영. 중복 코드 금지.
2. `--preview` 재실행 → `summary.undefined_categories`가 비어 있는지 확인(남아 있으면 코드표 보완 후 재실행) → `menu` 목록을 **메뉴(대분류)별 표**로 보고.
3. 메뉴별 채번 결과 승인 후 STEP 6로.

### STEP 6 — 명세서 생성·검증 보고
- **타입2 (기본)**: `python scripts/generate_spec.py _workspace/{slug}/parsed.json _workspace/{slug}/config.json -o output/{프로젝트}_화면명세서_v0.1_{YYYYMMDD}.xlsx`
  스크립트가 ID 중복·미정의 대분류를 자체 검증하고 실패 시 중단한다.
- **타입1·기타**: 먼저 `--preview`로 채번 검증을 통과시킨 뒤, 선택된 양식 파일의 헤더 구조를 읽어 preview JSON을 해당 레이아웃 xlsx로 변환 생성한다. 일회성 변환 스크립트는 `_workspace/{slug}/`에 둔다. 화면코드 컬럼에는 STEP 3에서 승인된 채번규칙 ID를 사용하고(양식 원본의 구식 코드체계를 따르려면 STEP 3의 `id_rule`로 조정), 작업관리·공정률 블록은 빈칸으로 둔다(수식 미포함, 사후 수기 관리).
- **검증 보고 (필수, 양식 공통)**: IA 행수 vs 명세서 행수 일치 여부 / 시트별 본수 합계 / 공통영역·메뉴별 채번 범위 / Menu·Link 등 ID 미부여 행 수. 불일치가 있으면 원인을 밝히고 수정 후 재생성한다.

### 수정 요청 처리
- **양식 변경**(타입1↔타입2↔기타): config의 `template` 수정 → 채번 결과는 유지하고 STEP 6만 재실행.
- **채번규칙 변경**(포맷·자릿수·접미사): config의 `id_rule` 수정 → STEP 4부터 재진행(기존 승인 내용은 유지, 프리뷰로 변경분만 확인). 기본값 자체를 바꿀 때만 `RULES.md`·스크립트를 수정.
- **코드표·공통영역 변경**: config만 수정해 해당 STEP부터 재진행.
- **생성된 xlsx를 직접 수기 편집하지 않는다** (재생성 시 유실).

## 입출력 규약
- `input/` — 사용자 IA 파일 (배포 시 비움)
- `_workspace/{slug}/` — `parsed.json` · `config.json` (배포 시 비움)
- `output/` — 최종 xlsx. in-place 갱신 기본, 구조 변경 시에만 버전업.
- `samples/` — 기본양식 2종 (샘플타입1·2, STEP 1 선택지 정본. 수정 금지)
- `references/` — `config-schema.md` (config 스키마 정본)

## 표기 규칙
한국어. 파일명 날짜는 `YYYYMMDD`. 범위 표기는 하이픈(-).
