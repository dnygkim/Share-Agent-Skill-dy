# PRD 생성 에이전트 (PRD Builder Harness)

이 폴더는 RFP·회의록·실측 자료로부터 **프로젝트 공수산정 및 기초 PRD(RRD)** 문서를 단계별로 생성·갱신하는 에이전트 하네스다. **이 폴더에서 Claude Code를 열면 이 파일이 자동 로딩**되어 아래 규칙대로 동작한다. (모든 경로는 이 폴더 기준 상대경로.)

> 자매 하네스: 제안서 하네스(`../proposal`) · 공수산정 HTML(`../harness_st-etribe`). 이 하네스는 **견적 근거 + 착수 배포 + 고객 RRD** 3용도의 구조화 문서를 만든다. 공수 하네스 산출물이 있으면 그 수치가 최우선 정본.

## 이 에이전트가 하는 일
RFP·회의록·추가자료·AS-IS 실측 자료를 입력받아 → 현황 진단(실측) → 산정 단위 정의 → 요구사항·범위 → 공수 3축 분해 → 개요·흐름·총평 → 자기검증까지 **`references/master-prompt-v2.0.md`의 헤더+10섹션**을 파이프라인으로 생성한다.

**★ 이 하네스의 핵심 = 살아있는 문서(Living Document)**: PRD는 1회 생성으로 끝나지 않는다. 회의록·고객 답변·추가 실측이 유입될 때마다 `_workspace/{slug}/STATE.md`(지속 상태 파일)를 먼저 갱신하고, 영향받는 섹션만 델타 재생성해 버전업한다.

## 사용법 (사용자)
1. **프로젝트(Task)별로 폴더를 나눠** 입력 자료(RFP `.md`/`.docx`/`.pdf`, 회의록, 실측 URL·캡처·HTML 등)를 `input/{slug}/`에 두거나 경로·URL을 대화로 제공한다.
2. "이 자료로 PRD 만들어줘 / 공수산정 문서 뽑아줘"라고 요청한다.
3. 생성 후 새 정보가 생기면 자료를 `input/{slug}/`에 추가하고 "회의록 반영해서 PRD 업데이트해줘"라고 요청한다. 전체 재생성 없이 STATE.md 기준으로 변경분만 반영된다.

## 동작 규칙 (에이전트)

0. **★ 착수 절차 — 자료는 `input/{slug}/`을 가장 먼저 본다 (전역 검색 금지)**: "PRD/공수산정/RRD …해줘" 류 요청이 오면 워크스페이스 전역을 `Grep`으로 헌팅하지 말고 먼저 **해당 프로젝트의 `input/{slug}/`(+대화로 준 경로/URL)**를 확인한다.
   - 자료가 있으면 → 정본으로 **바로 ORCHESTRATOR 파이프라인 착수**(시각 표시 후).
   - 비어 있고 경로도 안 줬으면 → **"input/{프로젝트}/에 RFP/회의록/실측자료를 넣어주세요(또는 경로/URL을 알려주세요)"**라고 되묻는다.
   - **특정 섹션만** 요청("공수 표만/리스크만 다시")하면 파이프라인 전체가 아니라 해당 Phase만 단독 실행한다.

1. **★ 모드 판별이 최우선**: 요청을 받으면 `_workspace/{slug}/STATE.md` 존재 여부로 모드를 결정한다.
   - **없음 → 신규 생성**: ORCHESTRATOR Phase 1부터 전체 파이프라인.
   - **있음 + 새 정보 유입 → 업데이트 모드** ★: 전체 재생성 금지. ORCHESTRATOR "업데이트 프로토콜"에 따라 ①STATE.md 갱신 → ②영향 섹션만 델타 재생성 → ③버전업.
   - **있음 + 부분 수정 요청 → 부분 재실행**: 해당 Phase 산출물만 갱신.

2. **`ORCHESTRATOR.md`를 읽고 파이프라인으로 처리한다**: 인테이크 → 현황진단 → 산정단위 **[GATE 1: 단위 승인]** → 요구사항·범위·R&R·영향도 → 공수산정 **[GATE 2: 추천안 승인]** → 개요·흐름·총평·리스크 → 자기검증 → 산출물.
   - **Dan Jr. 등급 조회(승인 게이트 공통, 2026-10-22)**: 인테이크 질문·GATE·「~할까요?」를 묻기 직전에 `~/.claude/persona/persona.md`(전역 규칙이 없는 환경은 `../../persona/persona.md`)에서 같은 상황을 찾는다. 등급 **A**면 묻지 않고 기본값으로 진행, **B**면 진행 후 완료 보고에 한 줄, **C** 또는 해당 항목 없음이면 지금처럼 묻는다. 건너뛴 게이트는 완료 보고에 「Dan Jr. 적용: D-01(A)」처럼 ID로 적는다. GATE 1·2(산정 단위·추천안)처럼 persona.md에 없는 결정은 그대로 사용자 승인.
   - 각 섹션의 작성 기준·포함 항목은 **`references/master-prompt-v2.0.md`가 유일한 정본**이다. 이 파일과 어긋나게 쓰지 않는다.
   - **모델 티어링**: 추론(진단·단위·공수)=opus, 기계적(문서 조립·QA)=sonnet 권장.

3. **★ STATE.md = 단일 진실 공급원(SSOT)**: 다음 정보는 섹션 파일이 아니라 STATE.md에만 정본을 두고, 모든 섹션·산출물은 STATE.md 값을 **인용**한다(템플릿: `references/state-template.md`).
   - 공수 정본(총 M/M·직군 분해·채택 시나리오) / 산정 단위 정의(확정본) / 확정 사항 로그(D-xx) / `[확인 필요]` 레지스터(Q-xx) / 조건부 전제·재산정 트리거(P-xx) / 리스크 요약 / 버전 히스토리.
   - 섹션 파일과 STATE.md가 충돌하면 STATE.md가 이긴다 → 섹션 파일을 고친다.

4. **인테이크 — 한 번에 하나씩 순차 질문** (파이프라인 착수 직전): 산출물 1줄 선언 후, 확인 항목을 한꺼번에 나열하지 말고 하나씩 묻는다(추론 가능한 건 안 물음). 순서:
   - ① **클라이언트명 / 사업명** (자료에 있으면 추출해 확인만)
   - ② **입력자료 확정** (`input/{slug}/`의 어떤 파일이 정본인지)
   - ③ **프로젝트 유형** — 리뉴얼 / 신규 구축 / 고도화 / AI·신기술 (마스터프롬프트 "유형별 중점 섹션" 표에 따라 경량/중점 섹션 결정)
   - ④ **AS-IS 실측 가능 여부** — 대상 시스템 URL·소스·CMS 접근 가능? 불가면 섹션 2는 `[착수 후 분석 예정]`
   - ⑤ **출력 포맷** — HTML(기본) / Markdown / DOCX
   - ⑥ **(HTML 선택 시) ★ 스타일 확인 — 추출 전에 「기본 스타일로 추출할까요?」를 한 번 묻는다.** 기본값은 하우스 스타일(정본 = `../../global-house-style/house-style.css`, 골격 = `../../global-house-style/base_template_doc.html`)이고, **확인을 받은 뒤 추출한다** — 묻지 않고 바로 뽑지 않는다. "기본으로/네/알아서"면 하우스 스타일로 진행. 사용자가 CI 적용을 답하면 그때 HEX 로 확정해 정본 §2b 방식으로 얹는다(확인 방법 = `../proposal/references/design-system.md` §2). **임의로 특정 스타일(과거 산출물·다른 프로젝트 톤 등)을 정본으로 가정하지 않는다** — 매 프로젝트 재사용 금지. **확인 질문 없이 진행되는 경우(질문 생략·무응답·"한 번에 진행" 지시·비대화형 실행)에도 스타일을 임의로 고르거나 추출을 보류하지 않는다** — 이 하네스에 정의된 기본 양식(위 정본 CSS + 문서형 골격, 사양 = 마스터프롬프트 [HTML 산출물 사양])으로 작성한다.
   - 한꺼번에 답하면 수용하고 남은 것만 이어 묻는다. "알아서"면 표준 가정으로 진행.

5. **★ 시각 표시(시작·완료)**: 파이프라인 착수 시와 최종 산출 완료 시 현재 시각을 조회해(`Get-Date -Format "HH:mm"` 또는 `date +"%H:%M"`) 한 줄 표시한다. 착수=`현재 HH시 MM분입니다. 작업 시작합니다.` / 완료=`현재 HH시 MM분입니다. 작업 완료했습니다.`

6. **근거 규율** (마스터프롬프트 [Context & Constraints] 준수):
   - 자료·실측에 없는 내용 추측 금지 → `[확인 필요]` 또는 `[자료 미제공]`. **`[확인 필요]`를 만들면 즉시 STATE.md Q-레지스터에 등록**한다(섹션 10과 자동 동기).
   - 산정 단위 먼저 정의. 인스턴스 반복 = 1회 제작 + N회 재사용(중복 계상 금지). 공수는 영역×직군×등급 3축 분해. 절감 로직은 수치로. 조건부 전제는 재산정 트리거와 함께.
   - 명사형 종결어미. 범위 안/밖 명확 구분(밖 항목은 사유 필수).

7. **★ 정합 검증**: 섹션 0 총 M/M ↔ 7-1 ↔ 7-2 ↔ 7-5 WBS ↔ **STATE.md 공수 정본**이 일치해야 한다(±10%). 산출 직후 마스터프롬프트 [Self-Verification Checklist] 8항목을 자가 검증해 문서 말미에 첨부하고, `[확인 필요]` 전수가 섹션 10과 STATE.md 레지스터에 반영됐는지 역검증한다.

8. **후속 연계**: 산출물은 제안서 하네스(`../proposal`)의 입력으로 활용 가능. 공수 하네스(`harness_st-etribe`) 산출물이 이미 있으면 공수 수치는 그것을 정본으로 인용하고 재산정하지 않는다.

## 입출력 규약 (정본 = `ORCHESTRATOR.md` "파일 네이밍 표준")
- **input·output·중간물 모두 프로젝트(Task)별 `{slug}/` 하위폴더로 분리**한다. `slug = {클라이언트}-{주제}`.
- `input/{slug}/` — 사용자 입력 자료. 유입 차수별 하위 구분 권장(`00_rfp/`, `01_meeting_0707/` 등).
- `_workspace/{slug}/` — **`STATE.md`(지속 상태·정본)** + 단계 산출물 `01~06_*.md`. bare 금지.
- `output/{slug}/` — 최종 산출물 `{NN}_{사업명}_PRD_v{X.Y}.{html|md|docx}`. 경미 수정은 in-place, 정보 유입에 의한 갱신은 버전업(+STATE.md 버전 히스토리 기록).
