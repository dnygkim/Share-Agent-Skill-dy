# 기존 사이트 IA 추출 가이드 (analyst 핵심)

리뉴얼·이관 프로젝트에서 기존 사이트의 정보구조(IA)를 **최소 3뎁스**까지 추출하고, 사이트 성격에 따라 API·관리자 영역을 유추한다.

## ★ IA 추출 정밀도 규칙 (필독 — 오답 방지)
> 상세·근거·사례: `references/ia-extraction-upgrade.md`. 도구: `python scripts/ia_extract.py <URL> [--json out] [--insecure]` (메가패널 파싱·탭/그룹/외부 태깅·page/view 이중카운트·footer·로그인 감지 자동).

1. **GNB ≠ IA**: 상단 대메뉴 골격(GNB)만이 아니라 **분리된 모든 페이지를 3뎁스까지 하나씩 노드로**. 공수 기준은 전수 페이지.
2. **정본 = 가장 깊은 패널**: 슬림 nav(2뎁스 1줄)가 아니라 메가메뉴/사이트맵(3뎁스 포함)을 정본으로. 같은 메뉴가 슬림·메가·모바일로 **2-3중 렌더**되니 dedup하고, 블록 경계 bleed(옆 메뉴 흡수)는 **섹션 비율로 소유자 판정**해 제거.
3. **1 노드 = 1 줄 = 제 깊이**: 형제 페이지를 점(·)/쉼표로 합치지 말 것(→ 페이지 과소·공수 깎임). 탭도 트리엔 각자 제 줄로 펼침.
4. **type 태깅**: `page | tab | group(#) | external`.
   - `group`: `href="#"`(+`item more` 마커) → 자식은 별도 페이지.
   - `tab`: **부모 URL = 자식 URL**(또는 페이지에 `tabmenu` UI) → 부모=page(탭형), 자식=tab. 트리엔 펼치되 페이지 카운트는 부모로 롤업.
   - `external`: 타 도메인 → 페이지 카운트 제외, "외부 링크"로 분리.
5. **이중 카운트**: `page_count`(개발·이관 단위, 탭 롤업) + `view_count`(기획·디자인·퍼블 단위, 탭 포함). 둘 다 산출.
6. **footer/유틸 필수**: 법적고지·개인정보처리방침·사이트맵·이메일무단수집거부·검색 = 별도 페이지(개인정보처리방침은 퍼블 큼). 패밀리사이트·SNS는 external.
7. **회원 도메인 유추**: 로그인 단서(로그인·마이페이지·회원·가입·탈퇴) 있으면 표준 회원 페이지 세트(로그인·회원가입[약관·인증·정보·완료]·ID/PW찾기·소셜로그인·정보수정·**탈퇴**·마이페이지) 포함(`source:추정`).
8. **접근 차단 시 ⏸ 멈춤**: 로그인 필요·봇차단 영역은 **추측 금지** → 진행 멈추고 사용자에게 "로그인 후 메뉴/화면 캡처 첨부 / 테스트 계정 / 메뉴 구술" 요청. 못 받으면 `접근불가`+`추정` 플래그.

## 추출 깊이 목표
- **1뎁스**: GNB(전역 네비게이션) 대분류
- **2뎁스**: 각 대분류의 서브메뉴
- **3뎁스**: 서브메뉴 하위 페이지/탭 (필수)
- **4뎁스(가능 시)**: 페이지 내 주요 섹션/컴포넌트 — 공수 영향 큰 화면만

## 추출 수단 (우선순위 + 선택 기준)
0. **`scripts/ia_extract.py <URL>`** — 본 하네스 내장 1차 추출기(정밀도 규칙 코드화: 메가패널·탭/그룹/외부·이중카운트·footer·로그인). 정적 메뉴면 이걸로 시작하고, 동적/차단 시 아래로 보완.
1. **works/054.site-capture** — 이미 보유한 크롤·캡처 도구. 페이지 다수·반복 캡처·스크린샷(디자인 레퍼런스)까지 필요할 때 우선.
2. **firecrawl `map`** → 사이트 전체 URL 목록 빠르게 수집 → URL 패턴으로 IA 트리 1차 구성. 이어 `scrape`로 페이지별 메뉴/헤딩 파싱.
3. **playwright** — 메가메뉴·드롭다운 등 **JS로 그려지는 동적 네비게이션**을 펼쳐서 읽어야 할 때. hover/click 후 DOM 스냅샷.
4. **수동 확인** — 위가 모두 차단(로그인·봇차단)되면 사용자에게 메뉴 구조를 직접 확인.

> 가용 MCP/도구는 세션마다 다를 수 있다. 없으면 다음 우선순위로 폴백하고, 무엇으로 추출했는지 출처에 기록.

## 출처 태깅 (필수)
IA 각 노드에 태그:
- `실측` — 실제 사이트에서 직접 확인
- `추정` — 레퍼런스/도메인 지식으로 유추 (근거 1줄 병기)

## API / 외부 연동 유추
프론트 기능에서 역으로 연동 후보를 도출:
| 프론트 단서 | 유추 연동 |
|------------|----------|
| 로그인/회원가입/소셜 | 인증·SNS 로그인 API |
| 결제·예약·구매 | PG(KICC/NICE 등)·결제 FEP |
| 알림/문자/이메일 | 알림톡·SMS·메일 발송 |
| 검색 | 검색엔진/색인 |
| 외부 데이터(시세·지도·날씨) | 외부 Open API |
| 기간계/ERP 연동 흔적 | 레거시 FEP·배치 |
→ 각 후보는 `추정` + 단서 명시. 확정은 RFP/고객 확인 후.

## 관리자(어드민) IA — admin 있는 사이트만 · 자료 > 유추
**★ admin이 존재하는 사이트만**(운영·콘텐츠·회원 관리 기능이 있으면. 순수 정적·소개형은 생략). **먼저 관리자 자료(기능목록·메뉴·화면·xls 시트)가 제공됐는지 확인.** 제공되면 그게 정본 — **자료 기반(실측)으로 충실 반영**(`admin_label`="자료 기반", 유추 아님). 아래 유추는 **자료가 없을 때만** 적용한다(전부 `추정` 태그). (사고: GS칼텍스 xls `프로그램목록_ADMIN` 79기능을 유추로 오표기.)

자료가 없을 때 — 프론트 IA에서 "관리 대상"을 역추론:
- 콘텐츠형 페이지 → 콘텐츠/게시판 관리, 카테고리 관리
- 회원 기능 → 회원 관리, 권한/등급
- 상품/예약 → 상품·재고·예약 관리
- 공통 → 통계/대시보드, 배너/팝업, 코드/환경설정, 관리자 권한
→ 관리자 IA도 사용자 IA와 동일하게 3뎁스 트리로. 전부 `추정` 태그.

## 신규 구축(기존 사이트 없음) 처리
- 자기 사이트가 없으면 **레퍼런스 사이트 + RFP + 동종 서비스**에서 IA를 역설계.
- 전체를 `추정`으로 태깅하고, "기준 레퍼런스: {URL}" 명시.
