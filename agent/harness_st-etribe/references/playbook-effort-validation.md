# Playbook — 공수 타당성 5축 자기검증 (architect 산정 후 / qa 게이트)

공수 산정 직후 아래 5축으로 자기검증한다. 수치가 산술로 맞아도(정합 a-h) **전제·구성이 틀리면 오답** — 이 체크리스트가 2차 방어선. (KB effort-validation 차용.)

## 1. 비교 (유사 선례 대조)
- [ ] corpus에서 유사 도메인·기능 과거 산출물 검색했는가(`corpus.py search`)?
- [ ] 유사 건 대비 ±30% 이내인가? 벗어나면 근거 명시.
- [ ] **과소산정 경고**(과거 실제공수 > 산정)가 있으면 버퍼 반영했는가?

## 2. 구성 (누락 작업)
- [ ] 분석·설계 / 디자인 / 퍼블 / 개발 / **QA·테스트 / 이관·인수인계 / 배포·안정화**가 모두 산정에 있는가? (운영 하네스 교훈: QA·배포·보안검토 누락이 흔함)
- [ ] PM·기획 공수가 별도로 잡혔는가?

## 3. 외부 의존
- [ ] 외부연동 N종 직렬결합 리스크, 규격·테스트 일정 의존(예: FEP 후반 압축)을 반영했는가?
- [ ] 솔루션/라이선스 비용은 공수와 분리 표기했는가?

## 4. 리스크 버퍼
- [ ] 추정 불확실 영역에 10-20% 버퍼 또는 옵션별 델타를 명시했는가?
- [ ] 필요 vs 가용 충돌 시 숨기지 않고 표면화 + 완화안(범위분리/기간연장)을 달았는가?

## 5. 신뢰도·데이터갭 (KB Counter-Arguments 패턴)
- [ ] 산정 노트에 `confidence: high|medium|low` 자가평가가 있는가?
- [ ] **데이터 갭**(미정 요건을 어떤 가정으로 채웠는지)을 명시했는가?
- [ ] 재스킨/신규 등 산정 밴드 가정이 틀릴 경우의 영향을 1줄 적었는가?

→ 한 축이라도 미흡하면 architect로 반려. 통과 시 confidence/데이터갭을 산출물 "산정 노트"에 그대로 렌더.
