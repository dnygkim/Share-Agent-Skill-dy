# IA·공수 리포트 생성 명세 (정본)

> 다른 세션에서 다듬어진 실전 명세. **이 문서가 생성 규칙의 정본**이다. 다른 레퍼런스(section-catalog·house-style-guide·consistency-checklist)와 충돌하면 이 문서를 따른다.

## 1. 산출물 정의 & 변형
- **타입 A — IA 정보구조도**: 사이트/시스템 메뉴 구조(1-3뎁스) + 관리자 IA 유추
- **타입 B — 공수산정 리포트**: IA + 영역별/월별/역할/WBS/간트 공수 (핵심)
- **변형**: ① 단독안(시스템 1개) ② 통합안(여러 건을 한 사이트로) ③ 옵션 비교안(옵션1/옵션2) ④ 동시진행안
- 1파일 = 1주제. 산출물은 단일 HTML(인라인 CSS + 말미 JS).
- **타입 C — 제출용 공수산정안(영업 · 고객 제출본)**: 요청이 「공수산정안 제출」이면 이 타입. 분량·작성 스타일 정본 = 롯데GRS 원보드 v1.0(2026-10-16 제출, 아래 §1-1). 타입 B 의 6표 리포트를 그대로 내지 않는다.

### 1-1. 타입 C 표준 (2026-10-16 GRS 원보드 v1.0 제출본 기준 · 사용자 확정)
- **기준 파일**: `output/261014_GRS 원보드 대시보드 구축/GRS원보드플랫폼-투입공수산정안-v1.0-20261016.html` · 빌더 `_workspace/261014_GRS 원보드 대시보드 구축/build_house.py` + `02_spec.json`(새 건은 이 빌더를 복사해 spec 만 교체하는 것을 기본으로 한다). 고객 자료라 git 미추적 — 이 Mac 에만 있다.
- **분량**: 본문 텍스트 약 1.2만 자 · 표 10개 · 5장. 타입 B 대비 약 50% 축소. 장마다 표 1-2개 + 짧은 목록, 설명 문단을 늘리지 않는다.
- **목차 5장 고정**: 1 프로젝트 개요 → 2 주요 요구사항별 구현방향(업무 프로세스 · 요구사항별 구현방향 · 제안 인프라(TO-BE) · 연결 범위 분석) → 3 사업 수행계획(단계별 수행계획 · 마일스톤) → 4 투입공수(영역별 공수 · 월별 투입 인력표) → 5 기타 고려사항(공수 · 기간 변동 가능성 · 상세 추가정의 · 사전확인 필요사항 · 전제 · 제외 범위).
- **표지·머리**: 작성 = 회사명(이트라이브) 표지 · 토프바 우측(이 타입 한정 예외), 작성일 · 버전만. 표지 헤드라인 · 요약 문단 · 1장 요약 줄의 기간 · 인원 · 공수 수치는 넣지 않는다.
- **넣지 않는 것**: 단가 · 금액, 개정 이력 · 출처 섹션(기록은 spec meta 에만), 외부 협력사명(개발 파트 산정 조직 표기 등), 「내부 검토용 · 외부 배포 시 별도 승인 필요」 문구, 푸터의 총 공수 · 기간 · 인원 줄(푸터 = 로고 + 「{고객} {사업명} · 투입공수 산정안 {버전} — {회사}, {작성일}」 한 줄).
- **소스 전용 작성자**: `<meta name="author" content="이트라이브 / 컨버전스 그룹 / 김단영">`(화면 미노출).
- **표기**: 월 = M1 - M9 형식(머리행 「안정화」 제외), 마일스톤 칸은 오픈 날짜만(「~ 말」 제외), 간트의 마일스톤 · 오픈 = 머리행 아래 띠 + ◆, 구현방향 · 산정 근거는 의미 단위 줄 목록(ul.tight), 거버닝 메시지 문체 · 명사형 종결.
- **표 규칙**: 두 행이 함께 쓰는 칸(rowspan)은 왼쪽 세로선(`td.span-l`)으로 끝을 닫는다. 인력표 등급은 사용자가 준 순서 그대로.
- **버전**: 제출본 = v1.0. 제출 뒤 피드백 · 공수 변경은 v2.0 으로 새 파일(v1.0 보존). 최종본은 output · 드라이브 해당 건 `02. Work` · 내부망 주소에 같은 파일로 둔다.

## 5. 공수 산정 6표 + 상호 정합 규칙 (가장 중요)
| # | 표 | 구성 |
|---|----|------|
| 1 | 영역별 공수 | 영역행마다 (디 X / 퍼 Y / 개 Z) 표기 + num=합 → 제작 소계(디/퍼/개) + PM/기획역할행 → 총 공수 |
| 2 | 월별 투입 | 역할×월(M-M+N) 그리드, 등급, 행합계, 직군 소계, 월 합계 |
| 3 | 역할 매트릭스 | 역할 × 단계(분석·설계/디자인·구축/연계·통합/통합테스트·오픈). **행은 월별 투입표 인력(등급·인원)에 맞춰 세분 — 4직군 뭉뚱그림·빈 cells 금지** |
| 4 | WBS | 월별 블록(M-M+N) × 단계 phase 배지 |
| 5 | 간트 | 주 단위(=개월수×4주), JS 렌더 |
| 6 | 핵심 요약 | 투입인력/제외범위/산정단위/전제 카드 4종 |

**★ 정합 규칙 (자동 검증 필수) — 하나라도 어긋나면 불합격:**
```
(a) 영역표 num column 합  = 제작 소계
(b) 제작 소계 + PM/기획 소계 = 총 공수
(c) 영역표 디/퍼/개 합 = 월별표 직군 소계 = hero "총공수" 분해 = 핵심요약 인력합
(d) 월별표: 각 역할 행 = 월셀 합 / 각 월 = 직군 소계 합 / 월 합계 = 총 공수
(e) 개월수: 월별 colspan = 매트릭스 단계 = WBS 블록수 = 간트 totalWeeks/4 = hero "기간" = footer
(f) 간트 totalWeeks = 개월수×4, W 컬럼수 = totalWeeks, 모든 task end ≤ totalWeeks
(g) 팔레트: 이전 브랜드 hex 잔존 = 0
(h) 변경 후 옛 총량/개월수 문자열 잔존 = 0 (예: 47.0→57.0 시 "47.0" 0건)
```

## 8. 표기/언어 규칙
- **★ 섹션 도입 prose 가독성**: 각 섹션 도입 서술은 **짧은 리드(1-2문장) + 구조화**다. 현행·유지/변경/신규·스펙을 한 문단에 줄줄이 욱여넣지 말고(런온 금지), 나열·목록·delta는 **표/불릿(`<ul>`·`.insight`)**으로 분리. 상세는 표·도식이 보여주고 prose는 요약만.
- **★ 표현 절제 — 과장 네이밍·미사여구 금지**: 섹션 제목·도식 라벨·서술에 마케팅 수식어("관제탑"·"혁신 허브" 류)·과장 서사 금지. 담백한 명사구 + 실무·기술 근거(공수·견적 문서의 신뢰는 미사여구가 아니라 근거에서 온다).
- 소통·문서 한국어. 범위 표기에 물결표(~) 금지 → 하이픈(-) (마크다운 취소선 오류). 단, HTML 본문 `~5스타일` 등은 렌더 정상이라 허용.
- 파일: `works/NNN.주제/`, `파일명_vX.Y.html`. in-place 수정 기본, 매우 큰 수정만 버전업.
